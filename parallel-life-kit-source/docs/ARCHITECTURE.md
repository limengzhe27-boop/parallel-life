# 架构与数据边界

## 1. 小库的职责

```text
用户经历 → life.interview → 用户确认 → 版本化 Profile
                                      ↓
                         generate_branches → 3 个 Branch
                                      ↓
                          world.initialize → World
                                      ↓
用户交互 → 保存原文 → conversation.plan：chat / image / world
                       │                  │
                 chat / image         明确 world / user_action
                 不结算世界               ↓
                       │          最多 3 个独立 decide 调用
                       │                  ↓
                       │          world.settle：统一校验与结算
                       └──────────┬───────┘
                                  ↓
              保存请求回放结果、正式事件及图片任务预约
                                  ↓
        role_card + 可见事实 + 会话 + 记忆 + 原文 → reply(str 草稿)
                                  ↓
                   可选一次 dialogue_review（默认开启）
                                  ↓
                    Message → 异步 memory / image Job
```

三个业务模块是 `life`、`world`、`interaction`。其中 `world` 主要保障叙事连续性：当前场景、人物动机和关系、提出但尚未回应的想法、关键选择和章节变化。位置与物品只是可选基础字段，不继续扩成复杂模拟。`models` 定义共享类型；`store` 负责 SQLite；`conversation` 保存派生会话状态与角色声线，`dialogue` 编译纯文本回复上下文；`memory` 负责证据、压缩与召回；`providers` 连接真实模型；`api` 与网页是薄交付层。

每个角色的 `decide` 都是一次独立调用，有独立目标、知识与可见上下文。它们可以共用模型账号，不是用一次模型输出假装三个 Agent。普通私聊只为当前角色生成台词，跳过 `decide / settle`；自然语言明确行动意图可触发当前角色决策，用户提交结构化 `user_action` 时最多激活三个角色，各提一项行动。行动轮以 `propose / promise / tell / wait` 推进叙事，随后仍只为当前聊天对象生成回复；后台记忆与图片另有模型调用。

意图路由只看当前输入、近期可见原文与有来源的会话状态，不接收人物长期目标或场景固定选项。`chat / image` 不增加 World 版本；会话自身有 `revision`，接入方用 `conversation_version` 检查当前角色的对话并发。明确索图字段绕过意图推断，但仍保留消息来源、图片额度和任务状态。

回复默认经一次 CHAT 模型校稿，再原子保存最终消息、诊断与轮次状态。草稿和 issues 只在分范围的 `dialogue_review` 诊断中保留，不混入角色消息或记忆证据；失败进入显式补回复，不自动循环反思。`DIALOGUE_REVIEW=0` 可关闭；这个编辑层改善的仍是概率行为，不成为第二个世界写入口。

## 2. 人生事实与虚构世界

- 访谈原文先落库；提取事件必须关联原话。日期不完整时追问，模型猜出的月日不作为确认事实。
- 用户确认产生档案版本。分支绑定 `profile_id + profile_revision`，并保存当时历史快照，后续修订不反向改变已玩的分支。
- 第一步模型选择真实 `divergence_id`；第二步分别初始化分支，只传该日期及以前事件。现今身份、现今价值观及后续人生不进入初始化上下文。
- 同一个转折允许三种不同反事实；标题与改变描述去重。人物、地点、选项接受结构校验。
- 分歧事件描述本来做过的选择，开场提示明确要求回到选择之前。自然语言内的隐含未来信息仍需产品内容审查，不声称通过日期过滤解决所有语义问题。

## 3. 叙事状态与最小规则

`world.py` 是同步、无模型依赖的规则内核。`initialize / visible_state / settle / advance` 都返回值，由 `Engine` 保存结果。

- 玩家动作先结算，再按角色 ID 固定顺序执行提案；每一步检查最新状态、前置条件、归属和可见性。
- 核心支持 `propose / tell / promise / cancel / fulfill / choose / wait`。`propose` 是人物想法、邀约或线索，只记录“提出了什么”，不把其内容当成已经发生。角色发言和模型提案不直接兑现世界事实。
- `move / transfer` 是保留的可选基础动作，不是默认叙事主循环；有需要的产品再接入。
- 仅用户可以执行关键 `choose`。移动目标必须存在，交物须拥有且同地，取消承诺须由承诺方操作，履约须用户作为参与方明确确认。
- `advance` 只修改日期与场景；需明确确认、已解决当前关键选择，时间不倒退，不自动完成约定。
- 分支级 `asyncio.Lock` 串行化交互，SQLite 短事务提交快照、事件和回放结果。请求指纹阻止同一请求 ID 换内容；已提交动作的重放返回已有结果。
- 这套锁与工作器是单进程设计，不支持直接启动多个 Uvicorn worker。外部权威数据库接入还需统一存储和事务边界。

行动轮的回复生成发生在正式结算之后，普通聊天无需结算。模型只获得对自己可见的结果；提议、可能后果与实施结果明确区分。模型被要求不声称未执行动作成功，自然语言遵循仍是概率性的。调用失败可能留下 `reply_status=pending/failed` 的已提交轮次，应查看 `history.turns`；专用回复重试接口只补最新未完成台词，不重新执行动作或创建图片任务。提交前失败则由原请求 ID、原请求体重放；请求指纹阻止借重试修改输入。

## 4. Context 与记忆

存储记录以用户、分支、角色分层过滤，再做召回。世界事件和消息携带 `visibility`；人物只获得自己可见的消息、事件与约定。

| 内容 | 来源与处理 |
| --- | --- |
| 人设、用户世界内身份 | 固定字段，显式编辑；记忆模型不覆盖 |
| 世界事实和承诺状态 | 正式事件与执行器结果 |
| 偏好与经历 | 引用用户原话或可见事件 |
| 推测与认识 | `belief / agent_inference`，与事实区分 |
| 近期原文 | 过滤后的最近 20 条消息 |
| 当前会话 | topic、focus、parked_topics；按用户×分支×角色保存版本与消息来源，不作为世界事实 |
| 派生对话角色卡 | 从原人设整理身份/语气/价值观；按来源和整理规则版本缓存，显式 voice 优先 |
| 旧对话压缩 | 20 条以外每 10 条一组；场景结束补齐，摘要关联原始 ID |

召回采用英文词项、中文双字片段、重要性、时间排序，明确纠正优先。它不具备完整语义检索能力。`context_chars` 默认 24000，统计序列化上下文字符；固定约束和近期原文已超预算时直接报错，保留全部原始数据，由产品缩短输入或增加预算。

纠正把旧记录及关联摘要标为 `superseded`，新增明确纠正。遗忘标为 `forgotten`。`memory_edit` 保留精确来源：屏蔽对应原文、同轮可见助手回声，并沿来源关系屏蔽依赖它们的摘要/记忆，而不是把一个摘要中的所有无关消息一起扩散为遗忘对象。自动记忆替换不触发这个机制。

被阻断的来源退出原文注入、提取、压缩、会话状态和召回；动态知识通过 `knowledge_sources` 映射回事件，也会在模型上下文里过滤。正在进行的提取返回时再次检查，避免把刚遗忘的内容写回。不同轮次中没有来源关联的后来改写不通过关键词全局删除，来源过滤也不保证识别所有这样的改写。

遗忘是**角色召回层的遗忘，不是删除数据库原文**。世界正式事件、用户浏览历史与审计仍保留；需要数据删除时，由产品实现统一删除/保留政策。用户后来重新告知同一信息形成新证据，不属于从旧证据偷偷重建。

## 5. 异步任务、图片与恢复

同一个进程轮询持久化 Job，记忆通道与图片通道可分别运行；每条通道串行，避免图片阻塞记忆。

- 记忆失败保留原文，自动尝试最多 3 次，也有显式重试接口。
- 每轮最多 1 张图；每个用户、每个分支默认冷却 300 秒、每天 10 次，按 UTC 日期计数，失败/待确认任务也计入额度。
- 默认 `PROACTIVE_IMAGES=0`；显式开启后，角色可以从当前原文的视觉场景片段提出一张图，不依赖历史私有记忆。仍共用额度，不离线推送，不把图片细节变成世界事实。
- 图片以固定外观、画风、当前场景组织提示；实际图像一致性不是保证，图片细节不回写世界事实。
- 图片完成下载并原子保存后，才写入图片消息。生成超时或进程中断后的图片任务标为 `uncertain`，不自动重发。
- 图片返回 URL 仅允许 HTTPS 公网地址、固定已验证 IP、保留 TLS SNI、拒绝重定向，不向图床转发模型密钥；大小上限 12 MiB。
- 图片失败不阻断文字。用户检查服务商状态后，可明确发起一个新请求；不确定请求可能已计费。
- 回复失败与后台任务分开恢复；重放旧任务句柄时先检查持久化任务状态，避免重复生图。回复重试增加的新证据合并到原记忆任务，若提取正在执行，结束后重新排队处理增量。

数据目录保存 SQLite 和图片；本机启动器另存受限日志与进程状态。备份请先停服务，再整体备份目录，保留数据库与图片的对应关系。

以上是当前代码契约，不是部署或真实对话质量验收声明。注入式测试用于状态、隔离与恢复；自然度、索图质量和长对话连贯性仍需分开的真实模型记录。

## 6. 来源与精简范围

参考 JoyAI `services/webinfer/agent_memory/` 中的 `models / store / derivation / retrieval / context_compiler` 分层设计，保留证据、记忆派生与上下文预算概念。此次实现是小型重写，没有搬入其音视频服务、完整推理调度、情感推理或向量检索；原项目和部署保持独立。来源版本与 Apache-2.0 信息见仓库 `NOTICE`。

**校验实现补充**：最终采用删除式对白校验。CHAT 模型仅选择保留哪些完整原句，程序按原顺序拼接，不接收校稿模型新写的台词；原稿逐句保留，程序不按关键词或正则删除台词及动作。全部句子被否决时明确返回 `dialogue_draft_rejected`，由用户手动重试，不无限循环。此举避免自由重写再次引入旧流程或新事实；保留句子的语义判定仍是概率性的。
