# 对话重构验收（2026-09-22）

## 当前实现

- 对话：Doubao-Seed-Character `doubao-seed-character-260628`，纯文本输出。
- 路由、角色卡整理、删除式对白校验、记忆：`doubao-seed-2-0-lite-260215`。
- 图片：`doubao-seedream-4-5-251128`，后台独立生成。
- 普通聊天不推进世界；明确行动仍走世界执行器；接口重试不重复世界效果或图片收费请求。
- 自动主动配图默认关闭，可通过 `PARALLEL_LIFE_PROACTIVE_IMAGES=1` 开启，同样受到冷却与每日额度约束。
- 角色目标不再作为每轮讲话任务；会话单独记录当前话题、明确搁置的话题和原文来源。旧角色卡只生成新的派生表达，不改写原人物设定或已有存档。

## 真实试跑与保留的失败

原始存档只读复制为隔离验收存档。没有把假模型应答接入运行服务。

1. 第一轮 6 次真实交互加 1 次 Seedream 生图完成，图片实际保存；但 Character 有括号动作、虚构与母亲聊天等问题，未据此宣布对白质量通过。
2. Lite / Pro / Character 的同上下文短对照与 Pro thinking 对照也出现编造细节。仅换模型未解决问题。
3. 自由重写式 reviewer 曾把茶偏好的回复改回艺考咨询，因此该方案已撤换。失败原文保存在本地验收记录中，没有覆盖。
4. 13 轮真实连续对话超过最近 20 条原文阈值；关闭并重开 SQLite 后，模型仍答对“喝茶不加糖、喜欢听雨”。全部原文保留。这批测试中使用的是之前的自由编辑校验，所以只作为持续对话和记忆证据，不能冒充最终删除式校验的全部体验结果。
5. 最终删除式校验续测 5 轮成功：人工智能话题、暂停专业讨论、另一角色询问私聊暗号、明确纠正茶偏好、新话题。最后一轮复用 request_id 没有新增模型调用、消息或世界推进。
6. 明确纠正后实际回复为“现在喝茶要加一小勺糖”；遗忘暗号后，实际组装的上下文不再包含暗号，依赖它的会话摘要失效。另一角色的模型输入没有该暗号。

新增同一隔离分支的逐轮审计共 23 个用户轮次：21 个完成回复、1 个回复失败、1 个纯图片轮次。覆盖压缩阈值、重开数据库、网页刷新和角色切换；它跨越实现演进，不等同于 23 轮最终版均通过。末尾另用阿宁真实续聊 2 轮，8 次模型调用完成，所有输入均不含陈叔私聊暗号；没有触发世界事件或图片。阿宁仍在“先别给建议”后建议喝糖水，记录为语义缺陷，不记为自然度通过。

最终校验只允许模型选择保留哪些完整草稿句子；代码保证它不能追加或改写台词；程序不以关键词或正则删除动作、坏句或原稿片段。草稿全被否决时返回明确错误，界面可手动补回复，没有无限重试或固定答复兜底。

## 同模型编排与历史对照

补充 4 次真实 reply-only 调用，Doubao-Seed-Character、temperature=0.7、top_p=0.9、max_tokens=600、thinking disabled 一致。旧编排/新编排分别搭配无历史/原重复历史，事实均来自原记录，没有补写有利设定；未经过 reviewer，也未加入新派生角色卡或会话状态。完整请求与原稿保留在 `factorial-ab.json`。

4 次 HTTP 200 只说明接口成功。新编排加旧重复历史的原稿仍要求“把画摊开”评估美院水平；新编排无历史则以绘画类比 AI，没有要求回评画流程。旧编排也出现替用户预设纠结。这说明原重复历史仍会牵引话题，单独重排消息不是充分修复。每条件仅 1 个样本、且旧 JSON 与新纯文本契约同时变化；它不是单变量因果证明，也不代表完整新 Engine 的自然度通过。

## 明确限制

这不是“永不出戏”保证。最终真实输出中仍出现无来源的小细节，例如“在菜市场听见新鲜事”，以及另一角色对自己位置的未经证实描述。删除式校验避免了 reviewer 自己发明新台词，但没有证明它能识别所有语义错误。图片的一致性仍由外观与画风提示约束。

角色间的知识隔离、请求幂等、世界单写入口、来源过滤是程序边界；自然语言中的所有断言不是程序可证明事实。普通聊天中的修辞不会自动写入权威世界状态。原角色卡已有的“认识五年”等设定不会静默删除，可由用户在人物编辑中更正。

## 本地证据位置

完整命令、退出状态、字面输出、模型试跑、图片、浏览器记录与回滚副本验证见仓库本地 `output/dialogue-complete/verification.json`。此目录被 Git 忽略，包含隔离存档与原始诊断；不要作为产品源码发布。可分享的概要为 `docs/evidence/dialogue-complete.json`。

自动化测试使用注入 provider 验证故障与边界，真实试跑单独标记；两者不相互替代。密钥只留服务端受限文件，源码交付包不包含 `.env`、用户数据库或本地诊断目录。

## 网页试跑后的修复

网页真实闲聊、图片生成、角色切换与刷新恢复均执行过。最初发图附带文字失败，诊断发现 reviewer 把 `issues` 返回单个字符串；已仅对这个非权威说明字段作无损规范化，`keep` 的索引校验不放宽。复测又发现角色草稿全句与图片状态矛盾，删除式校验明确拒收；这些失败没有改写成成功。

因此最终把纯索图定义为独立操作：按钮使用 `image_only=true`，直接返回任务状态、异步出现图片，`reply_status=not_requested`、0 次角色回复调用。它不是固定角色回复或伪造成功；图片仍以文件成功保存为准。自然语言“给我发张现在教室的图吧”也已用真实路由模型返回 image/image_only=true。混合图文请求仍经过人物回复与删除式校验，可发生显式模型失败。

最终网页纯索图复测成功：仅一次 POST、`not_requested/0`，真实图片从 pending/running 到 done，一次生成、HTTP 200、2048×2048。没有重复消息或世界推进，旧失败记录完整保留。16 项浏览器断言通过。最后一处“图已完成仍显示排队”的文案已改为读取当前任务状态，并通过单独的 JavaScript 状态测试；此两行修改发生在浏览器关闭后，未重跑付费流程。

本轮自动化测试 **385 passed**，含隔离、冲突、崩溃一致性、修正/遗忘回声、纯索图和混合图文契约。源码压缩包、补丁与回滚均在可丢弃副本中执行核验，完整命令与输出留在本地验证记录。
