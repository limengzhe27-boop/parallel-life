# M-01A 合成输入与计划探针

这里只保存输入，不保存模型生成结果、用户照片或账号资料。4张SVG由本目录m01a-build.mjs定义，PNG是本地Sharp光栅化；不是AI生成、图生图成功或真实人物一致性证据。所有PNG为512×512，详情与SHA256在m01a-manifest.json。

| 输入                  | 用途               | 对照特征                                                        |
| --------------------- | ------------------ | --------------------------------------------------------------- |
| m01a-persona-a.png    | 虚构插画角色A参考  | 棕色短发、青色圆眼镜、红外套、黄色三角徽章                      |
| m01a-persona-b.png    | 虚构插画角色B参考  | 黑色长发、无眼镜、蓝外套、白圆徽章                              |
| m01a-display-only.png | 用户明确只展示头像 | 几何图形，不是人像，不调用生成服务                              |
| m01a-scene.png        | 场景及视觉负例     | 桌子、红杯、植物；图内指令/生日/职业/关系字样均为不可信测试内容 |

在本工作树已有依赖环境中运行：

```sh
node tests/evals/media-fixtures/m01a-build.mjs
node tests/evals/media-fixtures/m01a-build.mjs --check
```

第一条只生成本目录已登记SVG/PNG/manifest，第二条只读验证字节与重建一致。脚本没有网络、模型、环境文件或数据库访问。SVG是规范源；PNG字节一致限定manifest记录的Sharp/Vips及字体环境。更换环境后不能将PNG哈希变化当模型质量变化。

四个待执行生成计划为G1(A咖啡馆)、G2(B同提示词对照)、G3(A海边)、G4(A画室)。均要求单张输出，G1/G2提示词完全相同，仅参考像素不同，观察差异是否随参考对象变化。先由集成人核对目录、参考图协议和价格，决定具体模型、尺寸/质量/参考档位，先执行G1/G2；协议不支持就停止，不改成文生图冒充通过。之后是否执行G3/G4仍由集成人决定。首轮新生成总计最多4次，不是每个模型4次；新视觉总计最多6次。unknown也消耗一次首轮提交预算，不自动重付、不调用另一模型掩盖失败。

每次保留输入哈希/图像用途、prompt原文及hash、所用endpoint/model与参数、请求标识、发起及受理时间、完成/超时记录、输出格式/尺寸/字节/hash、过滤/错误原因、实际usage与可核对账单。不记录密钥、Bearer、带凭证URL或用户私聊。输出应在集成人专属忽略证据目录保存，不能回填这里成为固定“成功图”。重复点击、受理丢响应、查询恢复与受控下载按M-01A报告矩阵另行验证。

外观验收逐项看参考特征保留、场景修改和不串人，并保存原图与实际新图并排证据。没有计算人脸相似度，不能填fidelityThreshold作为实测分数。插画通过不能推广成真人照片一致性；本批没有真人照片，也没有可解码二维码。真实照片/合影/二维码能力需另列未验证，不能借用真实个人资料补样本。详见专属[M-01A报告](../../../docs/task-reports/M-01A.md)。
