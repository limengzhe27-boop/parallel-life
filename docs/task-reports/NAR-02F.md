# NAR-02F · 新结果优先承接

负责人：`codex-main-nar02f-20260928`。这是 NAR-02 的导演节奏修复，不等于完整剧情线或跨应用回报。

## 问题与处理

导演原先把最近 12 小时主动来信过的人整批排除。用户若在那之后向同一个人报告“做成了／卡住了／放下了”，该人物即便有未承接的新结果，也可能被普通冷却规则挡住；而普通提醒仍需要冷却，避免人物刷屏。

现在只有三种已发生、应当回应的新情况可越过普通人物冷却：用户仍欠回复、新选择结果、日历中用户明确标记的结果。普通选择催问、未定邀约和承诺仍受冷却。导演每次推进仍限制同一人物只出场一次；已承接的结果从待办消失，不会为了维持戏剧性重复发问。候选待办先按可用性过滤再截取展示上限，避免前面的冷却项挤掉后面的可回应事项。

## 验证

- 单元检查覆盖近期人物的结果优先、普通提醒继续冷却和同次推进不重复选人。
- 真实 PostgreSQL 链路：用户作选择 → 导演先来信 → 用户报告短片已导出 → 同一人物仍在 12 小时冷却期内但在下一合法世界节拍承接 → 再推进不重复。验证回执、版本、角色隔离与世界时间。`npm run verify` 全部通过（34 项真实数据库测试），`npm run build` 通过。
- 生产 Supabase 29 项迁移一致；本批无迁移、无模型提示变更。

## 仍有限制

导演仍只在进入／回访或手动推进时运行；这个修复不会产生后台实时推送。用户自述结果不是独立成就证据，人物消息也不能自动把报告变成照片、作品或奖项。完整剧情目标／阻碍／兑现条件和跨应用结果继续留在 NAR-02/03。
