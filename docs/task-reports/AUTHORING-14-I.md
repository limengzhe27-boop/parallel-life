## 本批实现

- 通用五模块、明确公开人物介绍的 Markdown 导入；保“需要刻画的信息”原文，不把“游戏作用”当人物设定。仅人物文档不会自动发明整个世界，未知内容、身份歧义仍保留核对。
- 项目整理 Agent 提出双向历史对话和文本朋友圈；原有作者内容、其他人物与世界保持。熟人有关系设定和可靠日期但未补历史/动态时，返回私有缺项，允许原流程一次纠错，不把空结果当完整成功。
- 人物页撤下自制聊天/朋友圈界面，复用已有 PublisherTrial → WorldPhoneApp / PhoneShell。实际发送、角色资料、朋友圈走玩家相同组件和运行链路，员工私有试演权限仍隔离。未保存草稿不挂旧手机，同一保存版本复用试演且仅一次挂载，不自动调用模型。
- 编剧建立独立事件标题、主角相关概述和可选前提。新导演事件默认需要推进；满足前提且有必须推进事件时，真实导演必须从合法池选一个入场。旧明确意图与可选事件保留。
- 导演可读绑定版本的总体设定及虚构人物关系/五模块；单 NPC 仅自己的模块、自己的已保存公开动态、裁剪事实，不收到他人的私有模块、完整幕后稿或现实访谈。
- 首次入场只保存 presented，outcome=null，不冒充玩家完成。依赖整事件完成的前提/阶段目前明确阻试演发布，原稿不被删除或改成入场前提；可用“已开始演绎”衔接。
- SQL0052–0055：双方历史发送方来源校验、导演选择预约/恢复、公开初始动态、仅导演/本人可见设定；生产55迁移一致。真实手机读取遗漏 introduction 导致503已修复。
- 真实验收发现交易池环境下旧会话锁可能造成409；世界活动锁改为显式事务锁，提交/回滚释放，回滚失败丢弃连接。没有重置共享连接或解锁他人世界。旧残留锁的安全恢复另列待办。
