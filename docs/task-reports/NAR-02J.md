# NAR-02J · 手机在线时主动来信

负责人：`codex-main-nar02j-20260929`。基线 `075c1e8`；属于 NAR-02 的一段在线主动体验，不等于后台推送或完整剧情线。

## 问题与处理

原有手机只在初次载入或重新载入后检查导演节拍。玩家一直留在手机页面时，即使世界时间已到下一节拍，也不会自动检查，因此此前的选择、受阻报告或日历后续只能等玩家刷新或重新进入。

现在手机保持可见时每分钟检查一次已持久化的世界时钟；只有按现有倍速折算达到 30 分钟节拍，且世界未暂停、页面可见、手机已载入、没有发送中的消息时，才请求既有导演推进。一个手机实例同一时间至多发起一次检查；同一时钟锚点的自动尝试用会话存储与内存双重保护。服务器仍独立判断是否有未了事项、角色是否冷却、是否能提交节拍；没有原因时不生成来信。成功提交新消息后重新读取世界，现有锁屏通知及页面横幅按消息来源与真实时间显示。浏览器隐藏时不轮询模型，返回页面仍走已有重载流程。

## 验收证据

- `npm run check`：232 项常规测试全部通过；`npm run build` 通过。新增时间边界测试验证未到期、到期、倍速、暂停、停止、坏时间与未来锚点。未改数据库、权限或任务队列。
- 本地 Ego Lite：390px 手机视口宽度及文档宽度均 390px；1440px 电脑视口中手机容器 420px，文档无横向溢出。样板标注为合成数据，未拿它冒充真实模型回合。
- 生产 Supabase 29 项迁移校验和一致，本批无新迁移。

## 边界与接续

该机制只在手机网页处于前台时检查；用户关闭网页后没有服务器后台唤醒，也没有系统级推送。每分钟只是读时钟，到期后服务端才可能调用模型；它不会机械地每分钟生成一条消息。未在本轮等待 30 分钟做自然时间长跑，实际来信仍由已有真实数据库验收覆盖的导演事务决定。后续应以长期剧情线与可靠后台触发为独立任务，不能把本轮称为完整主动世界。
