# NAR-02D · 用户结果报告与一次承接

负责人 `codex-main-nar02d-20260928`。这是 NAR-02 的结果来源切片，不等同完整剧情结局或现实证据核验。

## 实际交付

- 用户在角色聊天中明确说出某个既有选择的结果时，模型可提议 `choice.result_reported`：完成、受阻或放弃。提议必须带本轮用户原话、该角色已知选择的 ID 和结果类型。程序再次验证原文、第一人称结果表达、与原选择的具体词语关联及角色范围。假设、转述、未知选择和替其他角色报告都不能落库；无效的可选提议不阻断正常聊天。
- 结果只标为**用户自述**，保存来源事件与世界版本，不升格成已核验世界事实；纠正结果会保留旧事件、更新当前状态。同一表述重发不会再次触发导演。
- 导演待办从“尚未承接的结果”产生；舞台指示包含确切选择标记。只有该选择对应的导演回合才能记为已承接，因别的日程或承诺发来的消息不能误消耗它。角色不能凭用户自述编造自己看过文件、现场或奖项。
- 状态沿用既有世界事件、紧凑快照、版本回执与角色上下文，没有第二套剧情数据库。旧世界没有选择字段仍可正常运行。

## 验收证据

- `npm run verify`、`npm run build` 均通过；真实 PostgreSQL 验证相反结果并发仅一项成功、回执重放、重启恢复、跨用户隔离、一次导演承接。生产 Supabase 29 项迁移校验和一致；无新迁移。
- 真实模型使用合成纪录片剧情抽样四轮：明确完成、导出受阻、放弃均产生相应报告与自然回应；“如果我完成了”只回答问题，不写结果。模型输出经同一结构解析通过。
- 单元检查覆盖不存在的选择、无具体目标的“我剪完了”、假设、其他角色、否定完成、重复与改口。

## 仍有限制

“用户说完成”并不等于世界有照片、作品或第三方确认。此任务只让状态与人物承接不丢；目标证据、真实结果核验、跨日历／相册／便签回报及完整剧情线仍属 NAR-02/03。导演推进发生在进入或回访，不承诺后台实时推送。
