# D-08 世界生成的输出上限与解析容错

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-23。状态：已完成并上线验证。

## 问题（上线实测发现）

按用户的"完成即上线"要求部署后，我在生产环境跑完整链路，**世界创建任务失败**：`world-build | failed | INVALID_AI_OUTPUT`（连续两次），而同一份代码在本地却通过。查生产库确认了失败码，随后定位根因：

1. **输出上限太小（主因）**：适配器对所有模型调用固定 `max_tokens: 4096`。世界开场是产品里最长的结构化输出（3–5 个人物，每个 persona 最多 600 字，加上开场消息和便签），而该模型的**推理 token 本身就占 1000–1700**。实测多次返回 `finish_reason: length`（截断），JSON 不完整被解析器拒绝。
2. **解析过脆（次因）**：世界开场用 `z.strictObject` 校验，模型多输出一个字段（实测出现 `notes_placeholder`）就整份作废；且解析要求整段文本恰好是 JSON，前后有说明文字或 markdown 围栏就失败。

量化证据（同一输入、真实网关）：

| 阶段 | 合格率 |
|---|---|
| 修复前（4096 上限 + 严格解析） | 1/3，随后 2/5 |
| 修复后（8192 上限 + 容错解析） | **4/4** |

失败时的原始返回特征：`finish=length`、`completion_tokens≈4096`（其中推理 994–1743）、字符数 0–2274。

## 第二次修复：结构不合法时的一次纠正重试

上限修复上线后，生产仍有 1 次 `INVALID_AI_OUTPUT`（诊断字段显示 model=deepseek-flash、prompt=world-opening-1、23909ms，说明诊断改动已生效），而同一 seed 在本地连跑 2 次均通过（其中一次输出 4803 token，旧上限必然截断）。

结论：模型偶发返回结构不合规的内容（人物数量、key/name 重复、消息引用不存在的 key 等）。对这类**确定性失败**（没有写入任何东西、世界状态未变）增加**恰好一次**纠正重试，并在第二次请求里说明违反了哪些约束；**不确定性失败（超时/上游失败）仍然不重试**，继续交给用户明确决定（有测试锁住这条边界）。

## 遗留

- 其他调用（访谈、世界回合）仍用默认 4096；访谈是短回复，世界回合上限 500 字，暂未观察到截断。若出现 `AI_TRUNCATED` 应按同一方式提高对应上限，而不是放宽校验。
- 推理 token 不可控；若模型侧推理变长，世界开场可能再次逼近上限，`AI_TRUNCATED` 会让这种失败可见而不是伪装成内容不合格。
