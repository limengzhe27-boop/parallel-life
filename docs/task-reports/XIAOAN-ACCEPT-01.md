## 本轮修复

1. **明确来源的地图**：移除按城市推导通用街区/约定地点/固定时长/联系人顺序的逻辑。新建普通与固定人物世界的模型输出可携带明确 `space` 草案；地点、路线、分钟数和人物引用经既有纯领域校验后随初始世界保存。无空间草案则真实空态，不替旧存档补地图。空间是虚构剧情设定，不是现实导航实测。新提示版本含 `space` 以便区分。
2. **到达与赴约分开**：导演指示只能说主角地图位置到了；在未有参与/见面证据前，不得声称已经见面、赴约或完成活动，亦不得判失约。
3. **导演事项接线**：当前导演回合的角色可输出最多一条 `matter.proposed`，只包含具体提议的标题、描述、跨度与本轮回复逐字引用；普通用户私聊不能创建系统事项。运行时分配 ID、世界、事件来源、版本、时间和关联角色，初始待开始且归属角色提议。不是主角已接受或做完。
4. **事项边界**：外界不能伪造别的世界/不存在的事件/人物/地点/日程/初始完成状态。重复可见同跨度同标题提议合并，不重复新增。其他角色/隐藏/遗忘事项不进入当前 NPC 上下文；整个角色回复不能自认证世界成功。玩家报告与客观证据分开，玩家自述不能领取“世界核实”奖励；前置依赖缺失时拒绝进展。
5. **验收样例修复**：真实库世界事项使用符合实际 API 的 UUID 联系人；无地点测试改为确实不返回空间草案，而非复用带地图的输出；新增贯穿 resolveTurn、数据库、只读记录、幂等、回滚、隔离的真实测试。
