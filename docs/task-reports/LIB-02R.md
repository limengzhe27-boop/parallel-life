## 先定四个不可混用的身份与版本

1. **创作稿**属于作者账号，可编辑、私有，可供 Agent 提案与私有试演；草稿文本和素材默认不公开。
2. **公共设定版本**属于 publication 的一个固定版本。内容、来源声明、虚构标记、经审核封面和内容哈希在发布后不可变；`LifeSettingContentSchema` 目前只证明结构/本地引用可解析，不证明正文脱敏、引用支持断言或素材有再分发权。
3. **可用性**是单独的、可审计的发布生命周期：`draft → submitted → reviewed → published → withdrawn`（或拒绝/紧急停止）；不要为了撤下而更新不可变版本内容。目录只查当前可见且已审核的版本，审核记录不成为公开正文。
4. **玩家实例**由玩家账号拥有，引用 `publicationId + exactVersion + contentHash` 并保存建世界时的完整设定快照。作者/平台改“最新版本”不改变这个玩家的 Seed、世界或继续游玩的结果。

当前 `LifeDraft` 必须有个人 `directionId/discoveryVersion`，当前 `ApprovedSeed` 有个人 `profileVersion/directionId` 及可选 `draftRef`、人物和素材；`world_builds.seed_id` 是主键且对 owner 有外键。故不能直接把公共版本 ID 塞进 `seedId` 或伪造一个 Discovery 方向。LIB-02B 需由集成人冻结判别式来源（个人推荐/自由构思/已发布设定）与旧数据读取规则，再改迁移/仓储。旧 Seed 和世界快照不应强制改写；无新字段的旧记录按旧路径兼容读取。

## LIB-02B 推荐接线顺序

**集成人本轮已收窄为作者私有创作稿的创建、保存、重读和不可变历史修订。** 公共版本/审核/玩家实例化是后续门槛，不能拿本轮的私有草稿持久化替代它们。私有草稿也不能把作者现实 Profile、访谈、私有素材或试演记忆默认为创作内容。

私有稿的首个实现切片建议为：`setting_drafts` 存当前版本指针与 owner，`setting_draft_revisions` 存每次保存的完整内容和 `draft_id+revision` 唯一键，历史行仅 INSERT/SELECT 且数据库拒绝 UPDATE/DELETE；`setting_draft_receipts` 以 `owner_id+command_id` 唯一，保存 request hash、返回的草稿版本。创建/保存同一事务锁 owner/草稿当前行，比较 `expectedRevision` 后追加修订和回执，再推进当前版本；相同命令同内容回同一结果、同命令异内容冲突，换命令但用旧版本则版本冲突。默认不公开、不生成世界、不提交审核。作者私有读 API 可以查看当前与历史修订，但返回必须仅限 owner。即使创作稿内容符合 `LifeSettingContentSchema`，也只是结构上可保存，不代表内容审核或来源核验。
