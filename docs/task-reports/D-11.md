# D-11 停止把没有落地的操作显示为成功

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已完成并上线验证（便签真实持久化另立 D-12，尚未做）。

## 背景

2026-09-23 审计发现一批"看起来成功、其实没有落地"的问题，多数由并发提交引入。用户要求一并优化。本项处理其中不涉及新服务端能力即可修好的部分，避免用假成功掩盖缺失。

## 修复

|问题|原因|现在的行为|
|---|---|---|
|手机内消息"乐观上屏"被硬编码为已发送|`world-app-data.ts` 对所有消息写 `status:'sent'`；发送失败不回滚、不标记，`retryMessage` 从未接线|发送后先以 `pending` 上屏；服务端提交成功才移除本地条目并由服务端消息（唯一可信来源）显示；失败则保留该条并标 `failed`，气泡显示「发送失败」+「重试」，重试走真实重发。服务端消息仍是唯一 `sent` 来源|
|便签提示"便签已保存"|只写 localStorage，`onSaveNote` 从未传入，却无条件返回 committed|集成层用 `noteSync: 'server' \| 'local'` 如实声明；当前为 `local`，界面显示「已保存在这台设备」并说明"同步尚未接入，换设备或清除数据会丢失"，不再声称已保存|
|无邀约时伪造日历通知|世界有角色但无约定时，前端合成一条"日历提醒 · 阶段备忘"|删除该合成逻辑：没有真实约定就不显示日历通知|
|联系人会话里出现别人的日历卡|回退到 `invitations[0]`|只显示参与者包含该联系人的约定，否则不显示|
|开场时间戳被前端二次偏移|服务端已错峰保存，前端又按旧逻辑再偏移一次（对旧世界叠加、对新世界失效）|前端按服务端存储的时间展示，不再二次偏移|

## 验证

- `npm run check`：**103 项**单元测试通过（`tests/world-app-data.test.ts` 新增"只有服务端确认的消息才算已发送、本地在途保持真实状态、时间不再二次偏移"）。
- `npm run build` 通过。
- **生产实测（用户本人会话，https://parallel-life-nu.vercel.app）**：
  1. 正常发送一条 → 显示为已发送，无失败标记；
  2. 用 CDP 阻断 `*/worlds/*/messages` 后发送 → **1.5 秒内如实显示「发送失败」+「重试」**，文本保留；
  3. 恢复网络点「重试」→ 成功，服务端 version 2、7 条消息（两条都真正落库）；
  4. 桌面不再出现伪造的日历提醒；
  5. 便签页显示「便签同步尚未接入：内容只保存在当前浏览器，换设备或清除数据会丢失。」，且不再出现「便签已保存」。
