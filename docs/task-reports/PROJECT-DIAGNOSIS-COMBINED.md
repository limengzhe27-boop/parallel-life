## 零、小安的三大病症（保留）

```
① 机械化：把自然叙事做成了工单审批
② 补丁化：用无数硬编码 if/正则缝补
③ 割裂化：后台 / 手机 / 现场各自为政
```

**我的补充：还有第 ④ 条，它是前三条的成因**——

**④ 模型碎片化 + 交付基线混乱**：同一个概念在链路上有 4~6 套字段名与中间映射（每加一个功能就要写一层兼容清洗）；同时存在多个工作树/副本并行推进，**验收基线不统一**（我自己就因为本地副本落后 origin/main 350 个提交而给出过错误结论）。没有单一领域模型 + 没有统一基线，就必然会持续产生 ①②③。

## 三、根因归纳（五条）

1. **领域模型碎片化**：Actor/Persona/Contact 等概念被四五个模块各解释一遍，靠 `||` 兜底串联（小安第 5 条 + 我第 ④ 条）。
2. **用"证据审批"替代"叙事推理"**：为避免模型乱来，引入了 `inputQuote`/`observationIndex`/严格状态机，结果把自然语言玩成了对暗号（小安第 3 条）。
3. **Demo 逻辑沉入通用引擎**：R17/修车单/老周特判写进 `scene-planner.ts`，导致新世界仍跑旧状态机（小安第 2 条，已核实）。
4. **防御性补丁堆积**：每遇一次模型犯错就往提示词加一句警告 + 加一个校验分支，提示词与校验同时膨胀（小安第 6 条 + 我第 A/C/D 条）。
5. **测试固化实现细节 + 基线不统一**：测试保护的是"错误码/调用次数/特定 JSON"，改动即爆红；同时多副本并行让"以哪份代码为准"都成问题（小安第 5 条 + 我第 G 条）。

## 四、改进方案（分四批，含验收标准）

> 原则：**不动地基**（事务/幂等/RLS/Outbox/边界检查），只做"去官僚化 + 统一模型 + 基线治理"。一批一个分支、一个负责人、集成人合并。

### 第 1 批 · 立刻见效（低风险，1~2 天）
| 项 | 做法 | 验收 |
|---|---|---|
| 试演常驻 | `isDirty` 时保留 iframe，叠角标"以已保存版本运行" | 改表单时手机界面**不消失**；提示与画面不矛盾 |
| 删"待确认问题" | 移除 workbench `:893` 入口与 `:964` 面板，改行内提示 | 后台无该面板；无功能回归 |
| 长文本不再拦 | 超长改为"保存但不进入提示词"+ 字数提示 | 编导不会因写长被拒 |
| 角色下限放宽 | `characters.min(2)` → `min(1)`（并同步校验与文案） | 1 个角色即可试演 |
| 场景底色分层 | 底色仅在**首次进入/环境变化**时展示；无变化时明说"这里暂时没有新动静"并给 2~3 个动作 | 不再逐回合重放同一段 |

### 第 2 批 · 场景去官僚化（核心体验，3~5 天）
1. **在场人物改由导演派驻**：场所有候选池，导演按 agenda（欠回应/未定约定/必发事件）决定"此刻谁在"；**进入场景若无人，必须明说并给选项**（等人/去别处/推进时间）。
2. **动作分级**：对话/观察/移动/越界；越界动作要有**世界一致性裁决 + 可见后果**（有人报警、店主质问、消息与记录出现新条目）；规则禁止的内容要说明"是规则拦下"，不得让玩家误以为世界无反应。
3. **场景节拍并入导演**：`谁出现 → 发生什么 → 推进哪条必发事件 → 留痕`；打通第五节 E 条（必发事件当前无人消费）。
4. **删除 R17/修车店硬编码**：把动作模板改为**世界可配置的动作类型**（或直接移除），通用引擎里不得出现具体 Demo 名词。

### 第 3 批 · 事项回归"叙事推手"（3~5 天）
- "眼下的事"降级为导演动态生成的**线索/备忘**：只展示与指引，**不再阻断**玩家推进；
- `inputQuote`/`observationIndex` 从"必经路径"改为**可选证据**：玩家随口一句话也能推进，只有需要精确对账时才要求证据；
- 状态机简化为 `进行中 / 已完成 / 暂缓`，去掉"未提供标准步骤证据即 blocked"的判定。

### 第 4 批 · 模型统一与治理（持续）
- **单一领域模型**：确立 `Actor`（世界内角色）为唯一模型，`ActorEditorForm`/`PublishedActor`/`Contact` 只作为**编译层/展示层**的显式映射（一张转换表，禁止 `||` 兜底）；
- **提示词治理**：把"负面警告"改为**结构化约束 + 少量关键规则**，设定提示词预算上限并纳入评审；
- **测试策略**：守门测试聚焦"用户体验契约"（能玩通、有反应、不泄漏、不被卡）；删除/重写固化调用次数与特定错误码的用例；
- **基线治理**：主 checkout 只做集成，执行者一律在独立工作树；每份报告必须写明**基线 commit**；验收前统一 `git fetch && checkout <sha>`。

## 六、一句话总结（合并版）

> 小安说得对：**我们用企业级审批引擎束缚了一个本该有灵性的 AI 叙事产品。**
> 我补充的是：这套审批引擎之所以长成这样，是因为**领域模型碎片化 + 用证据校验代替叙事推理 + Demo 逻辑沉进通用引擎 + 测试固化实现细节 + 基线不统一**。
> 好消息是：**地基（事务/幂等/隔离/边界）是扎实的，人生记录四段化已经开始兑现**——所以这需要的是**分批去官僚化与统一模型**，而不是推倒重写。
