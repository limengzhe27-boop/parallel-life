# NPC 人感第二批任务（按最新产品意见修订）

**状态（2026-10-23）：P0 sticker、P0 撤回、P1 记忆/服务端主动均已完成并部署；证据见 `44-193-PROACTIVE-SCHEDULER.md` 和 `docs/DEPLOYMENT.md`。20 回合抽样中上游 unknown 已如实记录，不宣称发送率 100%。**

## 产品边界修订

- 表情包不是“玩家明确索取”的功能；
- 表情包是 NPC 自然表达的一部分，可以单独成条，不必配文字；
- 选择依据是“此刻想表达的含义/情绪”，不是每个角色的固定偏好子集；
- 不要求每条消息都有文字；
- 不用文字 emoji 冒充图片表情包；
- 玩家没有要求时也可以自然发表情包，但不能滥用。

## 任务

### P0 sticker 行为

1. 表情包协议改为结构化字段（`stickerId`），不再依赖自然语言 marker。
2. `statement` 允许 text 为空、stickerId 非空；至少一个非空。
3. 语义标签：崩了/好笑/无语/怀疑/就这/摆烂/冲/在吗/睡了/饿了/困/摸鱼/加油/可以/绝了/好/赞/疑惑/拒绝/晚安。
4. 选择依据：当前对话含义 + 情绪 + 关系，不使用固定角色偏好。
5. 独立选择调用或同轮结构化字段；不允许只口头答应。
6. 失败降级文字；不阻断主发送。

### P0 撤回

- 从 `[[recall:last]]` 改为正式 `recallLast` 决策；
- 服务端审计；
- 原文不再下发客户端；
- 撤回后可重说。

### P1 验收

- 干净世界必须先有 agent runtime，否则仅可读；
- 20 条自然聊天抽样，观察 sticker 是否自然、非滥用；
- 表情包单发/文字+表情包两种形态；
- 10 次 exact 承诺抽查 + fuzzy 记错不报错。

## 不做

- 不做每角色固定表情包偏好；
- 不把表情包绑定到玩家请求；
- 不生成新表情包；
- 不用文字 emoji 代替图片；
- 不让 sticker 影响事件推进或发送成功率。
