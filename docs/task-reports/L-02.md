# 任务交付报告：L-02 历史分支：从基线与事件恢复指定版本，新建人生；旧历史不改写、资源引用受控

## 一、任务背景与目标

在《人生剧本》的沉浸式生活体验中，玩家在经历一段人生旅程后，往往会产生“如果当时做了另一个选择，生活会怎样”的探索愿望。
与“从头重新开始”（即清空一切重新创生）不同，**历史事件分叉（History Branching / Forking）**要求从指定历史时刻分流出一条全新的平行轨迹：
1. **从基线与事件精确恢复指定版本 (Reconstruct Historical Version from Baseline & Events)**：
   - 依赖 `parallel_life.world_initial_snapshots`（不可变版本 0 初始基线）与 `parallel_life.world_events`（版本 1..N 的真实不可变事件流）；
   - 通过纯函数历史重放器 `replayWorldHistory(initialState, events, forkVersion)` 精确还原目标历史版本的全部状态；
   - 提取并重组对应版本的消息投影、约定行程、事实认知与时间戳，构成新分支人生的全新不可变初始快照。
2. **新建人生 (Create New Life)**：
   - 为分支生成全新独立的 `worldId`；
   - 新人生版本从 0 开始起步，其初始基线即为目标分叉时刻的完全状态，使得新分支人生能够无缝承接分叉前的全部记忆、人设与历史，并独立开展新的生活；
   - 在底层 `parallel_life.worlds` 准确记录 `parent_world_id` 与 `fork_version`，满足数据库触发器 `world_fork_check` 的因果一致性约束。
3. **旧历史不改写 (Old History Never Rewritten)**：
   - 父世界的版本、事件流、消息记录、时间时钟与状态快照**完全不发生任何突变**；
   - 新世界的新增回合与后续事件严格归属于新 `worldId`，杜绝任何历史污染与逆向篡改。
4. **资源引用受控 (Controlled Resource References)**：
   - 针对角色立绘、参考照片与视觉素材（`assets`），严格校验所有权（`owner_id = userId`）与生命周期状态（`status = 'ready'`）；
   - 若某张历史照片已被用户删除或状态失效，分叉逻辑安全过滤或置空，绝不因脏引用导致外键冲突或资源泄漏。
5. **多租户与边界防护**：
   - 仅允许分叉自己所属的未软删除世界；
   - 严格校验 `0 <= forkVersion <= parentWorld.version`；
   - 标题支持自定义，默认继承 `${parentTitle} (分支)` 并校验 1~60 字长度边界；
   - 非法请求统一遵循统一错误规范抛出 `NOT_FOUND` 或 `INVALID_COMMAND`。

## 二、架构契约与代码变更

### 1. 契约定义 (`src/contracts/life-management.ts`)
- 扩展 `WorldListItemSchema`：
  - 新增 `parentWorldId: z.string().nullable().optional()`
  - 新增 `forkVersion: z.number().int().nullable().optional()`
- 新增分叉请求与响应契约：
  - `WorldForkRequestSchema`: `{ forkVersion: number, title?: string }`
  - `WorldForkResponseSchema`: `{ world: { id, parentWorldId, forkVersion, title, version, status, storyTime, createdAt } }`
- 新增历史检查点契约：
  - `WorldForkCheckpointSchema`: `{ version: number, occurredAt: string, storyTime?: string, summary: string }`
  - `WorldForkCheckpointsResponseSchema`: `{ worldId, currentVersion, title, checkpoints: WorldForkCheckpoint[] }`

### 2. 仓储层实现 (`src/modules/world/infrastructure/postgres-world-repository.ts`)
- **`listUserWorlds` 增强**：
  - SQL 投影增加 `w.parent_world_id, w.fork_version`；
  - 映射并返回每个世界的分叉溯源元数据。
- **`getForkCheckpoints(userId, worldId)`**：
  - 查询指定人生的版本历史；
  - 提取版本 0（初始基线）及每一轮真实事件的历史发生时间、故事时间和关键剧情摘要（从 `userText` 或 `message.received` 提取），供前端展示时间线分叉节点。
- **`forkWorld(userId, parentWorldId, forkVersion, options)`**：
  - 开启事务与行级共享锁（`FOR SHARE`），核实父世界所有权与未删除状态；
  - 校验 `forkVersion` 在 `[0, parentWorld.version]` 闭区间内；
  - 解析并规范化标题，默认 `${parentRow.title} (分支)`；
  - 提取不可变初始快照 `world_initial_snapshots` 与 `approved_seed`，对其中的资产引用执行受控合法性过滤；
  - 根据 `forkVersion` 状态重构：
    - `forkVersion === 0`: 直接复用初始基线；
    - `forkVersion > 0`: 检索 `version <= forkVersion` 的事件，利用 `replayWorldHistory` 重放，并联合提取投影表（`world_messages`, `world_appointments`, `world_media_requests`, `world_facts`）在目标时刻的切片；
  - 生成 `newWorldId = randomUUID()`，组合构建全新世界的不可变基线 `newBaselineState`；
  - 写入 `parallel_life.worlds`（记录 `parent_world_id = parentWorldId, fork_version = forkVersion, version = 0`）；
  - 写入 `parallel_life.world_initial_snapshots`（记录 `version = 0, state = newBaselineState`）；
  - 写入 `parallel_life.world_clock`（对齐分叉时刻的故事时间，默认未暂停）；
  - 受控继承角色绑定 `world_person_bindings`（资产就绪才绑定，失效则安全脱钩）；
  - 父世界未发生任何 UPDATE 或 DELETE 操作，保障旧历史不可篡改。

### 3. API 路由集成 (`src/app/api/v1/worlds/[id]/fork/route.ts`)
- `GET /api/v1/worlds/[id]/fork`：
  - 鉴权并返回当前人生的分叉历史节点列表（含版本号、发生时间、故事时间与摘要）；
- `POST /api/v1/worlds/[id]/fork`：
  - 鉴权并校验请求体 `{ forkVersion, title? }`；
  - 调用 `forkWorld` 完成原子分叉，成功返回 201 Created 与新世界的概要信息。

## 三、测试与质量证据

### 1. 真实 PostgreSQL 集成测试 (`tests/integration/history-branching.test.ts`)
8 项核心测试全部在真实测试数据库（`parallel_life_test`）中通过：
1. **`getForkCheckpoints` 检查点检索**：成功返回版本 0（初始基线）、版本 1 与版本 2 的时间与摘要；
2. **`forkWorld` 分叉创建新人生**：从版本 1 分叉出全新世界，版本重置为 0，状态为 active，准确继承版本 1 的消息，且不含版本 2 的消息；
3. **旧历史不改写 ("旧历史不改写")**：核对父世界在分叉后版本依然为 2，全部 4 条消息和 2 个事件原样保留，`parent_world_id` 依然为 null；
4. **分支人生独立演进**：在新世界提交全新的选择回合（预期版本 0 -> 1），成功前进到版本 1 并增加新分支消息，父世界完全隔离不受影响；
5. **默认标题派生**：不传标题时自动派生 `${parentTitle} (分支)`；
6. **多租户与边界防护**：跨用户查看/分叉严格返回 `NOT_FOUND`，负数版本、超限版本、空标题、超长标题严格拦截并返回 `INVALID_COMMAND`；
7. **受控资源引用校验**：测试已就绪资产的合法继承，以及资产被软删除后分叉自动剔除损坏引用，保护外键安全与数据纯洁性；
8. **列表元数据核验**：`listUserWorlds` 准确返回 `parentWorldId` 与 `forkVersion`。
