# ACTOR-PROGRESSION-DIAGNOSIS-51：人物为何“有消息、没推进”

2026-11-05；独立只读诊断 `astra-progression-diagnosis51-20261105`；代码基线 `3ad5048e`。当前工作树含 root-director51 未提交修改，本报告不修改这些文件。

## 1. 结论

**最近的问题不是 NPC 不说话，而是说了很多话却没有下一步。** 本地原档最近30小时有 **776次真实 attempt、568次committed、399条人物消息，但0个计划、0次实际执行、六个人物目标/计划全为0**。人物在主动发消息，却没有把任何一次“参与”变成可持续的行动。

三个同时存在的问题：

1. **“参与”被一条消息结清**：真实 `engage` 响应大量是 `followUp:null`、`planIntents:[]`、`statements:1`；协议只在 `defer/need_information` 强制 followUp，`engage` 可以没有下一步。李之之当前15条已参与事件中 **14条是 `engage/none`**，没有计划、责任或后续。
2. **导演任务确实存在，但被定义为未来建议**：30小时内61次导演决定、35条人物请求，覆盖六人；既有具体作者事件（假扮男友、医院、同学聚会、债务），也有大量泛化“关心/询问”。具体任务会被 quiet/decline，接受的任务又只发消息；任务没有落到执行层。
3. **自主复盘在持续购买低价值轮次**：30小时内 `npc_agenda_review` 444次、`npc_own_condition_ready` 66次，人物问题累积到李之之22条open。系统用调用次数制造了“活跃”，没有制造推进。

另外，**后台主动进程当前已停止**；停止前大量轮次在模型调用前被 `NPC_AGENT_SNAPSHOT_LIMIT` 拒绝。当前3218运行的是较早的 `build-director50-global`，不包含正在进行的 stage51 修复。

## 3. 代码上的断点

### 3.1 engage 可以没有下一步

HEAD 中 `bindNpcConsideration` 只在 `defer/need_information` 强制 followUp：`npc-model-protocol.ts:1806`。责任对象只在 `consideration.followUp` 存在时创建：`npc-model-protocol.ts:1819-1820`。

提交时，`engage + 有消息` 会把共享事件标为 active，但不会为人物创建计划/动作/责任：`agent-narrative-repository.ts:699-700`。 生命周期随后看到没有 goals/plans/responsibilities，就给出 `followUp:'none'`：`episode-participation-lifecycle.ts:184-195`。

于是形成：

```
导演“关心/询问”机会
  → 人物 engage + 发一条消息
  → followUp=null，无计划/无责任
  → 人物侧 followUp=none（这条参与没有下一步）
  → 共享事件仍 active
  → 下一轮自主复盘再发一条关心
  → 循环
```

### 3.2 有任务，但任务只是 future_proposal_only

30小时内导演产生 **61次决定、35条人物请求**，覆盖六个角色。具体任务确实存在，例如：

- “主角假扮青青男友应付追求者，并回应感情试探”
- “母亲出意外，青青打电话让男主带舒雅婷孩子赶往医院”
- “主角参加同学聚会，发现林白语曾经默默喜欢过自己”
- “主角被卷入李之之的债务纠纷，并决定是否向舒雅婷求援”

这些请求确实交付到了人物：NPC收到 `npc_episode_consideration`，并返回 engage/decline/quiet。但提示明确把导演任务定义为未来建议：

- `director-agent-model.ts:356`：“任务是未来建议，不是既知事实或强制服从。”
- `npc-agent-model.ts:71`：“导演只是机会建议，可自主参与、调整、暂缓或拒绝。”
- 任务包 authority 为 `future_proposal_only`：`actor-episode-intent-repository.ts:218`。

所以“收到任务”不等于“必须执行”。真实青青的“假扮男友”任务被交付，她的原话理由是：

> “director_future_suggestion仅为参考，不强制执行；目前无新玩家消息且旧话题已自然延续，暂无自主参与动机。”

`choice=quiet`。这不是投递丢失，而是设计与模型判断共同作用。

### 3.3 最近任务大量泛化，接受后也没有执行

真实快照中的机会主题近义重复：

- “晚间关心玩家近期生活是否顺利，有无难处或心事”
- “询问玩家近期是否有困难或烦心的事，提出夜间照顾”
- “关心主角近况，试探其是否遇到不顺”

它们没有具体行动、地点、时间、障碍或完成条件；`proposedInteraction` 本身就是“主动联系/表达关心”。人物发完这句话，事件已经没有可执行内容。

导演提示本身要求“同一请求无新依据不能重复确认”：`director-agent-model.ts:346-347`。但实际机会仍以旧导演决定为唯一依据，属于把“还在等”当成“再关心一次”的理由。

即使换回具体任务，承接后也没有执行：30小时内26条 `engage` 全部只发消息、0计划、0动作；所以“任务存在”和“任务可执行”是两个独立问题。

### 3.4 自主复盘数量过大

30小时444次 agenda review，平均每个活跃人物每小时约2–3次。单次消息可能自然，但系统没有“没有新信息就不买这一轮”的硬门槛；提示虽然允许 quiet，却也鼓励“关心、分享、延续话题”。结果是大量低价值对话和问题堆积，真正有具体目标的事件反而被淹没。

## 5. 不应误判为原因

- **不是导演没有派任务**：30小时61次导演决定、35条人物请求、覆盖六人；问题在任务只是未来建议、承接后又没有执行。
- **不是运行时吞消息**：真实 raw 里有 `statements`，提交也保存了消息。
- **不是模型完全不调用**：568次committed，399条消息。
- **不是解析器把计划删掉**：raw 本身就是 `planIntents:[]`、`executions:null`。
- **不是单一模型配置**：此前grok4.3、gpt4.1-mini等对照都出现同类“只聊不推进”。
- **不能靠再调几次模型解决**：当前机会没有具体下一步，调用越多只会产生更多关心消息。

## 6. 建议的最小修复

按优先级：

1. **把 engage 变成有下一步的承诺**  
   `engage` 必须至少满足一个：具体计划/执行动作，或带关联问题的真实等待；只有一条消息、没有下一步时，不应把该参与当作“已承接完成”。可以保留“先联系”的短事件，但应在消息后显式关闭该事件，而不是让它以 active 状态无限重派。当前 stage51 自动补 self duty 是必要的第一步，但还需让下一次 wake 必须产出具体步骤，不能只再发一条消息。

2. **把“建议”和“已承接的第一步”分开**  
   导演可以继续给未来建议，但每个机会要同时给出“现在可执行的第一步”，并写清具体变化、涉及人物、地点/条件、完成或失败判据。人物接受后，这一步必须转成 plan/action 或真实等待；只有消息、没有下一步时，不应算完成。禁止把“关心玩家/询问难处”当作独立剧情事件反复派发；没有合格事件时应 quiet，而不是用关系关怀填满预算。

3. **减少自主复盘空转**  
   只在有新观察、新结果、到期条件或玩家新输入时给普通 agenda review；没有新信息时不要每15–20分钟购买一轮。保留人物合理安静的权利，也保留真正的主动联系，但不要把“发消息”当推进指标。

4. **修运行时容量与进程**  
   先量化 stage51 对 `state/sources/observations/episodeFollowUps` 的裁剪，确认 preflight 通过；再重启主动 worker。不要用重启掩盖超限，也不要在未验证时继续付费空跑。

## 7. 验收建议

只选一个具体事件做有界验收：

- 导演给出一个有明确下一步的机会；
- 人物 `engage` 后必须出现可执行的 plan/action，或一个带关联问题的真实等待；
- 下一次 wake 检查是否沿该 plan/action 前进，而不是再发一条泛化关心；
- 记录 `planIntents`、`executions`、`followUp`、问题/责任关联和实际消息，不以消息条数或 health 200 作为通过。

如果下一次仍然只有消息、没有计划/执行，就说明“事件性”问题没有修好，不应继续增加调用次数。

## 8. 产品契约修正：导演管事件，人物管立场

用户 2026-11-05 澄清后的正确关系：

- **导演负责剧情推进**，不能把“剧情是否发生”绑在单个 NPC 是否同意上；NPC 拒绝不能等于剧情停住。
- **人物负责自己的立场和做法**，可以拒绝、调整、改写具体说法，不必逐字照任务演；但不能把当前事件当没发生。
- **拒绝是合法分支，但必须有后果**：导演要准备“她拒绝之后发生什么”，而不是把同一任务再派一遍。
- **关心/鼓励只能偶尔作为关系节拍**，不能成为默认填充；每次主动消息应带来具体变化（信息、邀请、行动、冲突、披露、决定）。

### 8.1 任务应该包含什么

导演任务不能只有 `topic / personalObjective / proposedInteraction` 这类“未来建议”。至少要有：

|字段|含义|
|---|---|
|当前情况|现在发生了什么、为什么是现在、人物已知什么|
|当前可执行的第一步|人物此刻能做/能选择的具体动作，不是“关心一下”|
|压力/代价|不处理会发生什么；拒绝会失去/触发什么|
|完成/失败判据|什么算这一步推进了，什么算没推进|
|拒绝后的下一拍|她拒绝时，导演准备让谁/什么接上，剧情如何继续|

人物可以只完成“当前一步”，不必把后续整段剧情一次演完；但这一步必须落地，不能只发一条消息。

### 8.2 运行时必须改的语义

1. **engage 不能只靠消息结清**：必须有具体 plan/action，或带关联问题的真实等待；只有消息没有下一步，不算承接完成。
2. **quiet/decline 不能是 no-op**：要作为明确立场回传导演，导演据此推进下一拍；不能把同一任务无新依据地重派。
3. **消息必须改变状态**：一条主动消息至少要产生信息、邀请、约定、行动、披露、冲突或明确决定之一；单纯“最近怎么样/有没有难处”不作为独立剧情事件。
4. **不以消息数量衡量推进**：验收看 plan/action、事件阶段、责任/约定或真实结果，不看 messages 计数。

### 8.3 不能怎么做

- 不能为了推进剧情取消 NPC 的拒绝权，也不能替人物写固定台词或强行接受。
- 不能要求每次对话都逐字执行任务；人物可以调整方式，只要不回避当前事件。
- 不能继续用“关心/鼓励”填满导演预算；没有合格事件时，导演应 quiet，或推进已有事件，而不是造泛化关怀。

### 8.4 NPC 主动消息如何推进

**主动消息不是“定时醒来找话说”，而是“已有意图在正确故事时间被执行”。** 合法来源只有：

|来源|触发|作用|
|---|---|---|
|导演事件/任务|当前事件到期、人物需要回应|推进主线|
|人物自己的计划|`at_or_after` 等故事时间条件满足|执行承诺的下一步|
|约定/责任|约定临近、到期、逾期|赴约、提醒、改期、追问|
|新观察/后果|玩家行动、第三方事件、发现秘密|回应真实变化|
|关系问候|偶尔、有具体触发|维持关系，不计作剧情推进|

当前问题不是没有主动消息入口，而是**计划驱动入口是空的**：30小时0计划，26条 `engage` 全都没有 plan，调度只能反复走 `npc_agenda_review`，于是主动消息退化成泛化关心。

正确实现：

1. 人物接受任务时，必须形成自己的下一步计划（`planIntents`），而不是只发一条消息；未来动作写入 `at_or_after` 故事时间。
2. 到故事时间，现有 `plans` / `planReconsiderations` / `appointments` 调度器唤醒人物，让它执行该步并发消息；消息是计划的可见结果，不是独立 timer。
3. 计划必须带下一步或复查条件；发完消息后，要么更新责任/等待真实答复，要么安排下一次到期，不能停在 active。
4. 没有计划、没有到期条件、没有新观察时，不主动发消息；关系问候单独限额，不能填补所有空窗。

这样“推进时间”由世界时钟和计划条件负责，NPC 的主动消息只是到期执行；而不是每15分钟叫醒人物问“要不要关心一下”。
