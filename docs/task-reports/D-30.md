# D-30 对话中主动推荐分支 / 一句话创建分支并进入

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已完成并上线（单元与构建通过；浏览器点击级验证待补，如实记录）。

## 用户要的闭环

> 进入后和 Agent 对话，聊出东西 → Agent **主动推荐分支**；或用户提出要创建分支 → **直接创建出来并进入体验**。

## 现状核对（改之前）

- 已有：对话内的引导卡片（"向导已记录下你的关键经历。想看看…平行世界的你正在过着怎样的生活吗？"）、确认后创建并进入的模态、以及**仅覆盖"开始/开启/进入/体验这个分支"**的意图正则。
- 缺口：**"帮我创建一个分支""给我建个分支""我想试试另一条路""有什么分支吗""推荐一下"** 这些说法**完全识别不到**——用户说了，系统无反应；也没有区分"只是看看"与"真的给我建一个"。

## 改动

| 文件 | 改动 |
|---|---|
| [branch-intent.ts](../src/features/interview/branch-intent.ts)（新，纯函数 + 测试） | `routeBranchIntent(text)` → `enter` / `create` / `recommend` / `none`：进入类优先（不花钱）；创建类覆盖"帮我创建/给我建/生成一个/我想试试另一条/就按这个来"；推荐类覆盖"有什么/有哪些/推荐/看看/推演…分支或方向"；日常闲聊不误触 |
| [interview-app.tsx](../src/features/interview/interview-app.tsx) | 用意图路由替换原正则，并把**意图类型**一并传给对话区（原来只传了一个时间戳） |
| [proposal-thread.tsx](../src/features/interview/proposal-thread.tsx) | 三种行为分流：**进入**（已有世界直接进手机）／**创建**（用户明确要 → 先推演（如需要）→ **直接建第一个方向并进入体验**）／**推荐**（只展示：有方向就打开确认框，没有就推演） |

**设计取舍（如实）**：用户明确说"帮我建一个"时视为**已授权创建**（建世界会花钱与写数据），所以直接建并进入；只说"看看/推荐"时**不建**，只展示。原有"必须确认后才创建"的模态在推荐路径上保留。
