# NAR-02I · 受阻后的人物建议

负责人：`codex-main-nar02i-20260929`。基线 `56ab2ac`；这是 NAR-02 的一段受阻承接，不等于完整长期剧情系统。

## 问题与处理

用户报告某项选择“卡住了”后，导演原本只能让知情人物回应一次。人物即使在聊天里给出具体办法，该办法也不会作为选择的后续保存；用户回到便签只看见“遇到阻碍”，很难继续这条线。

现在，导演针对已保存的受阻报告唤起同一人物时，人物可以提出一条新的具体建议。建议必须逐字来自该人物本轮已提交的回复，并与受阻选择和来源事件绑定；普通安慰、没有说出口的办法、其他人物的话均不会入账。缺少结构标记时，只对本轮回复里的明确行动片段做保守摘录，仍经过同一领域校验。建议不是玩家已采用的决定，也不表示问题已解决。用户之后报告新结果时，旧建议从当前选择投影退出，历史事件仍保留。

手机便签的“走过的路”按用户原选择、用户自述受阻、人物后来的建议展示；消息和便签读取同一世界事件。角色下轮上下文会过滤用户已遗忘的选择及其嵌套建议来源，避免从选择记录绕回。

## 验收

- `npm run verify` 与 `npm run build` 通过；其中 34 项真实 PostgreSQL 集成测试通过。新增真实世界测试覆盖受阻→同人物建议→刷新读取、重复命令回执、跨用户隔离。领域测试覆盖伪造引语、其他人物、重复建议、效果先后顺序，以及用户后来报告完成后旧建议退出。
- 合成真实模型抽样：人物回复“先把开头整段拿掉试一版”，结构化建议逐字取自这条消息，未声称用户已按建议行动；仅做一次样本，不将其当成普遍生成质量保证。
- 本地开发样板 390px 手机便签可见“受阻”和“有新建议”，无横向溢出；1440px 电脑视口中的手机容器 420px，无横向溢出。样板明确标注为合成数据。
- 生产 Supabase 29 项迁移校验和一致，本批无新迁移。

## 仍有限制

人物建议的现实可行性不能由引用校验单独证明；现有世界只保留有界的近期选择，尚无完整长期剧情目标、阶段和结局。导演仍主要在进入／回访时推进，没有后台实时唤醒；这批不接入图片生成。
