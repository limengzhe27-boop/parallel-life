# CHARACTER-SAVE-21 · 长人物设定保存

## 问题与原因

现有正式草稿的整份内容已接近旧的 65,536 字节上限。单个人物每个维度允许 4,000 字，但整份剧本仅容纳约 64 KiB；因此李之之第一维之后，刘胜男及其他维度写入会被拒绝。保存入口把容量错误统一显示为「请检查填写的内容」，人物区还误写「填写即自动保存」。

## 修复

- 整份作者草稿上限改为 1 MiB；仍保留每字段、结构、层级与 JSON 值数约束，运行时可执行世界的独立紧凑预算不放宽。
- 保存/新建 HTTP 请求上限与数据库草稿、发布版本、幂等回执约束同步调整；超限返回明确且不丢输入的提示。
- 人物区状态改成实际行为：「有未保存修改 / 已保存」。
- 明确未来协议或非法人物键/姓名不能在发布检查中被默认值吞掉。

## 验证

- 单元全量 `npm run check`：2308/2308；`npm run build` 通过。
- 独立真实 PostgreSQL 发布与 HTTP 集成：25/25。六人物五维长文本超过旧限额，保存、回读、发布版本原文一致；权限、并发、幂等、回滚和非法稿检查保持通过。
- 正式库迁移前 58/58 校验和一致；0059 已应用，59/59 校验和及三条存储约束核对通过。
- 针对当前六人物真实草稿只读模拟：给李之之和刘胜男合计追加 10 个维度各约 2,000 中文字符后，整稿 125,572 字节，符合新草稿契约；没有写入或改动用户草稿。
