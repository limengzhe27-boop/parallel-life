## 实际验证

独立本地 PostgreSQL 55660，新建合成世界，走原世界初始化/人物状态初始化/epoch切换、`npcAgentAdvanceServices`、当前 `npc-wire-v15`、内核及事务消息投影。不直接插入消息、计划、执行结果或修改attempt终态。

- 两人物 goals/plans 均为空，自主上下文真实 origin=wake、source=actor_local；受控模型分别表达心情/关心，单批两人物各调用一次并落库两条消息。
- 同真实分钟再次 advance，人物不再调用，消息ID完全不变。
- 测试Date推进60秒（不等候、不改世界倍速/生产时钟）后，两个原人物各有下一次机会，累计四次调用/四条消息/四条committed attempt，无重复ID。
- 两次无候选刷新合计仅产生一次既有导演quiet review；首次两人物执行不需要此前导演审批，后续刷新也未重买quiet review。因此本旅程总成本为四次人物调用加一次导演调用，不能宣称只有四次模型调用。
- 另一世界首次真实调用受控adapter抛网络不确定异常，原链路落 `unknown_after_send`。该人物总调用保持一次，另一人物仍可通过原advance提交真实消息。重复advance不增加人物调用或消息；没有篡改unknown，也没有使用固定生产台词。
- 模型执行时本地PG无pl_app idle-in-transaction，未长期持有生成事务。
