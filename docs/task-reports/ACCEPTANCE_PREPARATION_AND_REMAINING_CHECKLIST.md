## 二、第二阶段真实验收准备（针对主 Agent 体验评测）

为配合主 Agent 进行公网真实大模型连续体验验收，新架构交付团队已梳理排查路径与最短复现边界，重点防御并监控以下 5 类高频问题：

### 1. 无法进入或没有回应（Entry & Hang）
- **可能诱因**：
  - 角色开局消息未能及时从作品设定完成水合；
  - 任务或指令在处理中因未知原因挂起。
- **定位与恢复路径**：
  - 在试演界面查看状态胶囊：如显示为 ` quiecent`、`waiting_player` 或 `in_progress`；
  - 若为 `known_failure` 或 `unknown_result`，界面显式出现“重试”或“检查回执”按钮，点击后带原指令 ID 幂等恢复，不产生重复扣费或重复事件。

### 2. 人物承诺丢失、重复询问（Commitment Loss & Repetitive Queries）
- **可能诱因**：
  - 模型在私聊中答应了分工/约定，但未输出结构化 `AgentProposal`，或者内核未将状态写入 `actor_agent_states`。
- **已固化保障机制**：
  - Prompt v17 与内核校验已严格区分闲聊愿望与实质承诺；
  - 实质承诺自动持久化为 `responsibilities` 与 `goals`；
  - 预约日程生命周期现已形成闭环（`propose` $\rightarrow$ `fulfill` $\rightarrow$ `cancel`），NPC 不会遗忘已达成的约定，也不会无故重复询问已拒绝或已取消的邀约。

### 3. 事件长期停滞或重复触发（Stall & Repetitive Triggers）
- **可能诱因**：
  - 编剧预设事件的先决条件（时间、地点、前置剧情）未达成，但系统未告知原因；
  - 处于合理安静阶段却被误判为卡死。
- **定位机制**：
  - 运行状态纯函数明确区分 `conditions_not_met`（条件尚不满足）与 `quiescent`（剧情合理平静等待），并在后台用编剧语言提示“事件尚不满足条件”，不泛化显示为系统错误。

### 4. 错误完成、越权知情（False Completion & Authority Leak）
- **已固化防御机制**：
  - 严禁角色通过纯文本宣称“我已到了”、“事情办完了”假冒完成；
  - `appointment.fulfill` 强校验权威位置 `world_authoritative_positions`；未到场或未到约定时间立即拒绝，附带虚假台词被系统拦截（`REPLY_DEPENDS_ON_UNEXECUTED_ACTION`）；
  - `appointment.cancel` 强校验角色参与身份，非参与角色不可越权取消。

### 5. 刷新、并发和失败恢复异常（Concurrency & Idempotency）
- **已固化防御机制**：
  - 多标签页或重复点击携带同一 `commandId`，返回已存证的 `result_state`，执行 0 次新调用；
  - 刷新页面纯只读重放，不推动世界时间或触发模型推进。
