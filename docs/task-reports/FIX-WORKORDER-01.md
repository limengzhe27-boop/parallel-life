## 0. 使用规则（必须先遵守）

1. **基线**：开工前 `git fetch origin`，从 `origin/main` 最新提交建**独立工作树**（`git worktree add ../<name> -b <branch> origin/main`）。**禁止**在共享主 checkout 直接改（该目录可能落后数百提交、且含他人未提交改动）。
2. **一个批次一个分支**，一个负责人；公共契约（`src/contracts/**`）改动只能由集成人合并。
3. **报告必须写明基线 commit**、改动文件、测试证据、未完成项。
4. 完成前跑：`npm run check:boundaries`、`npm run typecheck`、相关测试、`npm run build`；界面改动需**手机与 PC 双端**检查。
5. **交付即上线**（用户常驻要求）：确认生产库迁移已应用 → 用关联身份提交推送 → 等 READY → 公网实测关键流程；未验证不得声称完成。
6. **红线（不得破坏）**：事务与幂等、回执与 Outbox、RLS 租户隔离、私有档案与虚构世界隔离、模块边界检查、**不得伪造 AI 成功或假回复**。

## 2. 问题明细与修改建议

### FIX-01【P0】角色手机试演不常驻
- **现象**：编导只要改过表单还没保存，手机试演界面就消失，只剩提示条与保存按钮 → 体感"后台就是纯填表"。
- **证据**：`src/features/publisher/publisher-character-preview.tsx:92` → `{trial && !isDirty ? (<iframe src={phoneTrialUrl(trial)}/>) : …}`；而 `:71` 的提示却写"试演运行的是已保存版本"。
- **期望**：试演区**常驻**；有未保存修改时在 iframe 上叠角标"以已保存版本运行"。
- **改法**：`trial ? (<div class=trialWrap><iframe/><span class=staleBadge/></div>) : (引导：还没有试演 → onStartTrial)`；CSS 增 `.trialWrap{position:relative}`、`.staleBadge{position:absolute;top:8px;right:8px}`。
- **验收**：编辑表单时手机界面**不消失**；角标文案与"已保存版本"一致；`tests/publisher-character-preview.test.ts` 补"isDirty 时仍渲染 iframe"用例。

### FIX-02【P0】删除通用引擎里的 Demo 硬编码（R17 / 修车店）
- **现象**：通用场景引擎内含"修车店交接工单"专属逻辑，新世界仍在跑旧状态机。
- **证据**：`src/modules/world/infrastructure/scene-planner.ts:44`（`kind: z.enum(['receive_r17','inspect_r17'])`）、`:164`（`NpcActionSlot` 同款枚举）、`:276`（`/R17|接头/`）、`:281`（`R\d+` 只能是 R17）、`:636/:649`（提示词出现"核对 R17 维修单""R17 钥匙和维修单"）。
- **期望**：通用引擎不得出现任何具体 Demo 名词；动作类型改为**世界可配置**（如 `actionTemplates: [{ key, label, requiresReceiver, steps }]`）。
- **改法**：把这些枚举/正则/示例抽成"世界内容里的动作模板"，引擎只按模板 key 处理；示例文案改为占位符（`{{actionLabel}}`）。
- **验收**：`grep -rnE "R17|维修单|修车|receive_r17|inspect_r17" src/modules/world` 为空；现有场景测试改为使用通用模板并通过。

### FIX-03【P0】现场在场人物不可变更（导致"现场永远没人"）
- **现象**：玩家在微信里 NPC 秒回；进现场喊"有人吗"却无人应答。
- **证据**：`scene-planner.ts:724/731` 强校验 `presentActorIds` 集合与当前实际在场者**完全一致**，否则拒绝；提示词明确"已有 action 时……**不增删人物**"（`:636/:649`）；在场人物主要来自"当前有效约定"（`activeAppointment?.participantIds`）。
- **期望**：场所应有**候选人物池**，由导演按 agenda（欠回应/未定约定/必发事件）决定"此刻谁在"；**进入场景若无人，必须明确提示并给出选项**（等人 / 去别处 / 推进时间），不得静默。
- **改法**：新增"导演派驻"步骤（在世界推进时决定各场所的在场者）→ 场景回合只**读取**该结果，不再要求"玩家侧不能引入人物"；`presentActorIds` 允许从派驻结果变更并记录原因。
- **验收**：进入有候选人物的场所，**至少 1 人可对话**并能回话；无人时出现明确提示与选项；补真实库测试"无人场所进入→提示→推进时间后可有人"。

### FIX-04【P0】事项回归"叙事推手"，去掉对暗号式审批
- **现象**：玩家随口一句生活化对白，被判 `blocked` 或报错（"未提供标准步骤证据"）。
- **证据**：`src/contracts/world-matters.ts:153` `inputQuote: z.string().min(1).max(4000)`；`scene-planner.ts:100/318` `observationIndex`（0–7）；提示词中"completed 仅由 succeeded 支撑""blocked 只由 failed 支撑"等严苛规则（`:636/:649`）。
- **期望**："眼下的事"= 导演生成的**线索/备忘**，只展示与指引，**不阻断**推进；证据字段改为**可选**（仅精确对账场景需要）。
- **改法**：`inputQuote`/`observationIndex` 设为可选；状态机简化为 `进行中 / 已完成 / 暂缓`；移除"无证据即 blocked"的判定路径。
- **验收**：连续 5 次随性自然语言输入均可推进剧情、不出现 blocked 报错；保留"完成需可信证据"的**可选**校验。

### FIX-05【P1】编导"必发事件"世界侧零消费
- **现象**：编导在候选库存的必发事件，无法保证在世界中全部演绎（可能被自由节拍稀释或跳过）。
- **证据**：`git grep -l candidates origin/main -- src/modules/world` **无命中**（消费点全在 `src/modules/settings/**`）。
- **期望**：必发事件进入"必演绎队列"，逐条演绎直至清空；清空前不得生成自由节拍。
- **改法 + 代码与测试**：见附录文档 `docs/task-reports/DIRECTOR-OBLIGATORY-BEATS-01.md`（调度模型、`obligatory-beats.ts` 完整实现、迁移、7 条纯函数测试 + 3 条真实库守门测试）。
- **验收**：世界带 3 个必发事件 → 受控推进下 **100% 被触发**、不重复、期间不产生自由节拍。

### FIX-06【P1】事件表单过重（前提/阶段/条件/互斥全铺出来）
- **现象**：编导新增事件时面对"发生前提 / 剧情阶段 / 条件键 / 互斥节点"等大量竖框，无从下手。
- **证据**：`src/contracts/published-world-content.ts:244-279`（`candidates[]` 含 `prerequisites`、`conditionKeys`、`mutuallyExclusiveNodeKeys`、`timeline.stageKey/window/excludeIfResolved/alternatives`）；编辑器把契约字段直接铺成表单。
- **期望**：编导只填 **事件名称 + 事件概述（起因/博弈/结局，可合并为一段）+ 主要人物（就在概述下方选择）**；其余字段移入"高级（默认折叠）"或由 AI 推断生成。
- **改法（推荐：schema 保留、UI 隐藏、AI 推断）**：保存时由 authoring 规划器生成 `stageKey/prerequisites/互斥`；表单仅暴露 3 个字段 + "主要人物"多选。
- **验收**：默认视图只有 3 个字段；不带前提/阶段也能保存并试演；高级字段展开后仍可编辑。

### FIX-07【P1】删除"待确认问题"面板
- **证据**：`src/features/publisher/publisher-workbench.tsx:893`（Tab 计数入口）、`:964`（`<section aria-label="待确认问题">`），另有 `:574`、`:1321` 引用。
- **期望**：移除该面板与入口；必要的提示改为**对应字段旁的行内提示**。
- **验收**：后台不再出现"待确认问题"；原有校验提示仍能在字段旁看到。

### FIX-08【P1】场景底色重放 + 行动无后果
- **现象**：同一段"场景"描述每回合整段重复；"我把店铺烧掉了"只得到"并未成功"，下一回合毫无变化。
- **期望**：① 底色仅在**首次进入/环境变化**时展示；无变化时明说"这里暂时没有新动静"+ 给 2~3 个动作；② 行动分级（对话/观察/移动/越界），越界动作有**世界一致性裁决 + 可见后果**（有人报警、店主质问、消息与记录出现新条目）；规则拦截要说明"是规则拦下"。
- **验收**：连续 4 回合不再逐字重复底色；越界动作至少产生 1 条可观察后果并写入记录/消息。

### FIX-09【P1】导演不"入驻"场景
- **现象**：世界在场景里"什么都不发生"，导演没有安排谁出现、也没有事件在此发生。
- **证据**：`advance-world.ts` / `agenda.ts` 只**读取**空间（`state.space.places`、`currentPlaceId`、`positionSource.kind==='travel'`、`scene_action|scene_steps`），无"场景节拍"类型。
- **期望**：场景节拍 = `谁出现 → 发生什么 → 推进哪条必发事件 → 留下什么痕迹`。
- **验收**：与 FIX-05 联动——必发事件可指定场所在场景中演出；场景回合出现导演安排的入场/事件。

### FIX-10【P1】下限过严 + 长文本被拦
- **证据**：`src/contracts/life-settings.ts` 的 `characters: …min(2).max(7)`；`publisher-workbench.tsx:243/247/249`（"这段总体设定太长，暂不能保存或整理"）。
- **期望**：1 个角色即可试演；超长文本**保存但不进入提示词**并给字数提示。
- **验收**：单角色可保存并试演；超长内容不丢失、不被拒绝。

### FIX-11【P2】统一领域模型
- **证据**：`src/features/publisher/publisher-editor.ts:21-22 / 106-107`（`caresAbout`、`immediateGoal`）与世界侧 `lifeModules.drives` 等并存；存在 `motivation: motivationText || existingLifeModules.drives || '按既定处境与玩家互动'` 这类兜底。
- **期望**：确立唯一 `Actor`（世界内角色）模型；`ActorEditorForm`/`PublishedActor`/`Contact` 仅作**编译层/展示层的显式映射**（一张转换表），**禁止 `||` 兜底**。
- **验收**：`grep -rn "|| '按既定处境与玩家互动'" src` 为空；新增角色往返（编辑→发布→世界→手机）字段无丢失，有测试覆盖。

### FIX-12【P2】提示词治理
- **证据**：`scene-planner.ts:636/649` 两段系统提示词数百字、密集否定与格式补丁。
- **期望**：结构化约束 + 少量关键规则；设定**提示词预算上限**并纳入评审；示例用占位符不用具体 Demo。
- **验收**：提示词长度下降（给出前后字数）；删除因提示词补丁而存在的冗余校验分支。

### FIX-13【P2】测试策略调整
- **证据**：`tests/group-client.test.ts:31/76`（`calls.length`）、`tests/matter-ai-guidance.test.ts:90`、`tests/nar03-phone-feedback.test.ts:400`、`tests/experience-rules.test.ts:147`（`INVALID_PROPOSAL`）。
- **期望**：守门测试聚焦**用户体验契约**（能玩通、有反应、不泄漏、不被卡）；删除或重写固化实现细节的用例。
- **验收**：FIX-01~FIX-10 的改动不再因"实现细节测试"爆红；新增体验级守门测试。

### FIX-14【P2】手机各 App 互联
- **期望**：日历里的邀约→一键去微信发"我快到了"；备忘录/人生记录里的事项→一键跳转到现场/地图；减少只读卡片。
- **验收**：上述两条跳转可用且返回后状态保持。

### FIX-15【P2】"现场"App 的定位
- **期望**：现场互动发生在**地图到达场所后的即时舞台**，而不是 dock 上一个独立"现场"App 空壳。
- **验收**：从地图进入现场；dock 不再单独出现"现场"。
