# D-33 根因（UI 侧）：为什么已有世界时"创建分支"只会提示进入已有分支

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已修复并上线；点击级验证待补。

## 诊断（用用户真实数据，先证伪服务端）

用用户本人会话把 UI 会发的请求原样跑了一遍（不需要跑模型）：

```
profileVersion: 3 · confirmedFacts: 1 · seedsCount: 1
directionsCount: 3 · adoptedDirections: 1 · unbuiltDirections: ['0c7f9464','48c50808']
POST /life-proposals（带对话 brief + 实时版本）→ 202，任务已创建
```

结论：**服务端完全正常，而且还有两个"没被采用过"的方向可用**。所以问题在 UI 这一跳。

## UI 侧根因（两处，都是真问题）

1. **`approveSeed` 用了过期的 discovery 版本**：
   `confirmAndBuild` 里写的是 `discoveryVersion: data?.version ?? 0`，读的是 React 状态。创建路径是"先 `await discoverBranch()`（内部 `setData(fresh)`）→ 紧接着 `confirmAndBuild()`"，此时状态**还没更新**，于是把**旧版本**发给了服务端 → `VERSION_CONFLICT` → 建世界失败。
2. **失败信息在有世界时根本不渲染**：
   渲染结构是 `{entry.kind === 'open-ready' ? (已有世界 → 进入体验卡片) : (…含 error 提示…)}`。用户已经有世界，所以**任何失败提示都被挡在条件之外**——屏幕上只剩"进入这个分支体验"，用户自然认为"它只是让我进旧的"。

另外：识别措辞过窄（"创建一个**新的**分支""建一个**属于我的**分支"这类中间带修饰词的说法不命中）。

## 修复

1. `discoverBranch()` 现在返回 `{ directions, version }`；`confirmAndBuild(target, discoveryVersion)` 使用**刚拿到的版本**，不再依赖可能过期的 state。
2. **进度与错误改为在任何状态下都渲染**（放在入口条件之外）：推演中/保存中/构筑中/进入中都会显示，失败会显示可行动文案（例如"资料刚更新过，我按最新内容再试一次就好。"）。
3. 识别规则放宽：`(创建|建立|建|生成|开|做) + ≤6 个任意字符 + (分支|平行人生|平行世界|… )`，覆盖"创建一个新的分支"等说法。
