# STORY-PLACE-02 · 剧情消息揭示地点

负责人：codex-story-place-reveal-20261014；独立工作树：`story-place-reveal`。状态：已集成部署，公网访问验收完成。

## 交付与边界

- 编导原稿里明确写出的隐藏地点、地址和有向路线保留在受权限保护的不可变作品来源中。导演选择事件及角色出场能读取对应地点信息；未揭示前玩家世界、地图接口和路线均看不到该地点。没有作者地址与可达路线的事件继续不可执行，不从 NPC 自由文本发明地址。
- 事件选中和 NPC 回合提交并不自动解锁地点。故事对账只检查同一世界、同一角色、由成功命令提交的真实 assistant 消息；消息明确提到作者地点名（至少两个字符）或完整作者地址后，才追加 `space.place_revealed` 世界事件、版本、状态与命令回执。玩家自己提及、NPC 寒暄、模型失败、事件跳过均不能解锁。若首条消息未提及地点，同一角色之后的已提交消息可补揭示。
- 揭示写在故事对账事务内；世界事件可重放，重复对账不会重复加入地点或路线。路线 ID 来自完整作者路线的稳定排序，并与开场路线 ID 分开。揭示前验证从玩家**当前位置**沿现有有向路网能到达新地点；单向移动到无法回返的地点后不会再选中该隐藏地点事件。
- NPC 首次剧情回合与后续地图揭示是**两个事务**，不能称为同一回合的原子提交。`advancePublicationStory` 会在对外返回 `played=1` 前等待对账；若中途崩溃或对账失败，既有已提交消息保留，随后故事进度和普通聊天后的对账会修复。普通聊天对账失败不会把已经提交的玩家消息伪装成发送失败。
- 导演/人物提示现在说明：若确实邀请主角前往仍未知的作者地点，消息正文应自然明确说出地点名；未说出时地图保持隐藏。
