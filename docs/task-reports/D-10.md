# D-10 资料沉淀优化：该记的自动写入、噪声与重复不落档案

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已完成并上线验证。

## 用户反馈与目标

用户原话：沉淀到资料里的信息"有时候会有一些问题，会重复沉淀，什么东西都沉淀，并不能正确的将其提炼"，并且"提炼之后自动写入就 OK 了，但是有时候需要采纳，需要反复确认"。

目标：**只提炼值得长期保留的信息；重复的合并而不是再写一条；提炼后直接进档案，不再要求逐条采纳。**

## 诊断

|问题|证据|
|---|---|
|什么都沉淀|抽取提示词上限为每轮 4 条事实 + 2 个事件，且未禁止寒暄、情绪、临时状态、AI 自己的话|
|重复沉淀|流式路径与 handler 路径都只写"待确认候选"，与档案里已有内容不做比较；用户确认后由 `applyConfirmedCandidateInTransaction` 合并，但**在确认之前**同一件事会被反复登记|
|反复确认|两条路径都留下 suggested 候选，用户在「我的」逐条点「记住这条」；而未确认的候选又会让分支入口一直提示"还有 N 条记录等你确认"|
|基础资料重复|用户在城市/职业卡片里填过的内容，模型又提取成 identity 事实，与 `个人资料` 记录并列出现|

## 已知边界

- 用户既有会话里由旧策略留下的待确认候选（例如 2 条）仍会显示一次，需要用户点一下"记住这条/暂不记录"；新产生的沉淀不再需要采纳。
- 合并判定仍是字符集相似度（`isSimilarText`），对语义相同但用词差异大的表述可能判为两条；本次先解决"完全重复与近似重复"，语义级去重需要模型参与，未做。
- 已确认事实仍可在「我的」编辑或删除；用户删除/拒绝过的同一条不会再被写回。
