# EXP-03G · 聊天照片与「我的」资料保存一致性

状态：已实现，待生产验收。负责人：codex-main-exp03g-20261002。基线：`92574ac`。

## 问题与范围

聊天里选照片后，当前界面先上传素材，再尝试把照片加入现实档案；第二步失败会被静默忽略，但照片消息仍会发送。这样用户看到「已分享」，而「我的」没有这张照片，后续草案也无法明确选择带入。此任务只修复这段真实资料写入与发送的顺序，不调整世界相册、生图或整个界面。

## 验收计划

- 成功时同一素材先出现在现实档案，再出现在访谈消息中；重复/并发资料版本变化不重复上传。
- 入档失败时不发送照片消息，不清空用户输入；保留已上传素材，允许就地重试。状态文案明确，不报假成功。
- 检查与构建通过，手机与 PC 核对上传/失败/恢复界面；部署后验证公网关键流程。

## 已实现与验证

- 上传后先把同一 asset ID 加入现实档案；只有服务端返回的档案确实包含该 ID 才发送照片消息。资料版本冲突时重新读取并重试一次，响应丢失但已保存时直接复用已有记录。
- 入档失败时保留用户输入和已上传素材 ID，显示可重试提示；刷新后从当前访客的 sessionStorage 找回待发送照片。此时不发送带照片的消息，也不再重复上传。入档成功后删除本地待发送标记。
- `npm run check`：247 项常规测试通过，包含 5 项照片保存顺序/冲突/重复/失败专项；`npm run build` 通过。首次在默认沙箱里执行完整检查时，本机 PostgreSQL 连接被 EPERM 拒绝；获准访问本机数据库后全量复跑通过。
- Ego Lite 本地合成访客，390px 手机与 1440px 电脑：用 sessionStorage 模拟“已上传、入档待恢复”状态，刷新后重试提示可见且按钮可用；390px 无横向溢出，电脑容器宽 430px。截图位于忽略目录 `.local/exp03g-mobile.png`、`.local/exp03g-desktop.png`。此项验证没有真的上传图片，也未调用图像模型。
- 2026-10-02 发布前只读核对：独立 Supabase 生产库 30/30 迁移与本地文件校验和一致，无待执行或被改动迁移。

## 限制

上传成功但用户主动放弃重试时，未引用的私有素材仍可能留在存储中；本任务没有新增素材清理命令。照片消息仍是旧的文本标记形式，正式消息附件契约及世界相册联动属于 EXP-03/NAR-03 后续范围。公网真实上传及入档失败注入尚未验收，不能以本地模拟代替。
