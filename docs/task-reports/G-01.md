# G-01 任务完成报告：正式账号/登录、游客归并、退出/恢复

## 1. 任务概述与验收标准
- **任务 ID**: G-01
- **硬依赖**: B-06 (已满足)
- **目标**: 正式账号/登录、游客归并、退出/恢复；会话和归属可验证，不因归并读取他人资料。
- **核心安全约束**:
  - 密码使用带盐哈希存储（Node.js `crypto.scrypt` + 16 字节安全随机盐）；
  - 密码比对采用常数时间比较（`timingSafeEqual`），防止时序侧信道攻击；
  - 访客归并（Guest Merge）严格遵循**“不因归并读取他人资料”**：仅允许合并当前已验证签名的游客会话与已验证凭据的目标账户，归并时原子迁移所有者资源并合并档案，彻底清理旧游客，防止任何跨租户数据越权与脏读；
  - 退出与恢复：提供 `DELETE /api/v1/session` 销毁 Cookie，以及通过 `SignedSession` 强签名 Token 和 CSRF 机制无缝跨请求恢复会话。

## 2. 交付清单与实现架构

### 2.1 数据库架构 (`db/migrations/0089_account_auth.sql`)
- **`parallel_life.account_credentials` 表**:
  - `account_id text PRIMARY KEY REFERENCES parallel_life.accounts(id) ON DELETE CASCADE`
  - `identifier text UNIQUE NOT NULL`（规格化为小写，长度 3~64）
  - `password_hash text NOT NULL`
  - `salt text NOT NULL`
  - 启用并强制 RLS（`pl_app`, `pl_worker` 受控访问）。
- **`parallel_life.register_account_credentials` 存储过程**:
  - 原子建立 `accounts`（`kind = 'account'`）与 `account_credentials`；
  - 处理唯一性冲突，重复注册抛出标准 `CONFLICT` 异常。
- **`parallel_life.lookup_account_credential` 函数**:
  - 检索规格化标识符对应的账号 ID、密码哈希与盐。
- **`parallel_life.merge_guest_into_account` 存储过程**:
  - 校验访客有效性（必须为 `kind = 'guest'`）与目标正式账号；
  - 档案合并：如果目标无 Profile 则整体继承；若已有 Profile 则原子合并 facts 与 people 列表，去重保留；
  - 面谈与发现合并：若目标已有则清理访客重复记录，若无则转让所有权；
  - 动态业务表数据转让：遍历 `parallel_life` 模式下所有含 `owner_id` 的业务表（如 `worlds`, `world_events`, `world_messages`, `world_notes`, `scene_sessions`, `publication_world_bindings` 等），在 `session_replication_role = 'replica'` 下安全原子迁移复合外键约束资源；
  - 状态同步：同步更新 `parallel_life.worlds.state` JSON 内的 `ownerId`，保证投影与物理列完全一致；
  - 级联清理旧访客账号。

### 2.2 契约与接口 (`src/contracts/auth.ts`)
- `RegisterRequestSchema`: `{ identifier, password, mergeGuest?: boolean }`
- `LoginRequestSchema`: `{ identifier, password, mergeGuest?: boolean }`
- `AuthResultSchema`: `{ accountId, identifier, kind: 'account', mergedGuest: boolean, csrfToken: string }`
- `SessionStatusSchema`: `{ authenticated: boolean, kind: 'guest' | 'account', userId: string | null, identifier: string | null, csrfToken: string | null }`

### 2.3 领域与服务适配
- **`SignedSession`** (`src/modules/identity/infrastructure/signed-session.ts`):
  - 扩展 `issue(userIdOrNow?, now?)` 支持显式指定 `userId`，使得正式账号登录/注册后能直接颁发绑定该账号的会话 Cookie 与 CSRF 令牌。
- **`IdentityRepository`** (`src/modules/identity/infrastructure/identity-repository.ts`):
  - `registerAccount`: 支持直接注册全新账号，或将当前访客账号直接提升（In-place Promotion）为正式账号；
  - `loginAccount`: 验证账号存在与密码哈希比对，支持在登录时将当前独立访客产生的数据原子归并进正式账号；
  - `getAccountInfo`: 查询账号分类与登录标识符。
- **`LifeClient`** (`src/features/api/client.ts`):
  - 提供 `getSessionStatus()`, `registerAccount()`, `loginAccount()`, `clearSession()` 完整方法，与服务端 CSRF 握手联动。

### 2.4 HTTP 路由
- `POST /api/v1/auth/register` (`src/app/api/v1/auth/register/route.ts`): 返回 201，写入 `pl_session` Cookie；
- `POST /api/v1/auth/login` (`src/app/api/v1/auth/login/route.ts`): 返回 200，写入 `pl_session` Cookie；
- `GET /api/v1/session` (`src/app/api/v1/session/route.ts`): 检查当前会话登录状态、身份类型与 CSRF；
- `DELETE /api/v1/session` (`src/app/api/v1/session/route.ts`): 清空会话 Cookie，实现退出登录。
