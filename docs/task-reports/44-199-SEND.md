# 44-199-SEND — 私聊发送关键路径去除无关前置读取

负责人phone199，基线6bd14800，独立树`.local/worktrees/phone-send199`。root唯一集成/部署。只改world-phone-app.tsx发送段、use-world-time.ts startConversation、新聚焦测试及本报告。

## 根因

- deliverMessage在pending气泡、command持久化和try之前await startConversation；后者无条件await clock/activity，排在现有s.tail串行心跳队列。发生多个15秒超时时，点击发送可排队数分钟，尚未发出/messages。
- 随后发送还await完整client.world刷新，失败虽然catch继续，仍额外增加一次读取延迟。内核已支持无关版本追加，此GET不再必要。
- MessagesApp提交时先清草稿；clock前置失败时没有pending/failed气泡、没有保存command。provider只记录错误signature，不恢复草稿，形成“内容还在”但页面无内容的错误体验。

## 修改

- 先建立本地pending气泡并持久化原文、command，再进入错误处理。
- startConversation同步检查现有active/returning/paused/pendingWait边界；活动sync沿原队列异步上报，独立catch时间同步错误，不阻塞/messages。保持当前3倍前台时间政策，不新增队列或状态字段。
- 删除发送前完整world GET，expectedVersion取现有data与confirmedSendVersion的较高已知版本；既有服务端版本/依赖/权限/幂等机制不变。
- 本地前置拒绝按明确INVALID_INPUT失败保留原文，不能误标unknown或已发送。
- 图片、群聊、消息未知结果恢复和服务器提交逻辑未修改。

## 验证

执行实际组件函数（从TypeScript AST提取并转译，仅替换外部依赖）：clock promise持续pending时仍立即调用sendWorldMessage，world读取0次；使用现有7/9版本得到expectedVersion9；发送拒绝后failed原文与同command保留。暂停/返回/待核对等待仍在HTTP前拒绝。原发送投影/连续检查回归共17/17通过。类型检查通过（修正新增测试闭包的TypeScript缩窄后重跑）。
