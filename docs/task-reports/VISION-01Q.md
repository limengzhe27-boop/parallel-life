## 用户实际要求与本轮分工

用户希望选照片后再输入“这是小芳”，照片与说明一起发送；后补第一张、第二张人物说明目前仍有漏关联。用户同时询问是否应改为多模态对话 Agent。PHOTO-COMPOSE-02由辅助开发图文编辑与照片组规则，公共仓储、真实数据库、实际模型及部署仍由唯一集成人串行验收。本任务只读业务，不修改共享AI端口/环境或生产资料。

## 直接复现的事实

- 当前前端选图立即执行上传、入共享访问登记和发送；caption只捕获选图前已有draft。故“先选图，再说明，再发送”并未实现。
- 单图后文字“这是小芳的照片”：explicitPhotoPeople与resolvePhotoReference纯计算能得到小芳及那张图。用户真实漏入档不能仅用这项成功证明已解决，需要合成复现实际保存入口、资料版本及既有人物冲突。
- 两张连续图片，之后分两条说明“第一张是小芳”再“第二张是王大毛”：第一条能关联第一张，第二条返回null。第一条文字说明打断adjacent标记，是明确复现的规则缺口。修复必须只延续明确照片说明，不把普通聊天、否定或多批歧义当成同一组。
- 追加单图条件性反例：history为旧图、普通话题、刚发的新单图，当前“这是小芳的照片”。literal仍得到小芳，但resolver因旧组存在且不认“这是”为最近指代而返回null。已交PHOTO-COMPOSE-02修复：紧随最近单图的明确指代可关联；最新组多图、普通话题已打断、引用否定或不明跨组序号不能猜。未读取用户私有历史，不能确定这就是其实际漏入档唯一原因。
- AI端口 ModelMessage.content目前仅string；网关适配器校验string，访谈上下文只传hasPhoto并明确说没有看见照片。上传附件、保存和显示图片不是模型视觉接线。

上述纯计算亲自运行，无数据库或真实用户素材访问。只读定位：src/features/interview/interview-app.tsx、src/modules/profile/application/person-extraction.ts、src/modules/profile/infrastructure/profile-repository.ts、src/modules/ai/application/ports.ts、src/modules/ai/infrastructure/yibu-text-model.ts、src/modules/profile/infrastructure/interview-planner.ts。

## 官方能力与一次真实网关探针

已阅读官方[GPT-4o Mini说明](https://developers.openai.com/api/docs/models/gpt-4o-mini)和[图像输入指南](https://developers.openai.com/api/docs/guides/images-vision)：gpt-4o-mini支持文字和图像输入；Chat Completions可在同条user.content数组中放text与image_url，图可用Base64 data URL。官方能力不能单独证明第三方网关可用。

已向本项目既有网关进行恰好一次请求，使用自制白背景、左红圆、右蓝正方形512px图片，不读取或发送用户照片，不改模型配置，不修改生产数据库。

- HTTP 200，使用gpt-4o-mini，耗时约2.8秒。
- 回答：左circle/red，右rectangle/blue。
- 严格要求右侧square的断言没有满足，原始结果passed=false保留，不改标准或再次付费调用掩盖。
- 输入2896 tokens、输出38 tokens。这是一例低细节合成图，不能推断复杂照片、头像、文字、人物一致性或所有请求的准确性/成本/时延。
- 结论限于网关接受图像内容，并得到部分一致画面描述；生产Agent仍未接图像输入。不应宣称已经识别人脸或知道小芳是谁。

忽略证据：.local/vision01q-probe.mjs、.local/vision01q-result.json。脚本运行时读取被忽略的服务端环境，未输出、复制或提交密钥；只输出合成图描述与用量，无真实用户信息。

## 建议的接线边界（未实现）

优先把图文发送及确定性人物归属修复好。读图不替代用户说明，也不要求先换掉整套Agent；现有模型和网关可作为小规模候选继续验证。

后续若接视觉，保持既有一轮访谈一次模型调用：由服务端以当前owner/访谈/已保存消息确定可用附件，读取该账号私有存储图片，按输入预算制作图像内容；在同一user消息中带文字说明与实际图像。私有带Cookie的资产URL不能直接交外部模型抓取；不能把桶改公开或发送访问密钥。不得让模型指定、修改assetId或personId。

共享端口须由唯一集成人冻结兼容格式。文字路径、世界/NPC等现有调用保持兼容，视觉内容仅由获准的访谈入口提供；domain不读文件/网络，application面向附件读取端口，server负责组装。网关检查类型、体积、数量与超时，避免把Base64按普通文字长度错误计入64000字符上限。

只发送与当前问题相关的有限图片，不每轮重新发送完整相册/所有私聊照片。是否保存视觉摘要及修订/撤回行为应单列实施任务；摘要只能标为视觉描述，不因照片推断现实恋爱、身份、性格、年龄或人物关系。关系、姓名与分支身份仍分别取用户陈述、照片对应和创作设定。

失败时如实显示图片已保存但未完成理解；不能声称看过，也不能以自动第二次AI请求伪装成功。共享上传不能自动设本人头像；已有分支的头像/相册来源继续沿用授权快照，不因视觉描述改写。

## 完成验收应包括

1. 手机与PC先选图、预览、编辑说明，再显式点发送；同一持久消息含照片和说明。
2. 单图“小芳”实际入档；两图分两轮说明一一关联；同名、冲突、多个组、否定、普通话题转移不猜。
3. 发送失败、保存成功但响应丢失、unknown、重复command及刷新不会重复图片/模型付费或清空下一草稿。
4. 只有服务端确认人物绑定后，界面才能呈现“已关联小芳”；不得用模型承诺或前端临时状态伪造保存成功。
5. 后续视觉实测分别覆盖合成可识别画面、插画头像、带字图、多人图及不可用素材；图像内容不能越用户/访谈/世界读取，模型读图失败不改变人物对应。
