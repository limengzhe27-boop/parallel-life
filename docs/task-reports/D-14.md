# D-14 AUD-15 访客创建限流（按调用者）

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已完成并上线验证。

## 问题

访客创建只有一个**全局单行计数器**（`guest_limits(id=1)`，60 次/小时，`0003_limits.sql`）。任何单一调用者都能把它耗尽，之后**所有新用户**都会被拒绝；`session/route.ts` 也没有任何 IP/指纹分桶。

这不是理论风险：2026-09-24 我在跑真实库测试时，`ensureGuest` 直接返回 `RATE_LIMITED`，必须手工删除计数行才能继续（见 [D-13](D-13.md) 的"顺带发现"）。

## 方案

| 部分 | 内容 |
|---|---|
| 迁移 [0020_guest_limits_by_caller.sql](../db/migrations/0020_guest_limits_by_caller.sql) | 新增 `guest_limits_by_key(key, window_start, count)`；函数 `reserve_guest_key(bucket, per_key, ceiling, window_seconds)`：先占调用者额度，再占全局上限；**被全局上限拒绝时把调用者额度归还**（否则恶意调用者会顺带烧掉全局上限）。表对 `PUBLIC/pl_app/pl_worker` 全部 REVOKE，只能经 SECURITY DEFINER 函数访问 |
| [guest-bucket.ts](../src/modules/identity/infrastructure/guest-bucket.ts) | 调用者识别：`x-forwarded-for` 第一跳，回退 `x-real-ip`；**存的是加盐哈希**（32 位十六进制），原始地址不落库；无地址的调用者共用一个桶（有意为之）。策略常量：每调用者 30/小时、全局上限 600/小时 |
| [identity-repository.ts](../src/modules/identity/infrastructure/identity-repository.ts) | `ensureGuest` 变回**纯幂等建号**（内部调用与测试不再消耗公共额度）；新增 `reserveGuestCreation(bucket, limits)` |
| [services.ts](../src/server/services.ts) | 在组装层暴露 `reserveGuestCreation(headers)`，把"如何识别调用者"与限流策略留在服务端；路由不必也不允许 import infrastructure（边界检查会拦） |
| [session/route.ts](../src/app/api/v1/session/route.ts) | 仅在**需要新建访客**时预留额度，被拒时返回 429（`http.ts` 已带 `Retry-After`） |

- **生产实测**：
  1. `POST /api/v1/session`（带调用者地址）→ 200，发放 guest + CSRF；生产库出现一条 **哈希桶**记录（`259a81…`，count 1），全局计数 1；
