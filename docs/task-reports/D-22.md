# D-22 导演接 agenda：节拍由"未了结的事"驱动

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已完成并上线验证。

## 问题

导演骨架此前只按"沉默最久"轮转选人，等于随机找个人说话——而"楚门的世界"的关键是**每个人都围绕主角的未了之事运转**：谁该给主角回应、哪条约定还没定下来。

## 改动（无新增迁移）

| 文件 | 改动 |
|---|---|
| [agenda.ts](../src/modules/world/domain/agenda.ts)（新，纯函数） | `buildAgenda(state)`：① `awaiting_reply`——主角最后一句是对某角色说的、对方还没回；② `proposed_appointment`——仍处于 `proposed` 的约定及其参与者。确定性、上限 5 条。`threadFor(agenda, actorId)` 取该角色最紧迫的一条 |
| [clock.ts](../src/modules/world/domain/clock.ts) | `selectSpeaker(state, spoken, agenda)` 改为**未了结优先**：先"欠回应的人"，再"未定约定的人"，都没有才回到"沉默最久"；`beatCue(state, actorId, agenda)` 把具体那件事写进舞台指示（"未了结的事：……可以自然提起，但不要替用户答应用户的事"） |
| [advance-world.ts](../src/modules/world/application/advance-world.ts) | 每一拍构建 agenda 并交给选人与舞台指示 |

## 验证

- `npm run verify`：**165 项单元测试 + 24 项真实库测试**通过。新增单元用例：主角刚说话 → 欠回应的角色优先（即使另一个角色从不说话）；`proposed` 约定把参与者拉进节拍；**无事可做时才回到沉默规则**。
- 真实库集成测试扩展：世界里存在一条 `proposed` 约定时，**第一次推进的第一拍就是该约定的参与者**（`spoken[0] === second`），其余断言（3 拍上限、时间追上现实、暂停 0 拍且无模型调用）保持通过。
- 无新增迁移；生产无需迁移步骤。

## 遗留

- 记忆里的 `commitment`（角色承诺）与 `episode` 尚未进入 agenda（现在只用世界状态里的约定与对话）；下一步可把记忆作为 agenda 的第三类来源。
- 手机端时间控件（暂停/倍速/跳下一事件）与离线摘要展示仍未接 UI；L-03 导演控制面（调角色/主题/冲突/节奏）仍未实现。
