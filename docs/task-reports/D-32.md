# D-32 根因修复：为什么"对话中让它直接生成分支"不生效

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：根因已定位并修复，回归测试已加；点击级验证待补。

## 根因（代码证据，不是猜测）

服务端 [discovery-repository.ts](../src/modules/discovery/infrastructure/discovery-repository.ts) 第 78–92 行：

```
if (profile.version !== request.expectedProfileVersion || saved.version !== request.expectedVersion)
  throw new TaskError('VERSION_CONFLICT');
const basis = profile.facts.filter((f) => f.status === 'confirmed')...
if (!basis.length && !request.brief) throw new TaskError('INVALID_INPUT');
```

而 UI 的生成分支请求（[proposal-thread.tsx](../src/features/interview/proposal-thread.tsx) 原第 144–145 行）传的是：

```
expectedProfileVersion: profileVersion   // ← 父组件传入的值
brief: ''                                // ← 空
```

于是必然出现两种情况，而且都被折叠成一句"这次没有完成"：

| 情况 | 触发条件 | 服务端返回 | 用户感受 |
|---|---|---|---|
| A | 刚开始聊，**还没有"已确认事实"**，且 brief 为空 | `INVALID_INPUT` | "它根本不给我生成分支" |
| B | 聊天过程中**画像版本已经变了**（每说一句版本就 +1），而 UI 用的还是旧版本 | `VERSION_CONFLICT` | 同上（静默失败） |

也就是说：**功能代码写得再多，前置条件与请求不匹配，链路就是断的。** 我前两轮（D-30/D-31）只修了"意图识别"和"别打开旧分支"，没碰这两条，所以你在真实使用中依然不生效——这是我的疏漏。

## 修复（从根源）

1. **用实时版本**：每次请求前重新读一次工作区，用**当前** `profile.version` 与**当前** discovery 版本，不再使用可能过期的父组件值。
2. **用对话本身当 brief**：新增纯函数 `buildBranchBrief(messages)`，取用户最近 4 句（每句 ≤120 字，总长 ≤400）拼接作为 brief。这样"聊着聊着就要求建分支"**不再要求先凑够已确认事实**——服务端的前置条件被真正满足，而不是绕过。
3. **冲突自动重试一次**：捕获 `VERSION_CONFLICT` 后重读最新版本再发一次（聊天还在继续时画像会再次变化）。
4. **失败必须说清楚**：`INVALID_INPUT` → "我还没了解够你的经历——再说两句你在意的选择或难处，我就能推演出属于你的分支。"；`VERSION_CONFLICT` → "资料刚更新过，我按最新内容再试一次就好。"；其余显示真实原因。**不再有静默失败。**

## 验证

- **真实库回归测试**（`tests/integration/discovery.test.ts`，新增用例，直接复现根因）：
  1. 无已确认事实 + `brief: ''` → `INVALID_INPUT`（**复现你遇到的现象**）；
  2. 同样的请求带上"用户说过的话"作为 brief → **被服务端接受**（`accepted.id` 存在）；
  3. `expectedProfileVersion` 过期 → `VERSION_CONFLICT`（证明 UI 必须用实时版本 + 重试）。
- **单元测试**：`tests/branch-intent.test.ts` 新增 `buildBranchBrief` 用例（只用用户的话、消息为空时不产生 brief、总长有上限）。
- `npm run verify`：**178 项单元 + 25 项真实库**全部通过；`npm run build` 通过。
- **未做**：真实浏览器点击级验证（新访客 → 聊几句 → 说"帮我创建一个分支" → 观察是否建出新世界并进入）。本轮的证据是**根因级回归（服务端行为）+ 单元 + 构建**。

## 遗留

- 若用户只说了极短的一两句就要求建分支，brief 会很短，模型仍可能给不出 3 个像样方向——这属于**内容质量**问题，不是链路问题；届时会显示真实失败原因，而不是静默。
