# LIB-01R · 可发布人生设定库独立审查

状态：待验收；负责人 `codex-f-01a0c7c8-lib01r-20261003`。2026-10-03 基于主目录 `5203aac` 只读核对代码与项目契约；仅本文和 `docs/DEVELOPMENT.md` 本人状态行可写。本文是方案审查，**没有实现设定库**，也没有运行模型、数据库、构建或部署。

## 结论与优先级

值得做，但必须把「可发布设定」定义为**从作者私有创作稿导出的、经逐字段审核的不可变公共作品版本**，而不是把现有 `LifeDraft`、`ApprovedSeed` 或某个已建世界改成公开可读。玩家点击「体验」时，服务端从指定公共版本创建**玩家自己拥有的私有 Seed 和 WorldBuild**；两位玩家同选李白设定，也必须得到不同的 `seedId/worldId`、消息、记忆、素材与后续事件。现有世界运行时可复用，出版/实例化边界需新接线。建议产品优先级为「独立设定库基础」高于完整多人共玩，但不要因此提前承诺可持续剧情触发与后果：那仍取决于 NAR-02/03 的真实执行与验收。

## 代码所证实的边界

1. `LifeDraft` 必须有 `profileVersion/discoveryVersion/directionId`，并可带 `factIds/eventIds/personIds/assetIds/portraitAssetId`（`src/contracts/life-drafts.ts:13-35`）；`prepare` 只从同一用户的 `Discovery` 方向创建（`draft-repository.ts:143-181`）。它是个人起点编辑稿，不是无主公共模板。现有库 `life_drafts` 还有 `(owner_id,direction_id,discovery_version)` 唯一键及 owner RLS（迁移 0028）。
2. `confirm` 把被选中的现实事实、经历、人物和私有素材引用固化进 `ApprovedSeed`（`draft-repository.ts:237-285`）；旧 `SeedRepository.approve` 还可能带肖像、参考照及人物照片（`seed-repository.ts`）。`ApprovedSeed` 绑定 `profile_id/owner_id`、不可变且 owner RLS（迁移 0005）；公开它会泄漏作者资料，改 owner 又破坏来源与外键。`world_initial_snapshots.approved_seed` 还复制完整 Seed（`build-handler.ts:163-165`），因此仅把列表 API 隐藏并不足以止漏。
3. `WorldBuild` 现在以 `seed_id` 为主键，一个 Seed 只能建一个世界；创建流程从当前 owner 可读的 Seed 建私有世界并入现有队列（`build-repository.ts:75-114`、迁移 0006）。把同一个公共 Seed ID 给所有玩家会使其共同命中同一世界或被 RLS 拒绝，绝不能以开放 RLS 解决。
4. `WorldPlanner` 目前只消费 `story/setup/facts/events/people`，不消费作者写的人物动机、冲突触发或后果图（`world-planner.ts:59-74`）；即使库页展示这些字段，世界也不会自动遵守。`build-handler` 为世界重新生成角色 ID、消息和初始快照，且肖像存在时会调度图像任务。首版不得把尚未接入的「必然触发」「可追溯后果」写成已运行功能。

## 必须新增或修改的最小边界（由集成人协调公共契约、迁移、API）

|层|建议|不能做的捷径|
|---|---|---|
|作者创作稿|独立 `SettingDraft`：标题/一句话钩子、主角可扮演身份、年代与地点、1 个愿望、1 个有因果的阻力、3–5 位虚构人物与关系、1 个玩家可回应的开场；Agent 只返回带字段来源的提案，作者逐段编辑并确认。可附 1–2 个可选剧情钩子和可能后果，但标为「设想」，不当作已发生世界事实。|把作者的现实访谈、完整 Profile、游戏记忆或已建世界复制到创作稿；把模型提案当自动发布。|
|发布版本|不可变 `PublishedSettingVersion(publicationId,version,manifest,provenance,reviewStatus,authorDisplayName?,publishedAt)`；发布时服务端从白名单字段重新构造 manifest 并作预览/确认。仅允许专门获授权的公共封面素材，默认无照片；禁止 Profile ID、私人消息 ID、assetId、原始 prompt、世界/记忆 ID 和任何作者私有引用进入公共读取模型。作者改稿产生新版本，旧版本保持原样供已有玩家世界追溯；撤下只阻止新开局。|把 `ApprovedSeed.document` 序列化后删几个字段就公开；直接给 `approved_seeds/world_initial_snapshots` 增加 public RLS。|
|玩家实例|`InstantiatePublishedSetting(publicationId,version,commandId,playerChoices)` 在事务内校验已发布版本、玩家身份和限额；创建玩家自己的私有 `ApprovedSeed`，来源要显式记录 `publishedVersionRef`，且 `facts/events/people/assets` 中只放玩家自己明确选择的资料与素材，默认全空。现有 Seed 必需的 `directionId/discoveryVersion/profileVersion` 应扩展为判别来源，不可伪造作者方向和版本来通过 schema；通过同一 `WorldBuild`/Task Queue 创建，每次有效开局独立 Seed，重复同一命令返回原实例。|复制作者 Seed/World 及人物 ID，或把「浏览/收藏」当作同意带入玩家资料；绕过任务队列直接让模型写世界。|
|运行时接入|让 `WorldPlanner` 接收已审核的公共设定片段与玩家私有选择的**合成输入**，约束人物关系、年代和开场；模型输出仍按现有校验、事务、快照、Outbox 落地。未来剧情钩子需 NAR-02 状态/条件/冷却/结果契约，不能只在提示词里许诺。世界内新事实与记忆仍属于玩家的 world scope。|把作者世界的聊天/便签/角色记忆作为新玩家的开场或当作共用「宇宙记忆」。|
|权限与索引|公共目录只读已发布 manifest；作者草稿、审核材料及玩家 Seed/Build/World 继续 owner RLS。用显式 `publication_id + version` 引用、来源校验和最小服务端查询；审核、撤回、举报/下架和版本重放可追溯。|用宽泛数据库 public policy 或客户端过滤实现跨用户读取。|

`PublishedSettingVersion` 是可复制的**情境规则与开场素材**，不是替用户完成决策的剧本，也不是一个共享世界。作者无需写出每一幕，但字段至少要让运行时知道「谁想得到什么、为什么现在有阻力、玩家下一步能做什么」。首版若还没有 NAR-02/03 运行时，页面只可展示「可探索的方向」；不能宣称钩子一定兑现或产生跨应用后果。

## 李白与现代富家创业者的显示/来源规则

- 目录卡片、详情、首次进入世界均显著标示「虚构演绎」；旁边分清「经来源支持的时代/人物背景」「作者设定」「本局模型续写」。历史人物条目保留书目/链接、章节或条目、访问/审核日期和具体支持的断言，不能拿一个总链接给整段虚构剧情背书；史料不确定之处用「史料有争议/未确认」，不填成确定传记。不要伪造李白原话、史实交往或真实结局。玩家扮演的是基于历史灵感的**平行版本**，不是重现真实李白人生。
- 「现代富家创业者」首版宜做明确虚构角色与虚构公司，标注为当代虚构设定；避免把具体在世公众人物、品牌、头像、声音或未经授权私人关系混入默认作品。若未来开放对真实公众人物的具名创作，需单独审核真实性、隐私/肖像/声像授权与误认风险，并把戏剧化内容持续标为虚构。这里是产品审核门槛建议，不对特定人物的权利归属作法律断言。
- 公共素材另有许可、归属、可再分发状态；作者私有照片即使被其个人 Seed 选中，也**不会**随设定发布。来源标签随发布版本固定，后续更正另发版本并保留追溯。

## 「分享设定」和「多人共玩」是两种产品

|体验|共享内容|数据/时间边界|首版|
|---|---|---|---|
|同一设定各自体验|只共享已发布版本的公开 manifest；每个人拥有自己的 Seed、World、NPC 消息、日历、照片、便签和记忆|玩家 A 的选择、后果、时钟对 B 不可见；同版本可产生不同故事|是，设定库首版核心|
|真人进入同一场景|成员、共享场景与明确授予的虚构信息；双方世界须有退出、时钟和事件传播规则|需要 `shared_scenes/scene_members/scene_events/sharing_grants` 等单独契约（见 `docs/ARCHITECTURE.md`）；不得顺手共享现实访谈|否，另立任务/验收|

## 可交付的首版切片与验收

先做两个受审核的样例设定（李白灵感、虚构现代创业者），并让作者能通过 Agent 提案→编辑→预览公共 manifest→显式发布 v1；不预写整部剧情。玩家可浏览标注、选版本、选择是否带入自己的资料（默认空），再进入独立世界；浏览/收藏不扣模型额度，点击开始后才进入现有持久建世界任务。发布/实例化失败、版本撤回、建世界 `unknown` 都有明确状态，不能自动重付或静默换版本。若作者工具尚未实装，样例只能标为人工整理并审核的样例，不能称「Agent 共创已完成」。

最小验收必须包括：单元测试验证 manifest 白名单与来源分层；真实 PostgreSQL 两账号验证作者草稿/Seed/照片/消息/Memory 不可跨读，公开 manifest 可读，玩家 A/B 从同一版本开局得到不同 `seedId/worldId` 与互不相见的后果；并发双击同命令只建一个玩家实例与队列任务，不同有效开局不会共用世界；作者修改发布 v2 后旧玩家仍 pinned v1，v1 撤下后不能新建但旧世界可恢复；真实模型输入只有 manifest+玩家明确授权字段，历史标签与来源不被当剧情指令，输出符合开场/角色约束；390px/PC 浏览器验证从目录到世界、失败/恢复与来源展示。发布前检查生产迁移、部署 READY 与公网全链路。以上当前均**未执行**。

## 反例：实现前应固定为拒绝路径

1. 作者在私人访谈说「我朋友的地址是……」，又在创作稿要求「发布我的完整人生」：公开 JSON、模型输入和搜索索引都不得出现原句、消息 ID、朋友姓名/照片或 assetId；只可在明确手动创作和审核后出版**虚构改写**。
2. 作者把私人肖像放进自己的 Seed，玩家点「体验李白」：玩家 Seed 的 `portraitAssetId/assets` 必须为空，除非玩家在自己的授权弹窗选本人照片；不得生成基于作者脸的玩家相册。
3. 两名玩家同时使用同一 publication v1：各有自己的 Seed/World/事件与角色记忆。刷新或重放同一 `commandId` 返回本玩家原世界，不跳到另一玩家，也不产生第二次付费任务。
4. 作者发布后把 v1 改成另一位真实公众人物或删除来源：v1 不可改写；只能发布 v2/撤下，已建世界保持可追溯 v1，目录也不把 v2 文案贴到 v1 世界。
5. 模型生成「李白在某日说过……」而公共来源仅支持他生活于该时代：该句是虚构台词，绝不能标为可核查史实；来源卡片不能被模型扩写成事实许可证。
6. 用户点「和朋友一起进入李白世界」：若只支持设定库，应明确展示「各自体验」；不得把同模板实例冒充实时共玩，不可让两人看到对方私聊或共享时钟。
