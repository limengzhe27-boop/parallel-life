# WRITER-UX-06B · 编剧后台与时间约束只读审查

2026-10-13；Agent codex-writer-ux-06b-01a11a84-20261013。读取root目录`.local/worktrees/world-publish-intake-01`，HEAD f7125df及其当前文件；未修改业务代码、Q文件、协议、数据库或模型。仅本报告与本人主表登记。0模型/DB/browser/端口/部署。报告待root验收。

## 可立即执行的结论

后台可以让编剧先写故事、人物、前后条件，而不要求每个剧情节点有日期。现有阶段和候选事件的时间窗口本就选填，已有可靠的阶段前后、事件完成后、按拒绝/跳过/过期结果分路机制。先把这些业务能力用编剧语言呈现，把日期与编号收进高级设置；不要靠删除必填日期绕过运行校验。

尚不能承诺“上一个事件发生后一小时/隔天再来”会自动执行：`timeNote`仅作者备注，当前运行逻辑不读取它；条件后的动态延迟没有对应字段。本轮可让作者选择“条件满足后由导演安排”，但不能把明确“一小时后”静默降成“随时”，也不能把它错误换算成开场后一小时。

## 时间实际约束与最小处理

|项目|当前代码约束|最小可行UI/处理|
|---|---|---|
|世界起点 world.startAt|具体ISO必填，直接成为世界时钟与消息历史起点|首屏用“开场时机：系统安排／指定日期”；系统安排仅为无时间约束的新稿一次性生成运行锚点，写入编辑稿、展示安排摘要，走正常保存。已有非空值一律保留，不猜它由作者还是系统填写。|
|已发生事实 history.occurredAt|每条必填，必须不晚于开场|作者必须确认“已发生”与谁知道；缺确切日期时提供“开场前／昨天／指定日期”的相对编辑。转换为同一锚点前先确认明确的相对语义；不能仅凭数组顺序捏造过去事实和精确时刻。|
|开场已有消息 phone.messages.at|history严格早于开场；incoming不能晚于开场；发送人须开场已认识|主层保发送人、原文、过去对话/开场来信；日期折叠。作者明确选开场来信，可直接用起点；过去消息先按作者给出的先后或昨天等约束排期。缺时间但历史身份已明确的自动排序须标为系统排期并可预览，不声称原稿提供了某分钟。|
|已有邀约 phone.invitations.at|不早于开场，关联真实开场消息、人物与地点，status仅proposed|保持“只是提议、尚未接受”，不可放成已经完成。具体见面时间无约束才可让系统建议；仍须保明示时间。|
|阶段 timeline.stages|window选填；order及afterStageKeys控制阶段次序|主层用阶段卡与“在什么阶段之后”；顺序号由UI维护，日期窗口默认关闭。order只是排序，不自动构成依赖；不能只拖卡不写afterStageKeys就承诺严格先后。|
|候选事件 prerequisites|支持history_fact、after_committed_node、after_resolved_node、at_place、not_before；日期条件是可选的一种|主层只保事件做什么、由谁、何时有机会（开场可出现/上一节点落实后/指定结果后/到地点后）。日期条件仅作者主动选时出现。没有前置不等于必然立即发生。|
|候选邀约 intent.earliestAt|具体ISO必填，不早于起点；不是候选事件的触发时间|“最早可约：由导演安排（无额外时间限制）”可在作者选择后用起点作为下限；不可描述为一定在开场见面。指定未来时间保留。|
|事件/阶段window、timeline.timeNote|window有严格开始/截止、嵌套限制；timeNote不执行|默认折叠“限定日期/错过后怎么办”，已有设置显示摘要；不要渲染空日期控件就生成空window。timeNote明确标“作者说明”，不要让自然语言承诺替代真实条件。|

**排期边界：**具体锚点一旦写入已保存草稿，就成为该版本的一部分，重新打开/检查/试演不能用Date.now漂移。试演、回执、导入前后核对绑定draftVersion/contentHash。当前协议没有“此时间由系统生成”的可靠持久标记；不新增协议时，保存后只能把所有非空时间当既有约束，不能实现可持续自动重排或无损切换“永远相对日期”。所以本轮承诺应是“一次性安排缺省运行时间”，而非“任意剧情自动排期”。

有作者明确年月日、钟点、今晚/昨天等原文约束，却缺少可靠日期锚点时，先显示一条业务问题“这段从哪一天开始”；不能因为结构startAt为空就采用今天并覆盖原文语义。仅“不要求日期”且没有相冲突的作者约束，才用系统锚点。未知/格式异常的非空时间保持原稿并提示修正。

## 真正阻止试演与不该阻止项

当前试演使用**已保存且版本/hash吻合的草稿**；未保存修改须先保存。编译器先完整schema验证，再查实际支持能力，不能仅靠前端隐藏字段解决。

会阻止：缺必填作品/世界/主角文字、少于2人物、人物必填人格文字、没有合法起点地点；上述必需时间缺失/错误或历史在未来；缺失/重复引用、知情权限冲突、剧情依赖循环/逆序/窗口矛盾；启用timeline却有事件未选阶段；不支持的运行能力。当前实现还限制所有人物开场已认识、单人物候选邀约、受支持的封面/头像资源、便签有玩家已知事实来源、已知地点数量及路线/人物文本预算。应按受影响条目给出解决路径，不能静默修成另一个故事。

**不该当试演门槛：**没有trialVerified（它是发布前验证的结果，首次试演不能先要求它）；未发布/未上架；没有媒体、历史、手机消息、候选事件或timeline（对应允许空/可选）；没有可选的窗口、日期前置、timeNote、互斥与替代。`editorial_only`可保存/编译但不会主动执行，应显示“仅作写作备注”，而非假装已经配置事件。

当前check.status会因trial_unverified显示blocked，这是**发布检查**，不代表不能首次试演。建议“可试演所缺内容”与“发布前待验证”分组，避免再次制造先试演/先检查互相卡住的体验。
