# 任务交付报告：L-01 人生列表、切换、重命名、归档与删除策略

## 一、任务背景与目标

在《人生剧本》的多人生与持续生活演化架构中，玩家可以拥有并切换体验多段不同人生（从飞书编剧稿导入的自定义世界、官方剧本创生世界以及出版作品世界）。
为了避免不同人生间人物资料、消息历史、素材与时间的串位，并提供完整且健壮的生命周期管理，任务 `L-01` 确立了如下核心目标：
1. **人生列表与切换 (Listing & Switching)**：
   - 为前端与移动端提供统一的 `GET /api/v1/worlds` 接口，完整聚合用户所有可用人生；
   - 包含世界 ID、标题、版本号、创建与更新时间、当前故事时间、角色人数、最新摘要与来源类型（`custom` / `official` / `published`）；
   - 支持按生命周期状态筛选（`active` / `archived` / `all`）。
2. **人生重命名 (Renaming)**：
   - 提供 `PATCH /api/v1/worlds/[id]` 接口，允许修改人生的自定义标题；
   - 具备完备的边界校验（1-60字，去除首尾空白，防空字符串）。
3. **归档与恢复策略 (Archive & Restore)**：
   - 归档时自动记录 `archivedAt`，并将世界时钟自动置为暂停（`paused: true`），阻止后台继续推进；
   - 恢复时移除归档标记，重回活跃列表。
4. **安全软删除策略 (Soft-Delete Strategy)**：
   - 提供 `DELETE /api/v1/worlds/[id]` 接口；
   - 采用安全软删除策略（记录 `deletedAt` 并暂停时钟），保障底层历史事件、媒体素材和因果关系的引用完整性，绝不破坏数据库物理外键；
   - 软删除后立即从所有人生列表中排除，后续对该世界的所有读写操作均返回 404 `NOT_FOUND`。
5. **多租户与跨人生权限严格隔离**：
   - 用户仅能查询、修改、归档或删除自己所属的人生（`owner_id = user.id`）；
   - 尝试跨用户或跨世界非法操作一律抛出 `NOT_FOUND`，保护玩家隐私与世界独立性。

## 二、架构契约与代码变更

### 1. 契约定义 (`src/contracts/life-management.ts`)
- 定义纯领域 Zod Schema：
  - `WorldLifecycleStatusSchema`: `'active' | 'archived' | 'deleted'`
  - `WorldListItemSchema`:
    - `id`: 世界 UUID
    - `title`: 标题
    - `version`: 当前版本
    - `createdAt`, `updatedAt`: 时间戳
    - `storyTime`: 故事当前时钟
    - `status`: 状态
    - `archivedAt`: 归档时间（可空）
    - `actorCount`: 人物数量
    - `previewText`: 最新预览（优先取最后一条助理消息，兜底使用场景设定或标题）
    - `sourceKind`: `'custom' | 'official' | 'published' | 'unknown'`
  - `WorldListResponseSchema`: `{ worlds: WorldListItem[] }`
  - `WorldPatchRequestSchema`:
    - `title`: 可选，1-60 字
    - `action`: 可选，`'archive' | 'restore'`

### 2. 仓储层实现 (`src/modules/world/infrastructure/postgres-world-repository.ts`)
- 新增核心生命周期管理方法：
  - `listUserWorlds(userId, options)`: 纯 SQL 查询用户拥有的非删除世界，按 `updated_at DESC` 倒序排列，合并时钟计算当前故事时间与来源类型。
  - `renameWorld(userId, worldId, newTitle)`: 严格校验标题边界，行级排他锁（`FOR UPDATE`）保障并发一致性，原子更新 `parallel_life.worlds.title` 与 `state->>'title'`。
  - `archiveWorld(userId, worldId)`: 写入 `state->'archivedAt'`，并在同一事务中直接更新 `parallel_life.world_clock` 将 `paused` 置为 `true`。
  - `restoreWorld(userId, worldId)`: 移除 `state->'archivedAt'`，重返活跃状态。
  - `deleteWorld(userId, worldId)`: 写入 `state->'deletedAt'`，暂停时钟，使后续查询与操作不可见。
- 增强 `owned` 检查：增加 `if (!row || row.state?.deletedAt) throw new DomainError('NOT_FOUND')`，确保软删除世界在所有业务入口一律不可读不可写。

### 3. API 路由集成 (`src/app/api/v1/worlds/`)
- 新增 `src/app/api/v1/worlds/route.ts`:
  - `GET`: 通过 `s.worlds.listUserWorlds` 读取当前用户的人生列表，支持 `?status=all|active|archived` 参数。
- 完善 `src/app/api/v1/worlds/[id]/route.ts`:
  - `GET`: 返回单个人生的手机端完整载入包，软删除自动拦截返回 404。
  - `PATCH`: 处理重命名、归档、恢复请求。
  - `DELETE`: 执行安全软删除。
