## 修复

`npc-agent-model.ts` prompt 升至 `npc-agent-v69-sticker-emotion-fit`，只加一条选择约束：

> 选 stickerId 时必须同时匹配你要表达的语气和对方当前情绪；安慰、道歉、对方难过/委屈/认真投诉时，不要选“笑死我了”“无语”“就这？”“摆烂”等调侃、否定或自嘲表情；没有合适图就不发，不能用一个不合时宜的图代替安慰。

仍然复用同一次 NPC 调用、同一 `stickerId` 字段和静态目录；没有新增情绪分数、审批、冷却、表或迁移，也没有第二次模型调用。表情仍必须独立于文字消息。

## prompt 单独不足，增加确定性删除闸门

第三次部署 `8bbef1a3` 后，用新命令 `50f45a04-3ccb-499e-94c4-528ca98a9f0b`（world 552→554）重试同一“委屈安慰”场景，NPC 仍输出：

- 文字“抱抱，别难过了。”
- 纯表情 `bailan`（摆烂）

说明只靠 prompt 不能保证选图语义。为此增加一个**只删除、不补图**的领域闸门：

- `stickerFitsStatement(text, stickerId)`：当 NPC 自己的句子包含委屈/难过/安慰/抱抱/道歉/认真投诉等语义时，如果该 sticker 的目录描述含自嘲、调侃、挑衅、无语、不赞同、冒犯、疲惫、崩溃、求情、哭泣、眼泪等负面/调侃词，则判定不适配。
- `agent-proposal-parser.ts` 在拆分文字+表情前调用该闸门；不适配时只保留文字 statement，删除 `stickerId`，不改变文字、回复意图或依赖绑定。
- 没有新增字段/表/迁移/模型调用；不是随机补图，也不是关键词选图，只阻止明显反向的安慰。
- `tests/sticker-protocol200.test.ts` 覆盖：`bailan/wuyu/xswl` 在“抱抱，别难过了”下被删除，`selected_ad` 保留；调皮语境下 `xswl` 仍保留。
- `tests/sticker-protocol200.test.ts` 3/3、`tests/npc-agent-model.test.ts` 49/49、`typecheck` 通过。

仍需第四次部署后重试同一场景；如果文字正常、图片被删除，即视为通过（宁可只发文字，不发不合时宜的图）。

## 发现并修正：v67 已经把文字和表情拆成两条 statement

第一次解析闸门只检查“同一条 statement 同时有 text 和 stickerId”，但 v67 的真实输出通常是：

1. `{text:"抱抱，别难过了。"}`
2. `{text:"", stickerId:"bailan"}`

因此仅检查合并 statement 不够，纯表情 statement 仍会绕过。已在 `normalizeExpressionMarkers` 增加同轮后处理：
记录最近一条非空文字；遇到纯 sticker statement 时，如果该文字与 sticker 不适配，删除这条纯表情，文字保留。调皮语境下 `xswl` 仍保留。

测试改为真实 v67 形状：合并 `bailan`、纯 `bailan`、调皮文字、纯 `xswl`，结果只剩
“抱抱，别难过了。”“看看这个表情，多调皮。”和纯 `xswl` 三条。`sticker-protocol200` 4/4、
`check` 3995/3995、`build` 通过。
