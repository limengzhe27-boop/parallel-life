# NAR-02B · 邀约的明确结果与一次承接

负责人 `codex-main-nar02b-20260928`，主目录。依赖 NAR-01、NAR-02A；这是 NAR-02 的一段纵向闭环，不代表完整长期剧情线已完成。

## 本段交付

- NPC 提议的约定仍只是提议。用户接受后，到了故事约定时间，可以在日历明确记录“已赴约”或“未赴约”；系统不会仅凭时间或 NPC 台词代用户认定结果。取消、改期仍可用，终态不允许再修改。
- 选择沿用世界命令、事件、回执和投影。记录包含故事时间与事件版本；刷新和重启后从事件恢复。同一命令幂等，并发相反选择只有一个成功，其他用户读写不到该世界。
- 导演只对已到期的确认约定或用户明确记录的结果安排一次有因由的 NPC 后续。角色只收到自己参与的约定；已回应结果不再反复提醒。舞台提示和角色创作规则禁止虚构主角赴约或现场细节。
- 日历详情把结果入口与普通聊天、改期、取消分开，二次确认后提交。开发预览只使用标明为合成的约定，不连接产品数据。

## 验收证据

- `npm run verify`：214 项常规测试、33 项真实 PostgreSQL 测试通过。新测试覆盖赴约时点、相反结果并发、回执重放、跨用户隔离、重启恢复、一次 NPC 承接后的停止。
- `npm run build` 通过。开发合成手机在 390px 无页面横向溢出，1440px 桌面内手机宽 420px；日历详情操作入口可见。按钮在开发样板中禁用是因为预览不接真实写入，服务端提交由真实库测试验收。
- 生产 Supabase 29 项迁移校验和一致，本段无新增迁移。

## 边界与接续

这只是“邀约”一种有明确用户动作的剧情线；大目标、障碍、证据、不同道路、可验证成就与跨相册/便签的回报尚未形成通用剧情线。自动检查仍发生在进入手机或返回前台，不是后台实时推送。下一步继续 NAR-02 的目标/阶段/结果状态与 NAR-03 的跨应用后果，不用加更多机械提醒替代故事。
