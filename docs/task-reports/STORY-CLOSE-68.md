# STORY-CLOSE-68 · 明确时间线的剧情接续

主线基线 `caf645de`，修复提交 `e6c3db55`。验证使用独立本地 PostgreSQL 55634 的合成发布作品和存档。

## 修复

编译后的旧运行计划会从第一个 `director_event` 推导开场。作者明确第一幕是邀约、第二幕才有 `director_event`，并留空开场时，推导会把第二幕节点设为唯一开场。原始资格中第一幕可演、第二幕被阻塞，而运行门只允许第二幕，导演候选变成空集。

导演快照与提交重验证均从已读取的同一份作者目录取开场与时间线。有作者时间线时使用作者开场，留空即按初始幕进入。没有作者时间线时沿用现有推导节奏。没有数据库迁移。现存记录保持原样。

## 验证

- 原有真实 PG 夹具修复前五项失败。适配当前导演 wire，并增加显式开场与无作者时间线两项正向断言后，真实 PG 7/7、阶段门单测 7/7、类型与模块边界检查通过。
- 可执行邀约、展示邀约均不解锁接受型下一幕。玩家接受写入唯一整事件结果，后续幕使用该结果的来源 ID 进入可演范围。重复请求没有产生第二份结果。接受型事件拒绝后仍被阻塞。作者明确要求拒绝结果时，真实拒绝也能开启下一幕。未经授权的另一个用户不能读结果。
- 额外使用真实 DeepSeek Flash 验证四个独立合成样本。首个真实导演有效选择第一幕，真实 NPC 参与但只询问方便时间，未生成邀约动作。第二个新样本的真实导演响应为无效 JSON，未重买。第三个以受控导演交接提供具体邀请时段，真实 NPC 选择参与并调用 `appointment.propose`，邀约实际落库，玩家通过正常响应入口接受，下一幕解锁。第四个样本的真实导演正确生成小店 10 点邀约任务，真实 NPC 发出具体邀请并保存等待计划和责任，但仍未调用日程动作，阶段按实际证据保持阻塞。样本验证了真实 NPC 行动到结果的链路，完整自然导演到人物的闭环仍需成功样本。
- 未用原用户存档执行、未切换 3218、未发布公网。
