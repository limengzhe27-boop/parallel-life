# CHARACTER-AUTHOR-20-O · 聚焦微信补写的安全采用器

状态：待集成人合入与线上验收。基线：`origin/main` 的 `8367add`。负责人工作树：`character-author20-q`。本任务未调用真实模型、未操作数据库或部署。

## 交付

- 新增纯函数 `applyDirectSocialProposal(current, proposed, actorKey, focus)`，供工作台在项目 Agent 返回完整草稿后采用。返回 `{ content, added, error? }`；失败返回原草稿引用、`added: 0` 与稳定错误码，不写入任何对象。
- 只接受已相识且唯一匹配的角色，在指定的历史聊天或朋友圈集合**末尾追加**。原有记录必须逐项、逐字、顺序不变；另一类别、其他人物、公开档案、五维人设、秘密、世界、扩展字段等任何变化都拒绝。新记录仅能使用该类别允许的字段，必须有唯一合法编号、指定人物、正文及合法 UTC 时间；已有明确开场时间时还要保证历史早于开场、动态不晚于开场。未写开场日期时不擅自补日期。
- 成功结果从当前权威草稿复制，仅替换已核对的集合，不直接采用模型提供的其他内容。没有新增内容也不会声称成功。
- 专属测试覆盖成功采用、原文保护、私密和旁支篡改、旧记录改删重排、错误人物、编号冲突、非法/未来时间、未相识人物、未设开场日期与输入不变性。
