## Defect and correction

Private/native loaders already cropped forgotten sources, but late attachAgentWorldContext fetched73 awareness afterward and added knowledge/self-position without the same revocation set. This could reintroduce a location report or revive state sourced by a previously withheld knowledge alias before the model call. A final kernel rejection would be too late to prevent disclosure.

forgottenAgentSourceIds now builds a **denial-only owner/world source-lineage closure**, starting from this actor's relevant forgotten memory provenance. Existing character/branch scope policy remains. Links cover original private message/opening/event/runtime input receipt, native original-command receipt/event/group message/scene item aliases and own report evidence.inputReceiptId/self-position aliases. Known wrappers normalize to their original record identities. Only IDs/lineage metadata are read; no private transcripts are returned. There are no thread/container/actor identity edges that would treat one forgotten input as an entire conversation forever. Native aliases are conservative suppression, never knowledge/read authorization. Optional new table queries use actual has_table_privilege checks, preserving older worker ACL boundaries; no new grants or permission mutations.

Late attachment first reads this actor's awareness, then obtains a fresh same-lineage forgotten set. It re-filters preexisting snapshot.sources/observations too (covers an earlier loader that ran before a revocation), drops knowledge whose event/knowledge handle/original report input receipt is forgotten, and checks source version/story time/available place. Own position with forgotten source/handle becomes unknown; it never guesses an older position. A newer independently sourced physical position can still be used. It recomputes authorizedAgentState using only surviving sources so a knowledge alias cannot resurrect hidden goals/decisions. Canonical actor state/history/awareness rows are not deleted or rewritten by reads.

The helper builds on previously authorized private/native snapshots and own-observer awareness; it is not a public arbitrary-snapshot authorization API. Existing identity/channel membership/source checks remain essential. Original receipt/event/input aliases are suppression only, not a way for another actor to read the owner's private line. No plaintext is added to errors/logs.
