# D-09 访谈重试路径必然失败（用户实际卡点）

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已完成并上线验证。

## 现象

用户自己在生产环境（https://parallel-life-nu.vercel.app）聊天时第一步就失败，界面显示「这次没能完成回应。你说的话已经保存。」+「重新回应」。**点几次都失败**，因此无法进入后续的档案沉淀、分支推荐与进入手机。

生产库记录：

| 时间（UTC） | 状态 | 错误码 | 模型/耗时 |
|---|---|---|---|
| 13:34:07 | unknown | INVALID_RESPONSE | 未记录 |
| 13:59:04 | failed | AI_FAILED | 未记录 |
| 17:36:53（我点重试） | failed | AI_FAILED | 未记录 |

## 定位

1. 用同一句话在本地直接调用模型 + 校验：4/4 通过 → 不是提示词或模型问题。
2. 关键差异：**「重新回应」走的是 Worker handler 路径，而正常发送走流式路径**。此前所有本地验证都只用过流式路径，handler 路径没有真实调用过。
3. 本地精确复现：中断流式请求 → 任务留在队列 → `retry` → `run`，稳定复现 `failed / AI_FAILED`（7.5s）。
4. 失败没有诊断信息（这是另一个缺陷），于是加了一行脱敏日志后读到真实异常：

```
DomainError INVALID_COMMAND: New memory candidates must start as suggested
```

根因：handler 把抽取到的事实**直接写成 `confirmed`**（并同时直写 Profile），而记忆领域规则（[candidate-repository.ts:39](../src/modules/memory/infrastructure/candidate-repository.ts)）规定候选必须先是 `suggested`，只能由用户确认后升格。异常让整个事务回滚 → 回复、候选、提问全部没有落库 → 用户永远重试不成功。流式路径写的是 `suggested`（正确），所以正常发送没事、只有重试必然失败。

## 修复

|文件|改动|
|---|---|
|[src/modules/profile/infrastructure/interview-handler.ts](../src/modules/profile/infrastructure/interview-handler.ts)|只登记 `suggested` 候选，与流式路径一致；不再直写 Profile（符合产品规则「AI 只提出变更、由用户确认」）|
|[src/modules/tasks/application/run-worker.ts](../src/modules/tasks/application/run-worker.ts)|失败时输出脱敏诊断（taskId/kind/errorCode/领域错误信息/耗时，不含用户文本与上游内容）；`INVALID_COMMAND` 按其本身上报，不再笼统归为 `AI_FAILED`|

## 为什么没有被测试拦住

覆盖这条路径的真实库集成测试**早就存在**（`tests/integration/interview.test.ts` 断言候选必须是 `suggested`），buggy 代码会让它失败。但 `npm run check` 只跑 `tests/*.test.ts`，真实库测试是独立的 `npm run test:db`，且仓库没有任何 CI（AUD-17）。**修复建议：把 `test:db` 纳入交付前必跑，或加 CI。**
