# NAR-02K · 多日回访与角色间选择性知情

负责人：`codex-main-nar02k-20260929`。基线 `26c4474`。属于 NAR-02 的一段可验证交付，不表示完整剧情引擎、关闭网页后的后台推送或多人玩家已完成。

## 用户问题与改法

旧导演按真实时间推进手机日历，却总把多日离线的最多三次节拍安排在离开后的前 90 分钟；没有未了事项时，几天都不会有新消息。现在对长时间离线只抽取最多三个分布在经过日期的节拍，按该节拍时间显示来信。已有私聊在超过一天后可触发一次自然回访；未回复的开场消息在超过两天后最多再触发一次。不因沉默无限追发、也不编造用户在离开期间完成了什么。节拍仍受世界暂停、页面可见检查、同轮角色限次与导演事务保护；一比一时间和日历保持一致。旧版已开始但结果不明的导演尝试用原命令 ID 人工恢复，避免排期策略变化造成重复模型调用。

NPC 之间从此可以发生**有来源的单跳转述**：导演只在当前人物的主动回合中，依据人物性格、已有关系和该人物亲自收到的用户原话，可选地建议转述给一位角色。运行时核对原消息确属用户发给当前人物、原话连续片段真实存在、接收者在本世界、同一来源未向该接收者重复传递；用户明确说“别告诉/保密/只告诉你”等则拒绝。有效转述保存在接收者私有的“听说”认知，不升级为世界事实；其他人物不因此获知。接收者可以在后续节拍做出自己的反应，并须说明消息从谁而来。模型可能选择不转述；这符合角色自主性，不保证每条秘密传播。

同时封住旧路径：世界回合摘要（branch episode）之前作为共享记忆直接发给所有角色，可能间接暴露另一位人物的私聊。现在它仍供导演管理全局，但不再送进任一 NPC 的角色上下文；角色保留自己的私聊、个人记忆、公开事实及明确转述给他的认知。

## 验证

- 单元：多日节拍分布、首次回访一次性、未回复开场不连发、来源/保密/重传拦截、接收者可见性、模型无效提案过滤。
- 真实 PostgreSQL：五天回访出现两个不同日期的角色来信；转述仅妈妈可见，朋友不可见；刷新重开保留；原命令重复推进无第二条；旧版结果未知的导演回合自动模式拒绝、人工恢复保留原命令。数据库测试与现有迁移兼容，本批无新增迁移。
- 合成人设真实模型抽样两次：谨慎的姐姐选择不转述，另一设定下姐姐提出先征求主角意见；证明角色可以不转述，不能把模型指令当作转述必成的承诺。
- `npm run verify`：240 项常规测试、36 项真实 PostgreSQL 集成测试全部通过；`npm run build` 通过。生产 Supabase 29 项迁移校验和一致，无新迁移。本批没有更改手机布局；旧的日期显示组件会按新的持久时间戳显示不同日期。
- 部署结果见下方发布记录，发布前本任务保持待验收。

## 仍待完成

- 关闭网页后由服务端定时唤醒、系统级通知、长期剧情状态与跨应用照片回报仍属 NAR-02/03；本次回访只在用户进入或保持手机页面时运行。
- 人物之间的关系仍主要来自生成时的简述，没有独立的人际关系图及“传闻可能失真”的后果模型。导演可按性格与关系决定是否传递，但尚未对角色转述质量做大规模评测。
