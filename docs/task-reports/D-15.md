## AUD-17 交付门槛与 CI（问题的根源）

**问题**：真实库测试是独立的 `npm run test:db`，`npm run check` 不跑它，仓库也没有 CI。2026-09-23 那个"访谈重试必然失败"的确定性 bug 因此漏到生产——覆盖它的集成测试当时就已经存在。

**改动**：
- 新增 `npm run verify` = `check` + `test:db`，作为交付前必须通过的单一门槛。
- 新增 `.github/workflows/verify.yml`：`check` 作业跑边界/类型/单元测试、`format:check`、生产构建；`database` 作业用 `postgres:18` service + `scripts/ci-db.mjs` 建好受限角色与库后跑真实库测试。
- 新增 `scripts/ci-db.mjs`：可复现地创建 `pl_app`/`pl_worker`（`NOSUPERUSER NOBYPASSRLS`）与 dev/test 库，写忽略的本地配置，**不打印任何凭据**；支持 `--dry-run`。本地已实跑（幂等，无副作用）。
- 预览开关收敛为一个决策点：`src/contracts/preview.ts` 的 `isPreviewOnly()`，替换原先四处分散的 `process.env.APP_PREVIEW_ONLY === '1'` 比较；新增单元测试覆盖 `'1'/'0'/''/'true'/缺失`。

## AUD-12 Worker 停机（不再把已付费的调用白丢掉）

**问题**：SIGTERM 直接 `abort()`，正在执行的任务被立即取消并记成 `unknown`——而那次模型调用可能已经完成并计费。心跳在中止后仍会续租。

**改动**：
- 新增 `src/modules/tasks/application/run-loop.ts`：收到停机信号后**不再领取新任务**，在途任务保持存活信号并享有**有界宽限期**（默认 20s）以提交结果；只有超过宽限期才中止（此时如实记为 `unknown`）。
- `src/workers/main.ts` 改用该循环，并打印本次是"允许在途任务完成"还是"中止并记为 unknown"。
- `run-worker.ts`：中止后不再续租心跳；`CANCELLED` 归入不确定结果（不当作普通失败）。
- 依赖注入 `sleep`，使 `application` 层不依赖 node 内置模块（边界检查要求）。
- 新增 `tests/worker-loop.test.ts`：停机发生在任务执行中时**工作信号不被中止**（drain 成功）、超过宽限期才中止、空闲轮询与队列错误不中断循环。

## AUD-13 索引与 N+1

**问题**：外键不自动建索引，`world_appointments`/`world_media_requests`/`outbox_jobs`/`assets`/`world_builds` 全表扫描；`BuildRepository.list()` 每个 build 两条查询（最多约 200 次往返）。

**改动**：
- 迁移 `0021_missing_indexes.sql`：补 `world_appointments(world_id)`、`world_media_requests(world_id)`、`outbox_jobs(world_id,status)`、`outbox_jobs(status)`（部分索引）、`assets(owner_id,status)`、`world_builds(owner_id,created_at DESC)`、`tasks(owner_id,scope_kind,scope_id,created_at DESC)`。
- `list()` 改为单条 `LEFT JOIN LATERAL` 查询（含 `scope_id::text` 类型转换，`tasks.scope_id` 为 text 而 `seed_id` 为 uuid）。
- 生产实测：分支列表接口返回 200、1 个 build、`ready=true`、`hasTask=true`，页面显示"我的分支 1 · 如果这家小公司变成你待了很多年的地方 · 进入体验"。

## AUD-08 非法 world id

`GET /api/v1/worlds/:id` 对非法 id 原先经 `Id.parse` 抛 ZodError，被归一成 503"暂时无法连接"；现改为 `safeParse` → **404**（形如 `not-a-uuid`）。本地已实测 404；未知但合法的 uuid 仍 404（所有权/不存在）。
