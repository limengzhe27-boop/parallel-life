## 1. 交付与解决的真实问题

### 1.1 彻底切断“玩家肖像默认泄漏至 NPC 请求”缺陷
- **历史缺陷分析**：原 `media-handler.ts` 第 39–46 行，当请求无 `referenceAssetId` 时，无条件查询 `world_initial_snapshots.approved_seed->>'portraitAssetId'`（即玩家本人的肖像），导致任何 NPC 的生图请求都会偷偷套用玩家的脸生成图片。
- **修复方案**：
  - 彻底移除玩家肖像无条件回退逻辑；
  - 角色生成仅通过 `targetActorId` 解析 `parallel_life.world_person_bindings` 中已授权的 `asset_id` 与 `asset_revision`，且要求该资产在 `parallel_life.assets` 中处于 `ready` 状态；
  - 若 NPC 无授权肖像底模，系统返回 `text_anchored_only`（纯文本外貌锚定）模式，不携带任何参考图，**绝对不拿玩家肖像冒充 NPC**；
  - 场景模式（`purpose === 'scene'`）严格拒绝携带玩家肖像作为参考图。

### 1.2 建立结构化、版本化的 PromptBuilder (`v1.0.0`)
- 新建 `src/modules/media/domain/prompt-builder.ts`：
  - 遵循 `prompt-images` 规范：使用完整摄影语言描述（35mm 胶片、Kodak Portra 400 颗粒质感、50mm 肖像定焦镜头），拒绝逗号标签堆砌；
  - 遵循 `prompt-videos` 规范：实现 7 层场景结构（主体、环境、动作、风格、运镜、构图、氛围）与 4 层音频描述（对白、环境声、音效、BGM）；
  - 强制添加 `(no subtitles, no captions, no on-screen text)` 指令抑制视频模型硬烧字幕；
  - 对白采用冒号语法（`The character says: ...`）确保口型与自然发音。

### 1.3 确立面向端口的媒体提供商适配器 `MediaProviderAdapter`
- 端口定义：`src/modules/media/application/provider-ports.ts`；
- Replicate 适配器实现：`src/modules/media/infrastructure/replicate-provider-adapter.ts`：
  - 支持 `black-forest-labs/flux-schnell`、`black-forest-labs/flux-1.1-pro` 与 `minimax/video-01`；
  - 支持 Base64 Data URI 或安全只读 URL 传输参考图；
  - 严格超时控制，提交超时抛出 `STATUS_UNKNOWN`，**绝不自动发起二次 POST 请求**，防止上游重复扣费；
  - 提供 `queryStatus` 与 `cancel` 能力，映射统一内部领域状态；
  - 严格遵守架构边界：不从 infrastructure 读取 `process.env`，统一由构造函数注入配置。

### 1.4 定义领域工具契约 `media-tools.ts`
- 新建 `src/modules/media/domain/media-tools.ts`：
  - `media.generate_image`：严格校验用途、宽高比、风格预设与构图；
  - `media.generate_video`：严格校验动作描述、运镜模式与 5/6 秒时长限制，不支持的参数显式拒绝，不静默忽略；
  - `media.share`：校验已有授权资产 ID 与目标角色接收者。
