# NPC-AUDIT-43：严格代码与产品联合审查

日期：2026-10-15。主审：codex-npc-audit43-01a13e13。用户明确要求使用严格审查者及产品经理角色；两位独立只读审查者交叉核对，主审复核证据并汇总。业务、数据库、生产、作者内容均未修改。

## 范围与结论

固定代码基线 a8e09c9f，来自 history-chat-media 集成工作树；用 git show 读取，避免其他集成者正在进行的修改改变结论。主目录 main 96e51d15 已落后。审查范围为世界/NPC业务链：进入、开场、私聊、群聊、人物目标、主动推进、等待、赴约、现场及恢复。不是对账号、支付、媒体、安全所有模块的全面认证，也不是对当前公网版本的重新验收。

产品依据采用用户最新要求：浏览12倍、交谈/现场1倍、空闲60～90秒检查有意义变化、重要节点阻止越过、等待可跳过、离开暂停、返回明确继续；明确区分沉默和拒绝，人物具有独立知情/动机/行动后果。不采用旧PRODUCT中默认1:1来否定当前需求。

结论：核心缺陷集中于业务因果和执行状态。多处用后续消息、关键词、计数、输入活动替代“谁负责哪件事、哪些行动真正处理了它”。当前不足以认定持续人生体验通过产品验收。没有发现可据本轮证据定为P0的灾难性故障；不能把所有结构债务一律当成发布阻断。

P1表示直接破坏核心旅程的逻辑问题；P2表示重构需要解决的职责、扩展或资源风险。以下路径均相对固定基线仓库。

## A1 / P1：无关聊天被当作约定已经得到承接

- 证据：world/domain/agenda.ts:94-102、120-128、143-154。
- 条件：已确认约定到期后，该NPC发过任何一条不同事件的assistant消息，即过滤appointment_due。赴约结果之后任意新回复，也能过滤appointment_result；未确认邀请类似。
- 示例：赴约时间已到，玩家问天气，NPC答天气，下次议程不再处理赴约。这不是取消日历约定，而是错误消除了该约定的主动承接资格。
- 根因：缺少行动与事项之间的明确因果确认，消息先后被当作处理回执。
- 重构边界：保存本次行动具体处理的事项及处理结果；普通闲聊不能消费赴约、交付等业务责任。
- 证据等级：直接静态条件确认，未真实模型/生产复现。

## A2 / P1：多套推进流程短路，人物行动未成为统一调度对象

- 证据：server/services.ts:239-272；server/publication-story-service.ts:69-85；settings/infrastructure/publication-story-repository.ts:1015-1072；world/domain/clock.ts:176-191。
- 条件：开场、发布剧情、通用agenda串联。发布导演池存在但没有候选时返回handled=true/played=0，通用推进没有机会处理普通约定或事项。
- 用户影响：一个分支暂时安静可以挡住另一条应继续的线。通用beat最终仍要求发一条来信，缺少统一的“人物选择行动—执行—结果—下次触发”协议；不能据此说所有效果或发布剧情都不能改变世界。
- 根因：以入口和发言回合组织运行时，各自拥有候选和进度解释权。
- 重构边界：同一个调度周期收集各来源候选，选择获准行动；消息是行动的一种呈现。保留暂停、未决调用和开场依赖等明确阻断，不简单删除handled判断。
- 证据等级：完整静态调用链，未线上验证特定存档。

## A3 / P1：同一NPC跨渠道的状态和来源协议断裂

- 证据：world/application/group-ports.ts:16-25、group-turn.ts:15-39；server/publication-character-planner.ts:26-92；world/infrastructure/group-repository.ts:234-255；world/infrastructure/actor-goal-repository.ts:78-91。
- 条件：群聊消息写world_group_messages，群邀约写world_appointments；普通目标寻找邀约来源只JOIN world_messages，无来源且不在初始快照就跳过。
- 用户影响：群内真实发起的约定可以出现在日历，却不成为普通人物目标。群聊也没有使用私聊链路补充的eventGoals、authoredLifeModules、actorSituation；同一人物跨渠道承接能力不一致。
- 根因：渠道各自建立输入、落库和来源识别，而人物只在actorId层面统一。
- 重构边界：统一角色状态读取、动作/来源协议与目标投影；各渠道负责不同的知情过滤和表达格式。不能共享完整私人聊天。
- 证据等级：完整静态写入/读取链确认。

## A4 / P1：群聊按关键词和数组顺序分配发言，忽略真实对话对象

- 证据：world/domain/group-runtime.ts:213-245；world/application/group-turn.ts:15-20。
- 条件：当前文本未@角色、与Persona无关键词匹配，所有分数为0时仍选人物数组第一位；函数不接群历史、上一提问者或事项负责人。
- 离线探针：直接执行固定基线函数，人物顺序[乙B普通朋友,甲A店主]，甲刚问几点来，玩家答“六点”，实际选B。“甲刚问”的信息根本没有输入通道。
- 用户影响：该回复的人沉默，另一个人接话；后续模型无法纠正已经分配错的演员。
- 根因：关键词相关性承担了对话轮次/业务归属路由职责。
- 重构边界：明确@、直接回应对象、当前线程、事项参与和自身行动责任共同决定候选；保留限制回复人数，不能以全员回复解决。
- 证据等级：独立审查者执行实际纯函数离线复现；非公网复现。

## A5 / P1：候选和实际续演使用不同进度口径，开场人数可以决定收尾

- 证据：settings/infrastructure/publication-event-goal-context.ts:324-336、406-455；publication-story-repository.ts:261-276、337-344；publication-progress-beat-store.ts:215-231；settings/domain/story-event-progress.ts:329。
- 条件：角色候选按本人可见记录算productiveBeats，真正领取续演时使用共享productiveBeats；多人物开场逐条计npc_progress。
- 主审固定基线探针：6人各1条开场、玩家0回复，共享计数6得到seek_closure；同时间、本人计数1得到advance_without_player。三项断言通过。说明同一后续在候选与领取阶段可能被不同口径解释。
- 用户影响：多人刚出场，后续已被要求收尾；不代表运行时自动判定成功完成。
- 根因：世界事件变化、角色有效交互和联系频率共用计数代理，两个阶段没有相同决策契约。
- 重构边界：事件事实进展、个人目标进展、联系策略分别有依据；准备候选与领取执行消费同一决策快照。聚合对象本身并非错误。
- 证据等级：实际固定基线领域函数探针 + 静态调用链。

## A6 / P1：未回应邀请变成所有快捷等待的阻断，沉默缺少可执行后果

- 证据：world/infrastructure/story-wait-repository.ts:240-255；world/domain/story-wait.ts:140-146。
- 条件：任意来源有效且时间未过的proposed约定设置importantMessage=true，等一会/等另一约定/休息到明早均原地停止。
- 用户影响：玩家想暂不回应，必须先处理邀请才能快捷等待，或者靠普通时钟流逝越过它；当前规则没有表达NPC何时改安排。保护重要节点本身正确，所有邀请统一阻断过宽。
- 根因：一个布尔值代替答复期限、是否已呈现、允许忽略、超时动作和影响范围。
- 重构边界：事项级决策窗口和超时/忽略后果；等待停在必要选择前，并允许明确暂不处理。
- 证据等级：静态确定条件，未公网复现。

## A7 / P2：交谈模式由输入框活动推断，阅读/思考不属于受保护的对话状态

- 证据：features/phone/time-experience-policy.ts:1-11；use-world-time.ts:89-111、153-159。
- 条件：非请求处理中、非现场，最近30秒未操作输入区域即恢复浏览模式。用户留在聊天阅读40秒也可回到12倍。
- 用户影响：用户理解为仍在交谈，时钟却恢复加速。已有约定截止保护，因此不能声称一定越过约定；确定问题是交谈定义与产品承诺不一致。
- 根因：DOM活动计时器替代交谈会话生命周期，且并非产品明确确认的阅读超时策略。
- 重构边界：明确进入/结束/暂离交谈的业务状态和可感知策略，保留浏览12倍、现场1倍。
- 证据等级：静态确定模式条件；未真机复验。

## A8 / P2：故事专属动作和台词句式进入通用现场协议

- 证据：world/infrastructure/scene-planner.ts:184、1031-1073、1111-1117、1165。
- 条件：结构化NPC动作槽只有receive_r17/inspect_r17，固定钥匙/维修单/R17/接头及第一人称执行句式。
- 用户影响：新题材的交接、检查要继续改核心代码；自然表达与执行证明绑在一起，人物可能被迫按统一句式说话。普通现场另有非结构化分支，不能扩大成所有现场只能玩R17。
- 根因：故事实例、能力授权和表达证据没有清晰分层。
- 重构边界：通用获准交接/检查动作，世界内容提供对象和约束，专属规则通过明确扩展点注册。不能把模型声称当成真实执行。
- 证据等级：协议和提示词硬编码确认。

## B：需要在同一次架构设计中处理的边界债务

1. **读取有写入副作用。** readActorEventGoals→publicationGoalContexts会初始化/补记已经发生的事件进度；模型准备失败也可能已经更新投影。它是基于成功事实的延迟投影，不是编造事实，但隐蔽了状态更新时机。读取和事件投影处理应有独立职责。
2. **运行状态与记忆混用。** actor-goal-repository.ts:177-225、498-523将普通目标进度JSON存为belief/agent_inference，发布目标则用专表；定义变化靠hash判定能否恢复。应统一执行状态语义。actor-context已排除内部进度记忆进入模型，不能报告成泄漏。
3. **持久化层反向协调业务。** PublicationStoryRepository承担选人/续演/协调；postgres-world-repository.ts:583-610直接调用它并构建人物上下文。应上移应用协调，并用共同事务工作单元保持原子性。
4. **外部调用期间持有数据库事务与连接。** clock-repository.ts:22-39在BEGIN和世界推进锁内等待完整模型工作，内部另走其他连接提交。存在慢调用和连接池压力风险，外层事务也不能回滚其他已提交事务。本轮没有压测，不能断言已耗尽连接。应分离领取、执行、校验提交和恢复。
5. **已知失败与unknown混用。** publication-story-service.ts:166-170将多种异常统一记unknown。明确输出不合法、版本冲突、已发送但结果未知需要不同恢复策略；禁止因此放松未知计费请求的防重保护。

## 对此前判断的收紧

- 中央调度、模块化单体、角色按需调用模型都可以支持产品，不是根因。
- 有状态字段不是能力验收；也不能称代码完全没有记忆/目标。
- 最新基线已修可选标注来源绑定与个人/shared阶段分离，旧quote格式故障不再列作当前同一缺陷。
- 只读补投影不等于无依据改世界；长事务风险不等于已发生连接池事故。
- 最新真实验收报告中重复回应/主动played0是历史实测证据，本轮没有调用新模型来重演，不把它们当成对固定基线的现场验证。

## 重构优先次序及验收

第一步：统一事项/人物行动的身份与因果回执，修正“任意消息已处理”语义；统一跨渠道来源协议。

第二步：统一候选评估与行动调度，整合开场/发布事件/普通事项。分开个人目标、共享事件事实及联系频率；加入明确的等待决策窗口。不要仅在现有分支上继续增设豁免。

第三步：渠道降为呈现/权限适配，故事实例从通用能力协议中移出；应用层拥有协调，仓储保存，投影消费已提交事实。建立领取→模型→短事务提交的执行阶段。

验收必须覆盖：开场途中回复；约定到期后无关聊天；群邀约切私聊；短答由原提问者承接；多人开场未互动；明确拒绝与沉默两条不同路径；等待途中重要变化；阅读聊天时的速度策略；换题材复用交接/检查能力。每条需要实际因果状态与玩家可见结果，不能只验API200或对白存在。
