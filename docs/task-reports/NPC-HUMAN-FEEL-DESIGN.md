# NPC"人感"设计要点（讨论结论，供开发参考）

> 来源：与产品负责人的讨论。**这些能力"都可以有"，但并非必须全部实现**——按世界与角色需要取舍。
> 本文只给方向与约束，不含实现细节；实现前请先与负责人确认范围。

## 0. 一句话目标

让人物**像人**，靠的是"行为 + 细节"，不是更华丽的文笔。
判断标准：把真人聊天片段和我们 NPC 的片段混在一起，人分不出来。

---

## 1. 必须遵守的原则

1. **行为优先于文笔**：会不会回、多久回、连发几条、要不要撤回——这些比措辞更能制造人感。
2. **情绪要"流露"，不要"播报"**：
   - ❌ "我今天心情很低落，因为工作不顺利。"
   - ✅ "算了，不想说这个。"
   - 不给模型"你现在愤怒/悲伤"的标签，只给**情境**（被客户骂、坐过站、没吃饭），让它自己写。
3. **时间触发只给情境，不发模板**：
   - 时间点（早上通勤 / 午休 / 下班 / 深夜）作为**上下文**交给模型，由它决定说不说、说什么；
   - **任何消息都必须带具体细节**（地点、身体感受、具体事），否则就会变成"早安～"式的模板，反而更 AI。
4. **状态用对话表达，不做状态字段**：不要心情值、亲密度进度条；情绪写在话里。
5. **不设硬性额度/冷却**：不要"每人每天 N 条"这种排班感。节奏交给角色性格与互动本身。
6. **允许沉默、允许无意义、允许记错**：真人会已读不回、会答非所问、会记错细节。
7. **聊天与事件并存**：闲聊要有，事件推进也要有；闲聊的价值在于**给事件供料**（提及的人/地点/情绪会变成后续线索），而不是废戏。

---

## 2. 两个高性价比细节（讨论中已确认想要）

### 2.1 正在输入（Typing Indicator）
- 消息落地前 1–3 秒显示"对方正在输入…"；
- 长度可感知：短消息 ~1 秒，长消息/连发 ~2–4 秒；
- **可以中断**（显示 2 秒后消失、过几秒再出现）——"打了又删"比一直显示更真实；
- 只在该角色确实要说话时出现；
- 实现上属于**呈现层**，可先不改消息契约；若要精确，可在消息上加 `typingMs` 元数据。

### 2.2 撤回（Recall）
- 由**人物回合**自行决定"发了又撤回"（角色行为，不是系统机制）；
- UI 微信式：`对方撤回了一条消息`；
- **撤回后原文不再返回客户端**；服务端只在审计里留痕（建议不存明文）；
- 可配合"撤回后换个说法重发"，真实感最强；
- 撤回事件进入世界事件，可被后续对话引用。

## 3. 可选能力（按需，不是必须）

| 能力 | 作用 | 备注 |
|---|---|---|
| 角色作息档案 | 上班族/夜班/学生/自由职业，时间触发天然错开 | 需要每个角色一份"身份 + 作息" |
| 说话样例（few-shot，3–5 条） | **提升辨识度最有效**的手段，比形容词管用 | 样例含：一句短的、一次连发、一次敷衍、一次情绪化 |
| 情绪记忆片段 | 让"昨天不开心、今天还没缓过来"成立 | 写进现有 memory（episode），不做状态机 |
| 连发多条 | 真人常一次发 3 条短句 | 需要消息契约支持一次生成多条 |
| 延迟回复 | 深夜慢、上班慢、亲近的人快 | 由代码/情境决定，不写死额度 |
| 无意义闲聊 | 让世界有生活感、为事件供料 | 与事件节拍并存 |

---

## 4. 内容边界（重要）

- **成人向内容采用"暗示式"**：暧昧、试探、留白（fade-to-black）、次日回响；
- **不写露骨性描写**：除合规风险外，模型供应商通常会拒答，直接导致现有链路报 `INVALID_AI_OUTPUT` / decode 失败（表现为红色感叹号）；
- 建议加 **18+ 门禁**（作品级标记 + 进入确认）；
- 亲密互动前应有明确的**态度表达/同意**，这本身也是"人味"的一部分。

## 5. 与现有系统的衔接（供开发定位）

| 主题 | 现有位置 |
|---|---|
| 人物回合提示词 | `src/modules/world/infrastructure/turn-planner.ts` |
| 事件节拍/议程 | `src/modules/world/domain/agenda.ts` |
| 时钟与节拍 | `src/modules/world/domain/clock.ts`、`src/modules/world/application/advance-world.ts` |
| 记忆 | `src/modules/memory/**`（episode 可承载情绪片段） |
| 消息与聊天 UI | `src/features/phone/apps/messages.tsx` |
| 契约 | `src/contracts/**`（如需 `typingMs`/`recalled` 字段，先定契约再改实现） |

**实现顺序建议**：先做**提示词与情境**（不加字段、不动状态机）→ 再做呈现层（正在输入）→ 最后才考虑契约变更（连发/撤回）。

---

## 6. 明确不要做（避免变成新的屎山）

1. 不要加"心情值/亲密度/活跃度"等状态机；
2. 不要加每日额度、冷却表这类排班机制；
3. 不要为每个角色写死对话脚本；
4. 不要在提示词里继续堆否定句（越长越容易输出成客服腔）；
5. 不要为了"像人"而伪造事实（没说过的承诺、没发生的约会）。

---

## 7. 验收方式（避免凭感觉）

1. **盲测**：真人聊天片段 vs 我们的 NPC 片段混排，人能否分辨；
2. **辨识度**：「这条像不像这个人物说的」1–5 分；
3. **行为指标**：平均消息长度分布、连发比例、不回比例、撤回/正在输入出现频率；
4. **不崩**：不得因新行为导致 `INVALID_AI_OUTPUT` 或消息发送失败上升。
