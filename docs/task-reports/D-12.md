# D-12 便签真实持久化

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已完成并上线验证。

## 问题

便签此前只写浏览器 localStorage，`onSaveNote` 从未接线，界面却提示「便签已保存」。D-11 先把它改成如实说明「仅保存在这台设备」；本项补齐真正的服务端持久化。

## 实现（照邀约 `respondToInvitation` 的命令/回执模式）

|文件|改动|
|---|---|
|[db/migrations/0017_world_notes.sql](../db/migrations/0017_world_notes.sql)|新增 `world_notes` 投影表（id 主键、world_id/owner_id 外键、command_id 唯一、document 有大小约束）；RLS 对 `pl_app` 与 `pl_worker` 分别建策略并最小授权；索引按 world + updated_at。**便签不写进 `worlds.state`**，避免快照随便签增长（与 AUD-09 同向）|
|[src/contracts/notes.ts](../src/contracts/notes.ts)|保存请求（commandId、可选 id、title ≤80、text ≤2000、expectedVersion）与回执（note 含 id/title/text/version/updatedAt）|
|[src/modules/world/domain/notes.ts](../src/modules/world/domain/notes.ts)|`applyNoteEvent`：校验 id/标题/正文/事件自洽，世界版本必须 +1，**每条便签有自己的版本**做乐观并发控制；不存在则创建、存在则按版本更新；上限 200 条|
|[src/modules/world/infrastructure/postgres-world-repository.ts](../src/modules/world/infrastructure/postgres-world-repository.ts)|`saveNote`：同一事务写 command（回执）+ event + 投影 upsert + 世界版本；重复 commandId 返回原回执（幂等），换内容则 `IDEMPOTENCY_CONFLICT`；`hydrate` 增加读取 `world_notes`；`compact` 不再把便签放进快照|
|[src/app/api/v1/worlds/[id]/notes/route.ts](../src/app/api/v1/worlds/[id]/notes/route.ts)|`POST /api/v1/worlds/:id/notes`：鉴权 + 限流；新便签 id 由**服务端分配**；`INVALID_COMMAND` → 422|

|[src/features/phone/world-app-data.ts](../src/features/phone/world-app-data.ts)、[notes.tsx](../src/features/phone/apps/notes.tsx)、[world-phone-app.tsx](../src/features/phone/world-phone-app.tsx)|前端不再自己造便签 id；保存走真实接口，成功后重载手机、失败则如实报失败（不再吞掉远端错误）；`noteSync: 'server'` 时界面才显示「便签已保存」|

- 本地端到端（真实模型 + 真实库）：建世界 → 保存便签 → 刷新仍在 → 更新到版本 2 → 旧版本被 409 拒绝。

## 遗留

- 便签打开/编辑时仍会在本地缓存一份（用于即时反馈与离线草稿），但**服务端是唯一权威**；失败不再被吞掉。
- 本地缓存与服务的双写没有冲突合并策略：同一便签在两台设备同时编辑时，后提交者会收到版本冲突并需要重新载入（不静默覆盖），这是有意选择。
