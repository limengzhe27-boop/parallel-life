# 产品优化总方案（按"影响体验"排序，附部署门槛）

> 编制：dsh-main-20260923 ｜ 基线：`origin/main c7fb4b46`
> 原则：**先修挡住用户的东西**，再补闭环，最后做扩展；每项完成即部署验证。

## 阶段 A · 解锁与可诊断（先做，成本低、立刻可验）

| # | 任务 | 内容 | 验收 |
|---|---|---|---|
| A1 | **保存失败指字段** | 服务端校验错误携带字段路径（如 `actors[1].key`）→ 报错区直接列出"哪个人物/哪个字段/为什么" | 故意写一个超限字段，界面能指出具体位置 |
| A2 | **删除地点** | 补"删除地点"按钮，同时清理引用该地点的 routes（避免悬空引用） | 删除后保存通过；`routes` 无悬空 key |
| A3 | **编导入门引导** | 世界设定区标注"填人话即可，Agent 会整理"；「整理」按钮标注**将消耗一次调用** | 文案可见、按钮语义清晰 |
| A4 | **保存前自检** | 保存前本地跑一次契约校验，列出将失败的字段（与 A1 同一套错误格式） | 不再出现"点了保存才知道错" |

## 阶段 B · 核心闭环（NPC 演绎，必须真实调用验收）

| # | 任务 | 内容 | 验收 |
|---|---|---|---|
| B1 | 失败可诊断 | `INVALID_AI_OUTPUT` 记录**具体校验路径 + 模型原始片段摘要**（不含隐私），可一键查看 | 能从库里直接看出为什么 invalid |
| B2 | 严格 schema + 归一化 | 统一 canonical schema；对常见偏差（缺字段、重复包、类型错）做**确定性归一化** | 同类失败率显著下降 |
| B3 | 有界重试 + 幂等 | 只对可重试错误重试（≤N 次，不进付费循环）；重放不重复执行 | 重复提交不产生两条行动 |
| B4 | 开场多 NPC 演绎 | 围绕开场把多个 NPC 串起来，并**承接玩家协商的新时间** | 真实世界完整跑通一轮"进入→对话→NPC 行动→玩家回复" |
| B5 | 已知失败恢复 | 已 failed 的消息可核对并显式重试；真 unknown 保留核对、不伪装成功 | 与 44-151 一致 |

## 阶段 C · 连续世界与呈现

| # | 任务 | 内容 | 验收 |
|---|---|---|---|
| C1 | 离线变化呈现 | 返回世界时呈现"你不在时发生的事"：新消息、朋友圈、地图变化、时间推进摘要 | 离线 6h 回来能看到真实变化 |
| C2 | 调度覆盖 | 到期领取、并发去重、失败续接；每日一次 + 全局 2 个世界 → 提升覆盖 | 100 个世界在窗口内全部推进 |
| C3 | 预算与成本 | 确定性行动与模型调用预算分离；服务端硬限额 + 告警 | 超限即拒并告警，不产生意外账单 |
| C4 | 全旅程验收 | 真实玩家"进入→聊天→离开→离线变化→返回"手机/PC 双端 | 端到端脚本 + 截图证据 |

## 阶段 D · 治本（持续，穿插进行）

6. 债留痕（重大妥协写 `TODO(任务ID)`）；基线纪律（报告写 sha，验收前 checkout）。

## 部署门槛（每项完成都要过）

1. 工作树内实现 → `npm run check:boundaries` + `npm run typecheck` + 相关测试 + `npm run build`；
2. 迁移先应用到生产库（如有）；
3. 提交并推送 → 等 Vercel READY → 公网实测关键流程；
4. 报告中写明：改动文件、验证证据、线上版本、未完成项。

## 优先级依据

- **A**：直接决定"编导能不能把内容做出来、出错能不能自救"——不修，后面都无法测试；
- **B**：决定"用户聊天是否像样"，是产品命门，但需要真实调用与引擎改动；
- **C**：决定"世界是否活着、离线是否有意义"，属于体验后半段；
- **D**：不直接产生体验，但决定后续速度。
