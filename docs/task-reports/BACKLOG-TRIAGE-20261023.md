## 2. 52 条历史行怎么处理

这 52 条是 2026-10-09 至 10-18 的架构审计、协议设计、旧引擎子任务。它们不是当前产品的 52 个独立功能，且多数已被 `44-137` 统一引擎、`44-161` 恢复链、`44-196` 人感收口覆盖。

处理规则：

1. **不删除编号，不批量改成完成**。历史行保留原状态与报告，作为追溯证据。
2. **不纳入当前活跃清单**。排期、验收、模型预算都不再按这 52 条计算。
3. **只在三种情况下重新打开**：
   - 当前真实用户旅程再次复现同一故障；
   - 某个历史缺口被新任务明确依赖；
   - 负责人能给出真实 PG/浏览器反例。
4. 旧 `44-9~59` 中仍有参考价值的协议结论，已经转入 `44-161` 的恢复/展示/窗口子项；不另建第二套引擎。

这相当于把这 52 条标成“冻结基线”，但不伪造完成。
