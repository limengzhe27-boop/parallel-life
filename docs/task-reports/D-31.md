# D-31 修复：说"帮我创建分支"却打开了已有的人生

负责人 dsh-main-20260923（主登记目录，单人执行并自审）。2026-09-24。状态：已修复并上线（含回归测试）；点击级验证待补。

## 用户报的问题

> 输入"帮我创建分支"，它会打开已有分支，而不会创建新的分支。

## 根因（我上一轮 D-30 的实现缺陷，两处）

1. **顺序错**：`proposal-thread` 的意图处理里，**"已有世界就直接跳去打开"这条捷径排在最前面**，所以只要这个人已经有世界，任何意图（包括"创建"）都会先跳走——"创建"分支的代码根本走不到。
2. **没有去重**：即便走到创建逻辑，它取的总是"第一个方向"；如果那个方向**早就被采用过**，结果还是那段旧人生（或直接被服务端幂等拦下），用户感受同样是"没创建新的"。

## 修复

- **顺序**：`create` 意图**优先处理**，不再被"打开已有分支"的捷径吞掉；只有 `enter`（进入）与无关对话才走"打开已有"。
- **去重**：新增纯函数 `chooseUnbuiltDirection(directions, adopted, preferredIndex)`——用已采用的种子（`ApprovedSeed.directionId`）算出**已采用集合**，跳过它们，优先采用用户当前选中的方向；
  - 若现有方向全都采用过 → 重新推演一批方向再挑；
  - 若仍然没有可用方向 → **打开选择框让用户挑**，而不是静默打开旧人生。
- `recommend`（"有什么分支吗"）也改为**优先展示方向**（而不是跳进已有手机）；`enter`（"进入这个分支"）保持"直接进入已有世界"（零花费）。

## 验证

- `npm run check`：**177 项**单元测试通过。新增回归用例（`tests/branch-intent.test.ts`）：**"创建分支绝不能重新打开已存在的人生"**——d1 已采用时必须选 d2；用户当前选中的未被采用时优先用它；**全部已采用时返回 null（要求调用方询问而不是重开旧人生）**；未采用任何方向时用首选。
- `npm run build` 通过。

## 遗留

- 若用户的世界已经存在且方向都被采用过，"重新推演一批方向"会产生一次模型调用（有既有频率与额度限制）；这条路径的点击级行为待验证。
