# 领导直接体验的默认分支

2026-10-10。用户新增要求：系统默认放几个内容设定好的分支世界，领导无需先与个人 Agent 聊天，就能体验手机中的世界。任务状态以 DEVELOPMENT.md 为准。本文件是待验收方案，不表示三个世界已经生成、上线或通过体验验收。

## 定位与当前事实

首批先准备三个「可直接体验的预设分支」，入口沿用“分支”，不增加底部导航。既能供领导演示，也能让新用户理解产品，再去聊天创建自己的世界。

这不是只有职业名称和第一条问候的模板；也不是大家共用的同一部手机。每条分支应有足够具体、彼此一致的初始内容，玩家进入后，人物通过现有真实 NPC 能力回应并保存后果。准备好的开场与历史明确是虚构剧本内容，不能标成现场 AI 已生成的结果。固定起点不固定玩家未来的选择。

已有内容协议、作者私有设定保存与私有试演可作为基础，但不等于现有系统已经支持公开精选目录与按玩家独立实例化。主表 LIB-02B/LIB-03 的剩余内容仍需完成；不直接把作者的私有试演入口或某个账号的测试世界暴露给领导。

本轮新增要求优先于旧方案中必须先检查或编辑完整起点的设想：默认体验按钮不要求访谈、不展示整页设定表单、不要求逐个人物确认。是否首次实例化、失败恢复、继续旧世界仍需诚实呈现，不能用动画掩盖创建失败。

## 进入方式

1. 分支页展示三个同等大小的体验卡片，与“我的分支”有清楚区分；卡片只显示身份、眼前发生的事及“开始体验”。无需先有真实档案。
2. 第一次进入，建立当前体验者自己的世界，并打开锁屏。只使用该剧本的虚构素材；默认不带入真实档案、朋友照片。
3. 锁屏有值得打开的消息，并有之前不同日期、时间的生活痕迹。点击后进入对应聊天、日程或已有可用页面。
4. 再次点同一体验入口，继续自己的存档；“重新体验”需单独明确确认，不静默覆盖。
5. 退出和切换沿用手机首页的现有入口。体验后可去“聊聊”构思自己的分支，不强制转化。

这些只是供选题讨论的原创虚构示例，不冒称已做好完整剧本，不视为用户已经选定三条，也不规定正式内容团队必须采用。候选可以替换为历史人物、都市关系或其他更合适的题材；正式预设剧本仍由相关人员提供，内容边界和编排规则尚未收到。

实际编写时必须避免只有“有人出事”而没有用户能做的事情。例如霓虹江湖开场不只催用户回复，还要给出可核对的联系人线索、合理的当前处境和可以改变后果的介入机会。地图、现场等仍待开发时，只使用已验证的交互，不靠台词宣布尚未发生的行动成功。

## 每个分支必须准备什么

- **主角处境**：身份、当前地点、世界故事时间、资源和已有承诺；说明眼下能介入什么，不泄露全部未来走向。
- **人物**：建议四至五人；姓名、关系、个人诉求、说话习惯、各自知道的事情及可转述边界。不是四个人同一个性格。
- **聊天历史**：每位可联系人物有合乎关系的少量既往对话，能体现已有生活；开场消息与历史错开时间。不得伪造真实玩家已经作出的关键选择。
- **锁屏**：一到两个重点提醒加其他自然消息。同一个联系人可折叠，重点依赖具体承诺或事件；不让所有人在进入这一分钟统一来信。
- **相册与头像**：少量经许可可使用的原创或合成剧本配图，明确素材来源与用途。禁止复制其他用户私有照片。没有可使用素材时不宣称生成了图片。
- **日程**：过去的有限生活背景与近期可响应的安排，和世界时间、人物消息一致；旧历史不得被当成刚收到的新邀请。
- **便签**：主角的生活背景、记住的承诺与眼下处境。系统安排的事项与玩家私人便签区分。完整自动长期/短期任务仍依赖 NOTES-WORLD-03/04，不能用写死清单冒充完成引擎。
- **首轮体验**：至少一个能通过现有真实能力介入的事件；自由回答后，NPC 保持立场，能看到后果而非只说“你的想法很有趣”。
- **后续方向**：若干可发展问题和不同结果，玩家拒绝开场方案也能继续；不提前强制结局。

地图、移动与现场尚未验收的能力不靠预设内容假装可用。可以准备地点和约定素材，但首批入口要基于实际可工作的应用；相应能力完成后再接入。

## 实现顺序与工作边界

当前 CHAT-SEND-ERROR-01 / CHAT-SEND-RECEIPT-01I 先验证部署，不因新需求扩大该批改动。

随后沿 LIB-03 拆为内容、玩家独立实例化、入口、体验验收四个切片，由唯一集成人登记源码和迁移范围后分工：

1. **内容切片**：先从较有吸引力的候选或内容人员提供的正式材料中确定一个完整样例及初始手机清单；不沿用已被否定的三个日常题材。内容负责人提供正式剧本时可替换内容，不推翻运行层。
2. **实例化切片**：固定内容版本映射到当前玩家独立人物、消息、日程与素材；使用现有世界事务和权限体系，不生成共享演示账号，不另建假聊天实现。初始状态必须经运行时校验。
3. **入口切片**：分支页直接开始/继续体验，保留自己的已有世界与三导航；手机、电脑窄幅均验收创建等待、失败恢复和重开。
4. **验收切片**：先验证一个分支的完整闭环，再扩至三个。每个都完成内容一致性和真实多轮 NPC 对话验收后部署，不因列表有三个标题就宣称三个可体验。

实际带费用的模型或生图验收需确认具体预算与范围；之前其他任务的限量测试授权不能挪用。本方案阶段不创建生产世界，不调用模型，不改变任何玩家存档。

## 验收标准

- 新访客没有生日、没有访谈也能从分支入口进入自己的手机；已登录老用户继续原世界不受影响。
- 两个账号体验同一剧本不共享消息、记忆、照片权限和后果；同一开始命令重试只创建一个世界。
- 内容版本更新不改变已开始的玩家世界；初始状态有可回溯的剧本版本与素材来源。
- 进入后每个可联系角色都有合理既往关系或对话；消息、日程、锁屏与故事时间相符，不统一“刚刚”。
- 玩家不同回答会收到符合人物立场的真实回应，并保存同一世界的结果；刷新后可继续。未实现的任务/现场/地图不作为验收成功项。
- 重点事件不泄露角色秘密或结局；只展示玩家当下可以知道的事。预设不等于把导演所有幕后内容展示给玩家。
- 首批三条内容均逐条验收；模型不可用时如实报错，不能返回写死的成功回复。
