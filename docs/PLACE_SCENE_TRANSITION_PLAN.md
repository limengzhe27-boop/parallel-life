## 1. 用户最新确认与保留讨论

已经明确：

- 到达地点后，应当有环境、实际在场人物、可参与事情、用户行动及可承接的反馈，不仅是回到微信继续聊天。
- 地点、联系人、日程和现场是一套有因果的世界；导演身份离开片场去医院，可能影响拍摄安排，制片人也可能因此联系玩家。
- 移动过程可以略过，用简短过渡和“半小时后，到达医院”这类明确提示表达旅程。但半小时仅为例子，不是统一耗时。
- 同一联系人的未读消息折叠；不同联系人、不同群分开；原始消息日期和时间保留。
- 加载、提交、开机、进入现场及回应过渡需要整体完善，不能只是零散等待文字。
- 继续未完任务，并分发给其他 Agent 实现和验收。

尚未确定：

- 地图的具体形式、是否显示几何距离、交通方式与耗时如何确定。
- 实时与跳过旅行时间如何共同工作，长时间行动是否采用同一规则。
- 常规地图是否需要独立App；所有地点的自由进入与特殊地点的访问资格。

## 2. 五个概念及其联系

|概念|含义|限制|
|地点|稳定的世界空间，例如片场、医院|名称和模型文字不等于可定位的唯一地点ID|
|移动|离开、途中、到达的一次用户行动|不能因查看地图或打字表达计划而自动执行|
|现场|具体时地的可参与事件，例如试拍、探视|同一地点可有多场事件，到某地点不等于加入全部事件|
|人物状态|角色实际位置、安排、动机与已获知内容|人物位置不自动成为玩家或其他NPC已知信息|
|手机页面|消息、日历、相册等呈现入口|切换页面不改变身体位置；返回手机不等于离场|

地图呈现已知地点、相关约定/人物与可选行动。现场呈现当地发生的事情。二者共同读取世界事实，不各自编故事。

## 3. 到达后的最低完整体验

不要求每次到达都自动发生大事件，但应能回答：

1. **我到了哪里，是什么时候？** 使用已经提交的位置与故事时间。
2. **眼前可观察到什么？** 门是否开着、有人等候、活动是否已经开始等；不把隐藏动机写成环境事实。
3. **谁确实在这里？** 实际参与和出现依据；邀请名单或联系人列表不等于现场名单。
4. **我可以做什么？** 自由文字表达观察、询问、尝试或对话；必要时提供少量有依据的操作入口，不强迫固定选项。
5. **刚才的行动造成了什么？** 尝试与结果分开；结果产生记录，并能影响事项、人物、消息和后续安排。

例如医院大厅暂无探视现场时，可展示开放的大厅和来自朋友的已知安排，玩家可询问病房、联系朋友、等待、离开。不能为了每一处有内容就捏造疾病、医嘱或角色到场。

现场既有文本项继续区分：环境/时间地点、旁白动作、人物对白、用户输入/尝试、裁定结果、真实素材。不要把整屏改为聊天气泡，也不要让旁白替用户作决定。

## 4. 导演从片场去医院的因果样例

以下仅为业务样例，不是预设剧本或实现事实：

- 玩家已在片场，14:30有试拍约定；朋友发来医院地址。
- 玩家选择前往，服务端校验当前状态、目的地与耗时依据。看地点详情和“我可能去医院”不算出发。
- 出发有记录；行程结束推进实际故事时间并保存到达状态，界面用短过渡展示已确认旅程。
- 片场的工作人员若观察到离开，可能告知制片人；制片人也可能在试拍需要玩家时发现不在。没有依据不得直接知道医院地址。
- 玩家到达医院后，看到当地已成立的环境与安排，可以进入探视、联系朋友或等候。不存在有效探视事件时，不自动虚构“已完成探视”。
- 对拍摄的影响需要依据约定、责任和人物行动裁定，可能延期、委托、继续等；不是每次移动都罚玩家，也不能直接奖励不存在的职业成就。
- 玩家之后回微信处理片场消息，身体仍在医院，除非另有明确移动。

路线行程、人物知情与任务变化均需要有来源；模型可以提出可能反应，运行时决定合法变更和保存结果。

## 5. 过渡不是等待结果的伪装

需要区分两条时间：现实请求等了多久，世界中实际经过了多久。现实网络请求等待2秒不代表故事过去30分钟；动画持续1秒也不能自己推进故事时间。

|过程|真实状态来源|呈现建议|失败或中断|
|创建人生|持久任务实际阶段|简短阶段文案，已有草案保留；准备完成后进入手机|保留已完成阶段与任务ID，允许查看/明确恢复，不承诺“马上好”|
|打开既有人生|世界与手机投影读取|壁纸/布局占位或克制淡入，读取成功后锁屏|保留所选分支，错误就地可重读，不重建世界|
|打开现场|真实现场记录与回应任务|先显示已有时间地点、可读记录，再显示正在准备现场回应|明确读取失败与现场回应失败；不凭动画把状态设为在场|
|提交行动|命令回执/持久任务|本人尝试立即可见，原记录可读；等待结果的轻提示|重复点击不重复提交；unknown仅核对，付费重试需明确操作|
|收到结果|真实保存的结果项|结果、对白与事项变化分别显示，可轻入场|拒绝或失败保留输入，不能显示为已完成行动|
|旅行（后续）|同一世界实际旅行回执与位置/时间|出发→短过渡→显示经过多久及到达；细节来自真实提交|失败留在最后已知状态；刷新恢复同一旅程，不二次推进时间|
|普通页面切换|已有已读数据|短滑动/淡入，尊重减少动态效果|不遮掉仍可读的内容，不制造额外故事时长|

禁止用假的逐步百分比、假角色“正在做某事”、假照片缩略图或“行动成功”遮蔽未完成请求。慢任务不增加永久盖住全屏的动画。短屏、软键盘、读屏、减少动态效果和返回恢复都是验收范围。

## 6. 现场独立入口：本轮可以立即推进

SCENE-03复用已上线现场记录和日程资格，不先等待完整地图：

- 正在参与：进入同一个当前现场，不重复创建。
- 可参与的约定：只展示真实符合条件的项目，保留原日期，不把陈旧约定改成今天；陈旧活动是否仍有效不能自动假定。
- 过去的现场：回看真实发生的记录与结果，不重新执行历史行动。
- 返回手机只切换视图；明确离场改变参与状态，保留历史。

本轮不宣称可任选医院/片场自由移动；现场入口不能冒充全局地图或位置引擎。

## 7. 联动通知后续规则

当前联合版已接私聊、群聊以及有效待回复日历邀请。后续可扩展真实约定提醒/变更、实际完成的相册更新、与活动关联的现场变化，但本次不挤入尚未验收的任务范围。

同一事件的微信/日历/现场不要占满锁屏；以人物消息和实际需要处理的约定为主要线索。不存在新事件可以安静。隐私场景、角色私下动机和未授权位置不直接出现在锁屏或地图。
