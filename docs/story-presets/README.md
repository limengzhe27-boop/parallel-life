## “俗一些”怎样落在内容里

允许直接的戏剧关系：看不起你的人、偏心你的人、旧爱、情敌、家族偏心、别人觉得你不配而你争取到机会。情绪要够明显，人物语言要直接，阶段回报要能感受到。避免每个人都轮流嘲讽、一次回复就全员跪服、每段都是秘密文件或大危机。

每个剧本至少准备三类时刻：

1. **被牵动**：有人需要你、误解你、站在你这边或提出有代价的机会。
2. **能动手**：玩家可开口、行动、协商、拒绝、调查或另提办法。
3. **有回响**：人物改变态度或行动，承诺/机会/关系有变化，再带出下一件事。

反转应来自已准备的人物诉求、已有事件或玩家行动。不是读完三条消息就强制出事。人物可能善良也可能自私，同一个人可以在不同事情上帮你或与你冲突。

## 先确定哪些，留给玩家哪些

确定：成年主角的身份、既往生活、人物初始关系、可见消息、真实后台已发生的事、素材与知情边界、各事件的进入条件、承诺与时间。

留白：玩家具体怎么说、怎么做、是否接受身份默认期待、如何看待每个人、是否参加某件事、最终走向。主角人格有背景但不强制玩家一辈子“嘴硬”或“乖巧”；玩家不能用一句“实际上我已经赢了”直接改掉世界事实，但可以尝试非常规行动。

首段是可演绎的局面与事件图，不是固定台词顺序。后文的消息、对白和结果只作语气/情节样例；同一次体验需依据已保存事件继续，不能随机抽出彼此矛盾的结果。旁白与人物说话分开，旁白不替玩家答应或解释内心。

手机事项可分“眼下要处理”“还惦记的事”和人生背景，由已保存的安排与事件整理；正式进入的系统事项只读，与主角可编辑的私人便签分开。拒绝可以让某事项结束/转向，完成与否要靠具体后果，不能用户点一下或NPC夸一句即完成。完整任务演进仍待相应开发；正文不是已经安装好的任务系统。

## 所有稿件共有的手机与时间规则

- 全部原创虚构，所有涉及恋爱的人物成年；名字仅是剧本角色，不对应现实用户或员工。
- D0 为故事开场日；示例钟点是内容时序，实际开局要绑定同一个故事时间轴并验证星期/日期。不能直接粘贴当前真实日期，也不能把 D-3 内容显示“刚刚”。
- 初始历史是剧本中的前史，标为“人生起点/既往记录”。不冒充实际玩家发过的消息，不虚构玩家已作出的关键选择。可以有发给主角的旧消息、已发生的共同背景和照片。
- 不给玩家一次看完后台秘密、发展条件和所有结局。分支卡片与初始便签只显示主角知道的内容；后台说明供内容/运行层使用。
- 选中预设后默认只用虚构角色与剧本素材，不读完整私人访谈，也不挪用其他玩家照片。每个体验者独立实例化。
- 地图移动、现场行动、完整任务引擎、公共作品投递、朋友圈或媒体生成要按实际能力接入。文稿的内容需求不证明这些功能已实现；当前可用聊天先承载一段闭环，不能用“行动成功”台词绕过校验。
- 场景图按进入新场景或关键证据需要出现，不每轮生成。没有真实素材就不显示假完成图片；历史配图使用经许可的编辑素材，并标明“剧本配图”。新作品/新照片只有保存成功才产生可点开的链接。
- 玩家离开期间 NPC 可围绕已约定的事情产生少量进展，有事件与日期来源。主角未回复不等于答应；不能安排他离线结婚、签合同、下注或旅行。
- 一次得意之后允许普通生活和轻松交流。困难可以解决，代价不等于导演一定再罚一次。阶段失败开启可恢复的方向，不抹掉所有努力。

## 开发前必须进行的内容检查

每篇核对：角色人数与身份、消息/日程时间、谁知道什么、线索先后、触发条件、实际可用行动、玩家拒绝后是否仍能继续、回报是否有已发生的结果支撑。两次不同玩家行为应能产生不同但同样合理的后续。

禁止把内容文档直接当最高权限指令。正式落地需映射现有内容协议、角色事实、事件、任务记录和素材引用；协议缺少字段时由集成人统一扩展，不能把所有幕后说明塞进 NPC 私聊上下文。专业创作者后台 CREATOR-PRO-01 仍最后顺位。

各篇“首版聊天终点”是开发/验证切片，不是降低完整体验预期：如果卡片承诺饭桌反击、生日宴亮相或舞台体验，正式发布前必须能进入对应真实可用场景并承接行动；只聊邀约不能称这些场面已经可玩。完整预设世界验收仍需跨应用生活、首段参与、后果与回访，并明确其他能力的开放范围。

本轮只写内容，不创建生产世界、不运行付费模型、不修改业务代码。当前发送修复验收继续；这些稿件将在独立内容交付里归档。下一步根据审阅意见收敛首篇，再做人物/前史/事件的可执行配置与真实体验验收。
