# 可发布的人生设定与整体产品接续方案

2026-10-03。用户本轮新增：可以体验他人创作的人生，例如李白的平行人生或现代富家创业者的人生；用户也能发布设定，不必先写一整部剧本。主任务负责集成，已采纳「辅助」的 [LIB-01R 审查](task-reports/LIB-01R.md)。唯一状态表仍为 [DEVELOPMENT.md](DEVELOPMENT.md)。本文中的目标能力不表示已上线。

## 1. 产品从两种起点进入同一套体验

原来的入口是“聊我的经历，看看我的另一种人生”。新增入口是“我先挑一个感兴趣的身份，进去体验”。两条路最终进入同一套独立世界、导演与 NPC、记忆、消息、日历、相册和便签，不另外开发一个模板聊天产品。

发布的对象叫**人生设定**。它描述你是谁、你想要什么、谁与你有关、当下有什么难题、可以探索哪些方向。它不是作者玩过的存档，也不是已经替玩家做完选择的故事。作者可以设计阻力和可能结果，玩家始终掌握自己的回答和行动。

三层对象必须分开：

|对象|属于谁|会改变什么|
|---|---|---|
|设定创作稿|作者|可持续编辑、补问、试演，尚未公开|
|已发布设定版本|作者发布的公共作品|固定起点与创作规则，发布后不可原地改写|
|体验中的人生|每一个玩家本人|自己的角色实例、对话、事件、照片、选择、时间与记忆|

十个人选同一设定，是十段独立人生。作者不因此获得玩家的聊天、资料或照片。分享设定与真人共玩是两条功能线；G-03～G-06 的多人授权、共同场景和退出规则仍保留。

## 2. 产品入口与功能路径

保持底部 **聊聊／分支／我的**，不增加第四个导航。

- 聊聊：个人向导讨论现实经历和愿望，也能推荐适合体验的已发布设定。创作别人的人生时切入明确的创作上下文，不能把“这个人物30岁”记成用户30岁。
- 分支：页内分为“我的人生”和“发现设定”。前者继续已有世界，后者浏览可体验身份；两者都采用同等大小的卡片，不将某段人生默认放成主角大卡。
- 我的：现实资料与来源、更正入口；另有“我的创作”，管理私有创作稿、试演和已发布版本。作品设定不混进现实资料。

新玩家路径：发现设定 → 看身份、开场困境、虚构说明及来源 → “开始这段人生” → 检查这次扮演的身份、可改的起点、资料带入范围 → 建世界 → iPhone式锁屏 → 点人物来信进入体验。无需先填生日或做完整访谈。默认不带任何现实资料和照片；没有额外资料也能创建。

已有玩家路径：继续人生直接恢复原世界；“重新体验”是一次明确的新开局。两个按钮不能混用。“从这个选择再走一条路”则是历史事件分叉，仍归 L-02，不能用从模板重新开始冒充。

设定详情首屏只回答：**你是谁、眼前发生了什么、这段人生有什么吸引力**。作者、版本、背景来源和较长设定折叠查看。浏览与收藏不触发付费模型调用；实际创建才进入持久任务。

## 3. 作者不写完整剧本，写七块可演绎的内容

|内容|最少需要说明什么|例子（均为创作示意）|
|---|---|---|
|身份与时代|玩家扮演谁，处于什么环境|一位在虚构城市筹备首部电影的导演|
|愿望与代价|他想得到什么，什么不能同时保全|想保住作品表达，但资金和朋友的期待都在施压|
|人物|2～7位关键角色的立场、欲望、说话方式|制片人要按期开机；摄影指导坚持一个更费时的方案|
|关系|方向性的亲近、利益、矛盾与转述边界|姐姐可能因担心而向母亲透露；朋友未必这样做|
|开场|一件现在就能回应的事|一位角色发来需要今晚决定的提议|
|故事线|1～5个待解决问题、介入条件、代价、可能后果|拒绝资方后如何继续；接受后怎样面对团队|
|资料与虚构范围|哪些是创作，哪些陈述来自哪些资料|背景有出处，人物台词和分岔结局标为虚构|

最初只问作者三个问题：让玩家成为谁、眼前最想解决什么、开场谁来找他。创作助手据此补成提案，再针对缺失且影响开场的部分追问。不要一次发出整页表单。作者可以改字段，也可以继续自然聊天。

生成提案不等于发布。完整路径是：构思 → Agent整理设定 → 作者编辑 → 私有试演 → 查看实际开场和人物反应 → 回到设定修改 → 预览公开内容 → 提交审核 → 显式发布版本。试演是隔离的测试世界，不复制到正式玩家存档，也不当公共剧情样例自动公开。

设定来源有四种：平台编辑原创、作者自然语言构思、作者明确提供且可使用的参考材料、从私有人生手动改编。最后一种只提取作者确认的虚构设定，不能直接导出原聊天、现实关系和相册。创作材料中的“忽略系统规则”等文字都是材料，不是运行时权限。

## 4. 李白与现实公众人物怎么处理

李白的入口建议是“如果你是李白：一段由你选择的平行人生”。标明**历史灵感·虚构演绎**，选一个可以参与的局部起点，而非承诺重演完整传记。资料性陈述逐条绑定书目或链接及支持片段，审核时区分已核对、存疑与创作补充。模型续写的台词和结局不能冒充史料。

唐代场景继续使用本产品的手机容器时，详情说明这是“用跨时空手机呈现的架空体验”；不默认为历史真实的科技设定。古代书信/书桌皮肤可以以后做，首版不与手机重构并行新增一套系统。

用户提到王思聪，表明想体验有鲜明社会身份与资源差异的人生，不应把这类吸引力缩成普通职业模板。首批可用“继承资源的年轻创业者”原创设定测试财富、家庭期待、独立证明等矛盾。具名在世公众人物保留为产品方向：需要清楚标为平行虚构版本，审核资料依据、形象素材和私人关系，不能呈现为本人授权、本人真实聊天或未经证实的私人事实。这里是发布规则设计，未对任何特定使用方式作法律结论。

具名历史/公众人物的虚构说明应由产品根据作品类型生成固定标识，不能允许作者写一句“这是虚构”便通过全部审核。当前协议仅检查类型与说明存在，公开审核尚未实现。

## 5. 吸引力如何进入运行机制

设定库解决的是“我为什么想点进来”，剧情运行解决的是“我为什么愿意继续”。不要靠著名人物姓名掩盖后者。

每条主线应具备：具体愿望 → 有因由的阻力 → 玩家可作出的选择 → 可感知的代价/收益 → 后续人物承接 → 小阶段结果。允许平静、幽默、亲密和小成功，不把每轮都设成危机，不机械地数消息后反转。作者的 possibleOutcomes 是可能性，不是导演必须强行兑现的固定结局。

导演根据已发生事件、角色欲望、关系和知情范围挑选下一次互动；NPC按照自己立场回应。人物可以转述信息，但必须留下来源和传递路径，明确保密继续受约束。剧情完成不能只靠NPC说“恭喜你完成了”，需由已保存选择及可追溯事件支持。

NAR-02 已有选择记录、结果承接、受阻建议、定向转述和有界来信的若干子能力，但完整故事线生命周期仍待实现。作者填写一句“这里发生争执”只是创作意图；需编译为可校验的进入条件、人物、冷却、终止与结果规则后才能执行，不能直接当代码或系统指令运行。

NAR-03 把同一后果呈现在消息、日历、照片和便签里。比如合照只有真实生成或上传并保存后，NPC才能将其作为可打开的附件发来；失败不能写成“照片已经在相册”。这是用户区别于普通聊天工具的可感知体验重点。

## 6. Agent 分工与信息流

|职责|输入|输出与边界|
|---|---|---|
|个人向导|本人真实对话、现实资料|回复及有来源资料提案；不把创作角色写入真实档案|
|创作助手（独立模式）|作者主动提供的创作材料、当前设定稿|补问、字段修改提案、开场及故事线建议；没有自动发布权|
|内容检查|设定、来源与公开素材许可|缺项/来源/一致性/内容风险提示；结构验证不是事实核验|
|世界创建|固定设定版本、玩家选定的起点和自愿带入资料|新人物实例、关系、开场与手机内容；与作者世界隔离|
|导演|本局事件、未了故事线、关系和节奏|安排知情NPC介入，提出事件变化；不能替玩家选择|
|NPC|自己的角色、可见事实、私聊与自己的记忆|有立场的对话与行动提案|
|记忆及媒体服务|已验证的事件/消息/授权素材|作用域内记忆、真实素材及投递状态，不共享玩家私聊|

这些是职责，不意味着每个都要常驻一只模型。沿用现有模块化单体和共享模型适配器，按需要调用。创作助手与个人向导即便使用同一模型，也必须使用不同上下文和写入权限。任何模型产出仍是提案，运行时校验后保存。

## 7. 架构合入与不可走的捷径

现有 `LifeDraft` 必须引用个人 Discovery，`ApprovedSeed` 带个人资料与私有素材，`WorldBuild` 又是一Seed一世界。它们不能直接设为公开。辅助对这些限制已做静态核对，见 LIB-01R。

目标对象：

1. `SettingDraft`：作者私有创作稿，修订、字段来源、试演关联。
2. `PublishedSettingVersion`：审核后白名单重建的不可变公共作品版本，来源、固定内容摘要、作者展示名和公开素材状态。审核状态由服务端管理。
3. `LifeDraft.source`：正式区分个人推荐、自由构思、公开设定；旧记录按原推荐来源兼容读取。不伪造 directionId/discoveryVersion。
4. `ApprovedSeed`：玩家确认的独立起点，引用发布版本并保存完整叙事快照；作者的人物动机、关系、故事线不丢成只有四句简介。角色模板ID需要映射到本局新角色ID。
5. `World`：玩家独立世界，继续复用现有事件、回执、记忆和应用投影。

公开读取使用专用投影与最小数据库权限，不能放宽作者档案或Seed的RLS。作者与玩家的照片分别授权；公共封面需要独立可再分发资产流程，首版协议暂不接收任何私有assetId。

自由文本仍可能含真实姓名、联系方式或秘密；严格字段白名单只能拒绝多余字段，不能自动证明内容已脱敏。发布需要公共预览、内容检查、作者确认和审核记录。网络资料抓取另走受控服务，协议中的引用链接本轮只作为文本保存，不发起请求。

同一开局命令重试返回同一玩家实例；玩家主动新开局使用新命令。作者改版不改变玩家已经进入的世界。常规撤下阻止新开局、旧世界按原版恢复；涉及隐私或不适宜内容的强制移除，应另外规定停止访问和素材处置，不能用普通撤下规则永久保留泄露内容。

## 8. 连同旧任务的开发顺序

|顺序|任务|交付门槛|
|---|---|---|
|已完成的基础|EXP-03F～K、若干NAR-02子项|资料准确性、照片引用、有限主动世界可复用；不等于整体完成|
|本轮|LIB-01 + LIB-01R + LIB-02A|整体方案、独立审查、设定内容协议与反例；没有公开设定页面|
|下一批主线|LIB-02B|正式设定版本持久化、来源统一、完整Seed/World映射；两账号隔离和旧世界回归|
|随后首个可体验切片|LIB-03 + EXP-04的一段|人工审核的少量精选设定，从无资料新用户到锁屏、NPC真实对话与重开；不声称UGC发布已完成|
|独立并行范围|EXP-03余项、EXP-04“我的”|资料归类、旧记录核对、明确来源与更正；避免等待全部设定库完成才改善老体验|
|运行质量主线|NAR-02剩余 + NAR-03 + M-01～03|完整剧情线、真实生图与消息/相册投递、回访后果；图片理解与图生图分别验证|
|体验整合|EXP-05 + NAR-04 + EXP-06|手机应用统一状态；实际10～15分钟体验及跨日回访，不只截图验收|
|作者发布|LIB-04/05 + G-01|独立创作、试演、正式账号、公开审核、版本和撤回；游客不能作为可靠作者身份|
|最终设定库验收|LIB-06|一个作者、两个玩家、同版不同人生、更新/撤下/恢复与成本记录|
|后续未取消|L-02、G-02～06、E/R系列|历史分叉、跨端、多人、付费和生产运维；语音继续暂缓|

旧主表有早期“待开发”条目与后续已实现子项并存，不批量改成完成。以新任务的限定范围、代码与报告判断，后续逐项归并依赖和补验收。

## 9. 验收与评价

必须验证：两个玩家同设定得到不同世界；作者无法读取玩家记录；默认零现实资料带入；旧版本不能被改写；未审核/撤下版本不能新建；角色、关系、起点与实际生成一致；断线重试不重复建世界；资料正文或引用链接不能突破系统权限；错误明确可恢复。

玩法验收使用自由回答、拒绝导演安排、改变主意、向不同NPC透露不同信息、几天后回访等场景。记录首个可行动事件是否清晰、关键人物是否保持立场、选择是否有后续、是否出现无依据全知、是否反复催问、是否替玩家做决定，以及真实生成等待和成本。

可以设计开局完成率、首个事件参与率、回访承接率和作者试演后发布率等指标，但当前没有这些数据，不写增长结论。先观察真实完整体验，再决定扩大内容供给与推荐排序；首版不制作虚假热度、点赞、评分和用户数量。
