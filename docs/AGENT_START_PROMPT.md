# 给其他开发 Agent 的通用启动提示词

> 最新改版：全流程都在手机视口中，PC 双栏与宽屏推荐已被否定。继续 H-01 的 Agent 请使用 [手机改版专用提示词](PHONE_FIRST_REDESIGN.md#6-给辅助任务的接续提示词)，本轮限定 U-06，不按旧规则自由领取 H-03 等任务。

将下面正文发给已经打开本项目或其独立工作树的 Agent。可以在正文前补“角色：界面/服务端/AI媒体/验收”和“任务 ID：P-04”等；未填时按任务表选择。只有一个 Agent 时可明确写“单人执行，兼任集成人”。同时运行多个 Agent 时，只指定一个集成人。

本文是启动文本，不代表已创建或派发任务。项目是否已完成准备，以主任务表为准。

---

你现在参与“如果 / Parallel Life”项目开发。请在现有架构下实际完成一项明确任务，不要重新设计整个项目，也不要只输出规划。

先读根目录 AGENTS.md、docs/PROJECT_BRIEF.md、docs/DEVELOPMENT.md、docs/ARCHITECTURE_REVIEW.md，再按任务阅读 PRODUCT.md、docs/ARCHITECTURE.md 和 DESIGN.md。开发进度以主登记目录的 docs/DEVELOPMENT.md 为准，独立工作树里的旧副本不用于抢领任务。

本机主登记目录是 /Users/limengzhe/Desktop/projects/demo/人生剧本。若该路径不存在，先确认实际主登记目录，不要自行创建一份副本冒充主表。

产品从用户真实访谈生成个人档案与平行人生，再通过虚拟手机体验。故事不能写死；真实资料与虚构世界隔离；AI 提案经程序校验再保存；同一事件要在消息、日历、相册等应用中保持一致。模型失败不能切换假回复冒充成功。先核对主表和实际实现边界；首阶段访谈已经接入真实 AI 和数据库，不能据此认为后续完整手机、世界或多人功能也已完成。

请按以下流程执行：

1. 建立唯一 Agent ID，检查我是否指定角色和任务。如果指定了任务，核对依赖和领取状态；否则选一项自己角色范围内、依赖已完成且未被占用的任务。已有集成人时不要自行接管其角色。
2. 按 DEVELOPMENT.md 的登记短锁流程，在同一主任务表将任务改为“进行中”，登记自己的身份、工作目录、基线、具体修改文件和独占资源。重新读回确认成功后才写业务代码。抢锁失败、任务已有人做或文件范围冲突时，不强行领取。
3. 使用独立工作树开发并遵守文件归属。公共接口、依赖配置、数据库迁移和合并由集成人协调；不要覆盖其他 Agent 的改动。未完成并行准备时不在同目录抢写代码。
4. 按该任务的完成标准实现、测试和恢复路径。每完成子步骤、遇到阻塞或准备结束当前轮次时，更新 docs/task-reports/任务ID.md 中的已完成内容、检查、未完成项和下一步，并同步主表中的简短进展。
5. 开发交付后先标“待验收”。完成集成与规定验证后，才由集成人标“已完成”；单人模式允许自己验收，但必须记录证据。别把界面夹具、内存测试和本地构建说成真实模型、数据库或线上验收。
6. 若有明确阻塞，登记原因和恢复条件，继续能独立推进的授权工作。无可领取任务时报告具体前置项，不绕过依赖、不重复做别人已领取的任务。普通实现选择自行处理，不反复询问已明确的需求。

密钥仅使用服务端环境配置，不复制进代码、前端、日志或报告。不默认使用“探索原型”的用户数据库或生产部署。

结束时说明任务 ID、修改内容、实际验证结果、主表状态和下一步。现在先完成阅读和领取，再开始开发。
