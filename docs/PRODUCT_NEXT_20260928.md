# 下一轮产品优化建议 · 2026-09-28

这是基于当前代码和手机体验的产品判断，不是已上线能力或经过用户实验验证的结论。任务状态仍以 DEVELOPMENT.md 为准。语音按用户要求暂缓。

## 优先目标

让用户进入后很快产生三个感受：这是另一种“我”；这里有人在等我的回应；我说的话真的改变了后续生活。先把这条体验做连贯，再增加应用和 Agent 数量。

## P0：可相信的手机

保存、已读、图片状态、邀约和导演设置都要与真实记录一致。未完成不显示成功；失败能保留输入；刷新不能丢掉已确认内容。PHONE-02 先修便签与导演刷新，其余待逐项验收。

图片请求仍需完整展示等待、生成、失败、结果待确认与成功，关联到提出请求的消息。当前相册只展示已入册照片，不能据此宣称生成全过程可见。不要自动重付结果不明的请求。

## P1：第一次开机就有一件想参与的事

分支卡只留身份、一句具体的生活切片和真实场景封面；所有分支同层级。没有生成封面就明确使用意境插画，不拿素材冒充本人。

进入锁屏后突出一个真实待回应事件。例如摄影师人生收到“展览明天布展，你愿意把哪一组放在入口？”而不是所有人物同时寒暄。例子是生成质量标准，不写成所有人的固定剧本。用户可自由输入，也可选择少量起手回应。人物应有自己的目标与态度，不能每次都讨好用户或强行提问。

验收：首次用户能够说清“我是谁、谁在找我、现在能做什么”；记录到第一次有意义回复的耗时、退出位置与主观困惑，不先编造转化率目标。

## P1：一次选择，在手机里留下可见后果

对话中的承诺成为待确认日程；完成的事件形成便签或相册回忆；角色下次记得用户的具体选择。跨应用使用同一事件来源，避免相册、日历各自编出不同故事。

优先做一条完整例子：收到邀请 → 自由讨论 → 确认约定 → 日历出现 → 后续对话承接 → 有真实生成照片时进入相册。不靠增加静态应用图标制造丰富感。

验收：刷新和再次进入仍能找到选择及结果；角色不知道未被告知的私人信息；一个事件不会重复生成多个互相矛盾的结果。

## P1：回来时能接上

锁屏只呈现真实未读。回到对话时用一句自然话承接上次尚未了结的事，不重新介绍人物。可按需查看简短“上次到这里”，不弹长摘要抢走聊天。

导演根据未了结的关系和事件决定谁出场，给用户留回应空间。回来不等于被一堆通知轰炸；暂离不会无授权制造关键承诺。

## P2：分支来自真正的选择

在重要选择后提供“另一种走法”。明确从哪个时刻分出、改变哪个选择，保留原人生。先展示差异，再由用户创建；不把重置整个世界叫作分支，也不为了增加数量自动复制人生。

## P2：个人化的画面与可调体验

在明确带入授权下，让同一人物在不同身份场景保持视觉连贯。先验收少量高质量身份照和事件照，再扩大数量。用户可调故事基调、关系距离和不想出现的主题；导演界面用人物姓名和结果说明，不暴露内部编号或技术术语。

## 开发顺序

真实存储与图片反馈 → 首次开机事件 → 一次选择的跨应用结果 → 回访承接 → 从选择处再分支 → 更丰富的画面和语音。保留多人、时间与多人生长期需求，不将其误标为已完成。
