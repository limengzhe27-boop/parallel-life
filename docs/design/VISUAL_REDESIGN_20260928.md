# 如果 · 视觉改版提案

2026-09-28 · VIS-01 · 用户已批准；本批实施外层三页，世界手机与人物场景素材仍为后续范围。

参考：用户六联屏与 https://parallel-phone-v10.frankfanyiming.chatgpt.site/#intro 。已实际打开入口、分支、手机主页、消息、相册和日历；参考网页自标 V12 预制剧情 Demo。截图中的完整素材效果与运行原型并不完全相同：原型部分联系人仍为文字头像，相册当前只有一张初始照片，不能把截图中的丰富程度当作已实现的数据能力。

## 1. Visual Theme & Atmosphere

主方向：深海蓝外层、人物场景照片、短句、克制的蓝色高光；进入世界后为浅色 iPhone 应用。吸引力来自“另一个我正在怎样生活”，不是更多装饰或更多说明。

沿用已确认的信息架构：聊聊 / 分支 / 我的；直接进入 Agent 聊天，不恢复姓名生日必填入口。分支同等大小；PC 仍是居中手机视口，不照搬参考站的两侧原型导航和说明栏。

## 3. Typography Rules

沿用项目中文字体和系统回退，避免引入阻塞字体请求。少量情绪标题用宋体或中文衬线，正文、导航、状态保持清楚的无衬线。

|位置|规格|
|---|---|
|产品顶栏|22–24px，单行|
|空态引导|26–28px，最多两行|
|分支标题|20–22px，最多两行，完整名称在详情可见|
|聊天正文|16px，1.75 行高|
|照片说明|14–15px|
|导航、辅助状态|12–13px|

文案改写：

- 长篇欢迎说明 → “有没有一条路，你一直想试试？”
- 五个长句提示按钮 → “换一种职业”“去另一座城”“重选一次”。点击只填入草稿，不自动发送。
- “肖像底模已就绪” → “你的照片”。
- “图生图生成开篇角色写真” → “让另一段人生，也有你的模样”。生成状态与必要授权就近展示，不承诺尚未完成的图片。
- “人生提案” → “还可以这样生活”；来源依据保留在详情。
- 未准备好的分支 → “正在准备 / 暂未完成”，不能统一显示“打开手机”。

生日仍可聊天提供，但不声称能据此可靠判断性格。

## 4. Component Stylings

### 逐屏构成

|页面|改版后的构成|保留的真实操作|
|---|---|---|
|聊聊|一个顶栏；空态一句问候与三个简短话题；已有对话时只显示消息流；输入框与照片按钮吸底|发送、流式回复、上传、失败重试、草稿|
|分支|等高横向场景大卡；标题、一个来自真实分支的短摘要、一个状态；多分支纵向滚动|查看详情、进入已创建世界、继续准备、明确重试|
|我的|主肖像大卡与姓名；照片小胶卷；兴趣愿望、重要的人、经历折叠展示|上传、更换、编辑、纠正、来源查看|
|锁屏|对应世界照片、大时间、真实消息通知、约定提醒；点击通知直达对应人|解锁、消息跳转、真实约定跳转|
|消息|浅底，单层人物标题与关系；44px 头像；左右气泡；图片与邀约卡进入消息流|真实回复、待发送/失败、索图、邀约|
|相册|有照片时用一张回忆大图+三列照片+人物筛选；无照片时展示可操作上传入口|上传、打开大图、分享给角色、查看生成状态|
|日历|清晰月历，日期下显示邀请与约定；地点、人物、时间优先|接受、婉拒、调整；只在已接通时提供赴约动作|
|便签/人物/导演|沿用对应系统风格，主次分明，辅助操作收纳|保留真实已接入能力|

### 状态规范

- 主按钮高 48–52px、圆角 16px；默认纯蓝，hover 提亮，active 缩放至 .98，focus-visible 外描边，disabled 减弱并移除点击反馈。
- 卡片圆角 20px；hover 边缘微亮、active 轻压、focus-visible 明确轮廓；只有可执行的卡片使用按钮语义。
- 图片加载中显示固定比例骨架；失败提供文字说明和已有重试能力；不留下空白破图。
- Tab 为三个统一线性图标+短文字，当前项蓝色，非当前项灰蓝；无真实未读数据则不显示红点。
- 普通访谈不反复插入分支推广卡；用户表达探索意图时再出现。

## 5. Layout Principles

手机全宽可用高度，PC 居中约 430px，不通过缩放整个页面适配屏幕。页面左右 20px；间距 8/12/16/20/24px。底部输入与导航单独占位，内容区滚动。

分支卡建议宽高比 1.7:1，所有分支尺寸一致；390px 屏幕能看到约两张完整卡和下一张提示。已创建人生与待选提案分组，但不按“第一条更大”制造主次。

“我的”肖像建议 4:3、脸部上中区域；未上传时用明确的“添加你的照片”，不能用他人脸冒充用户。聊天里有照片后可内嵌展示，不再加第二个展示型首页。

## 6. Depth & Elevation

外层依靠深蓝层次和照片形成空间，卡片只有细边与轻阴影。蓝光只用于主按钮和选中边缘。锁屏通知用有限面积的半透明材质；聊天和相册保持清爽浅底。禁止整页发光和逐卡强阴影。

## 7. Animation & Interaction

建议 L1：180–220ms 页面淡入、120ms 按压、照片打开时轻量过渡。无滚动劫持、3D 或额外动画依赖。`prefers-reduced-motion` 关闭装饰过渡。输入时停止无关动画，生成中不显示虚假进度。

参考网页的可观察交互以页面切换、选中卡描边、进入手机、打开照片和约定为主；本次未验证到需要复制的复杂滚动动画，不作过度推断。

## 8. Do's and Don'ts

1. 用与当前用户及分支一致的人物和场景建立代入感。
2. 只使用当前用户授权的素材或当前分支生成的图片。
3. 每屏一个主要动作；状态说明放在动作旁。
4. 照片、消息、约定共享同一事件，避免各自编故事。
5. 保留三导航和多个分支的同等层级。
6. 不恢复强制资料填写门槛。
7. 不写死参考站的三个故事与人物。
8. 不用别人的照片、通用图或未生成图片冒充该用户的世界。
9. 不向普通用户展示“底模、图生图、已绑定”等实现词。
10. 不把“生成中”变成无上限自动重试或重复付费。
11. 不用丰富的假消息、假未读、假相册掩盖空数据。
12. 不在 PC 外侧添加管理面板或营销说明来挤占手机体验。

## 9. Responsive Behavior

验收 390×844、390×500、768×1024、1440×900；触摸目标至少 44px，无横向溢出；底部适配安全区和键盘。短屏时缩小装饰区域而非缩小文字。图片裁剪不能切掉人物脸部。长姓名、长分支名、多分支、空相册、图片失败和慢网均需验收。

## 图片链路与实施顺序

当前代码核对：分支列表只有标题、状态与原始肖像；世界手机默认通用壁纸；世界角色契约不直接包含头像字段。图片缺口不能仅靠 CSS 补齐。

1. 外层重构：聊聊、分支、我的，统一色板、文案、卡片与导航。保留原操作契约。
2. 视觉素材链路：定义和区分本人照片、分支封面、角色头像、世界壁纸、事件回忆；沿用资产权限与真实生成能力；无素材时有诚实降级。
3. 世界内重构：锁屏、聊天、相册、日历逐屏一致性校正；验证消息→邀约→回忆→继续聊天。
4. 每个可交付批次：检查、构建、手机/PC验收，确认生产迁移状态，提交部署，公网验收；未部署或未实测不标完成。
