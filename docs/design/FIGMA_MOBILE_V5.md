页面：05 · 身份到锁屏 · 体验流程。

用户已认可 V4 等权分支方向。此次补充世界入口，不改变聊聊/分支/我的产品结构。

## 路径与状态

1. 点击已生成世界的身份入口，先进入该世界手机锁屏。未生成或加载失败使用已有明确状态，不用样例锁屏伪装成功。
2. 锁屏展示世界时间、壁纸与未读通知。消息由真实世界状态产生，不强制每次进入都凭空安排一句。无通知保留安静锁屏。
3. 上滑解锁进入桌面；点击通知解锁并打开该联系人聊天。PC 提供点击解锁（底部提示同一点击目标）；不要求用户完成真实 Face ID 或密码验证。
4. 桌面提供消息、便签、日历、相册。日程邀请必须标待回应，只有接受后才成为确定约定；示例聊天的“我来”代表用户接受，示例前的桌面邀请仍为待回应。
5. 世界内收起产品三导航，底部为手机 Home 指示条；应用内返回消息列表，Home 返回世界桌面。桌面/锁屏左上轻量“分支”退出入口；桌面身份条“管理”打开导演、时间、身份与切换等既有管理能力。
6. 解锁、打开通知不发送回复、不接受邀约；消息读状态仅在实际打开对话后更新。重新从分支进入先展示锁屏，应用内返回桌面不反复锁屏。

## 视觉

390×844 手机内容参考 iPhone 的圆角、顶部状态栏、时间、通知卡、图标和 Home 指示条；不在产品手机页面里额外套第二层硬件边框。实机避开重复系统状态区域，PC 居中展示。

保持文字克制：锁屏只有日期/时间、通知、操作提示；桌面一张邀请卡、四个应用与管理入口。壁纸沿用项目 first-window.webp，仅作设计占位；正式世界使用用户授权素材或世界生成资产。

## 交付与边界

四屏：身份列表、锁屏通知、手机桌面、人物聊天。通过 Figma 正常导入可编辑文字/矢量/图片图层，截图 figma-mobile-v5.png。四屏是静态视觉稿，点击与上滑行为是实现约定，尚未连线为交互原型。人物姓名、对话、日程均为示例。

未改业务代码、未调用模型、未部署。实施阶段接续已存在的手机锁屏与应用模块，避免重新实现，完成后验证手机/PC、上滑与点击、无通知、多通知、恢复与返回路径，并运行 check/build。
