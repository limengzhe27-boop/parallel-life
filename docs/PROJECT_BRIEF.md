## 产品定位

用户通过个人 Agent 理解自己的经历与愿望，讨论出一条想体验的平行人生，再进入这条人生里的手机。玩家是自己的故事主角；导演围绕他安排有因果的事件，NPC 有自己的立场与知情范围。选择应留下结果，世界应能主动回应，而不是只进行被动问答。

固定外层三个入口：**聊聊／分支／我的**。无独立首次资料表单，年龄/生日不作进入条件；Agent 按需要自然了解用户。手机全屏、PC 居中窄幅；进入人生后为iPhone式锁屏与应用体验。文案简短，内容主导，不做管理仪表盘。

当前重点是完整体验重构：[EXPERIENCE_REBUILD.md](EXPERIENCE_REBUILD.md)。NPC跨人物介入、群聊和剧情中主动生图是待验证方案，不因用户举例就全部立即开发。语音暂缓；多人、时间、多人生未取消。

## 架构与边界

模块化单体，不改为多个独立服务拼接：domain纯规则；application面向端口；infrastructure负责外部适配；server组装。AI只提出变更，由运行时校验、事务保存事件/状态/回执/后续任务。

- 现实资料、各平行世界和多人共享场景隔离；NPC不接收完整私人访谈。
- 人生创建使用已授权的设定快照，不能把“想创建”当成同意带入所有照片与私人资料。
- 事实、用户假设、角色看法、承诺和照片来源有区别，不能仅凭模型台词变成世界事实。
- 多个手机应用应读取同一事件及素材引用；禁止客户端拼出未发生的故事或把占位图标成生成成功。
- 版本、幂等、来源、可见范围、失败/unknown恢复是底座，不因重构UI或主动调度而绕开。
- Vercel请求可执行已有持久任务；不能依赖HTTP返回后进程继续工作。真正后台推进须有可靠执行者及验收。

目录职责：src/modules/profile现实资料；discovery方向；world世界事件/回合/导演；memory有来源记忆；media素材；tasks持久任务；src/server组装；src/features界面；src/contracts共享契约；db/migrations数据库版本。
