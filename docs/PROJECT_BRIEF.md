# 如果 · Parallel Life｜Agent 项目说明与接手入口

更新：2026-09-22。用途：让没有参与历史对话的开发者或 AI Agent 能理解产品、识别当前实现边界，并领取明确任务继续工作。本文提供背景，不另建一套任务进度；状态以 [开发任务总表](DEVELOPMENT.md) 为准。

## 1. 这个产品是什么

“如果”让用户从自己的照片、经历、兴趣、关系与愿望出发，体验一种平行人生。个人 Agent 通过聊天认识用户，逐步整理可编辑档案，再提出与其经历有关的“如果”。用户选择或改写一个方向后，进入平行世界中自己的手机，通过消息、朋友圈、相册、便签和日历生活。

产品的代入感来自“这仍然是我，但我经历了不同的人生”。真实照片、人物关系和生活细节需要连贯。目标是有成品完成度的完整体验，当前先按阶段实现，不把点击演示当作完整产品。

例如用户聊到喜欢摄影、想换一种生活，Agent 可以据此讨论摄影师人生；另一个用户聊到不同经历，应得到不同方向。例子只用于解释产品，**不能把导演、摄影师或某段感情故事写死成所有用户的流程**。

## 2. 已确认的体验流程

1. 认识我：自然访谈，上传自己的照片或补充重要人物，Agent 同步整理档案；可跳过、手动修正和继续补充。
2. 现实轨迹：记录重要事件和用户自评的起伏。未知就保留未知，不编造成评分、命运预测或心理诊断。
3. 另一种可能：从确认过的经历生成方向并解释依据，支持继续聊天、自定义、修改和重新生成。
4. 生成平行人生：身份、人物、关系、时间地点、初始事件和照片相互对应，生成阶段可恢复。
5. 打开手机：关键人物可以发消息、邀约和分享动态；用户自由回复或在应用中行动，引发后续变化。
6. 导演调整：用户可以改变主题、人物或节奏；重大历史改写建立分支，保留原人生。
7. 持续生活：切换多条人生，暂停、倍速、跳到事件，离线后补充压缩摘要。
8. 真人相遇：在用户主动允许的范围内，让不同用户在共同虚构场景中相遇，私人访谈和档案不自动共享。

## 4. 架构地图与不可跨越的边界

采用模块化单体：一个 TypeScript 项目，按业务模块分层；Web/API 接收请求，后台 Worker 执行耗时任务，PostgreSQL 保存事实，私有对象存储保存图片。

|区域|职责|
|---|---|
|src/app|页面与 HTTP 入口；其中 api 由服务端负责人修改|
|src/server|服务端配置与依赖组装，不向客户端泄露密钥|
|src/modules/profile|现实档案、推荐依据与带入资料的授权契约|
|src/modules/world|世界事实、版本、事件、回合及角色知识范围|
|src/modules/tasks|可在世界创建前运行的通用任务契约|
|src/modules/ai|模型端口和网关实现；不直接决定权限或写世界状态|
|src/modules/media|私有素材、生成任务、幂等与媒体修订|
|db/migrations|数据库变更；需真实数据库验证|
|tests、scripts|与改动相称的验证和边界检查|

目录内 domain 是纯业务规则，application 是用例/端口，infrastructure 是外部适配。没有的模块在对应任务中创建，不为了凑目录一次性造大量空实现。

必须遵守：

- 现实档案、平行世界、多人共同场景三类数据隔离。
- AI 返回提案，程序解析和校验后原子保存事件、状态、回执与后续任务。
- 手机应用共同读取世界事实，不能各自独立生成相互矛盾的剧情。
- 角色只收到自己能知道的内容；权限不能仅靠提示词约束。
- 角色声称的内容不自动等于世界事实，邀约提议不等于用户已经接受。
- 媒体完成使用独立修订，不因图片晚返回而让聊天版本失效。
- 私人访谈发生在创建世界之前，后台任务不能强制要求 worldId。
- 不在返回 HTTP 后依赖进程继续工作；长任务需要持久队列和可恢复 Worker。

这些约定中有的已实现，有的仍是任务验收条件；详见 [架构复核](ARCHITECTURE_REVIEW.md)，不要把写在文档里当成代码已具备。

## 6. 开始开发之前

按顺序阅读：根目录 AGENTS.md → 本文 → 主目录 DEVELOPMENT.md 的状态与领取登记 → ARCHITECTURE_REVIEW.md → 与任务相关的 ARCHITECTURE.md/PRODUCT.md；涉及 UI 再读 DESIGN.md。

当前集成人是主任务 codex-main-01a0c73b。另一个执行 Agent 不因主任务暂时空闲就自行接管 I 角色。用户明确单人执行或指定新集成人时可以交接；单人自己登记、自审并完成即可。无可领取任务时报告前置任务，不能抢占已领取任务或跳过依赖。

## 7. 开发中与收尾

每完成一个子步骤、改变文件范围、遇到阻塞、准备结束当前轮次时更新任务报告，至少写明已做内容、当前文件、检查结果、下一条动作和最后更新时间。不能只在聊天里说“完成了”而不改登记。

保留其他人的改动。需要公共契约变更时先提交具体建议给 I，不能在自己分支悄悄更改并让其他人猜。遇到测试失败，修正原因，不删测试、不放宽权限、不用假模型回复掩盖问题。

多人代码交付后写“待验收”，附提交/文件与证据，保留归属直到集成结束。I 合并并验证后勾选已完成；单人可自审，但仍要有证据。无法完成时标阻塞或保留进行中并写接续，不把时间不足等同任务完成。

需要交接时使用 [任务报告模板](TASK_REPORT_TEMPLATE.md)。最新事实记录到对应文档，不依赖新 Agent 读取整段历史对话。
