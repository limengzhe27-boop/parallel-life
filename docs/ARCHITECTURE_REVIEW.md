# 架构复核 · 2026-09-22

结论：总体分层方向可继续，但上一版存在真实代码缺陷与未闭合的设计。不能用构建成功或单元测试通过证明产品架构没有问题。

## 已复现并修正的代码问题

|问题|触发及影响|修正|
|---|---|---|
|模型 ID 跨轮冲突|模型第二轮再次输出 message_1 等局部编号，正常回复被整轮拒绝|服务端按事件生成存储 ID，模型 ID 仅用于本轮解析|
|角色权限只在应用层检查|其他内部调用直接提交事件可替另一角色说话|共用领域规则并在最终 reducer 强制检查|
|无回复却标记聊天成功|模型仅返回图片任务或事实变更|聊天提案必须包含合法角色回复，否则整轮拒绝|

以上三项在架构骨架阶段先新增测试复现，再修正。当时尚无业务 HTTP 写入口，记录的是潜在权限缺口。当前访谈接口已接入身份和数据库；世界角色接口仍未开放。

历史架构修复时验证为 18 项测试及构建。2026-09-22 开发增量现为 32 项单元、8 项真实库、真实文字与浏览器验证，详见 V-01 报告；不将后续世界体验记为完成。

## 不宜承诺的部分

- 多 Agent 长期一致性、人物自然交流、推荐质量，需要真实模型多轮评测。
- 用户人像在新场景中的一致性，不能只通过网关名称或代码推断。
- 持久队列和访谈幂等已实现；上游已接受但响应丢失的调用无法承诺撤单或退款，保留 unknown 并由用户明确重试。世界角色仍需 W-03 连接队列。
- 真人相遇涉及共享时钟与退出规则；当前只有设计约定，不代表联机已完成。

## 开发顺序调整

保留整体架构，不扩张为微服务。“通用任务 + 游客会话 + 访谈存储 + 真实文字”已接通。下一步个性化推荐及参考照片生成验证，之后让手机应用共同读取同一世界事实。上述缺口列为阶段验收条件，不带着它们直接接成生产接口。


## 本轮真实浏览器发现并修复

- 原生 fetch 被存成对象方法时丢失 Window 接收者，浏览器报 Illegal invocation；绑定接收者并新增回归测试。
- 手机档案弹窗里的上传失败提示原在背后的聊天区；改为就近显示，上传保留原照片并允许重试。
- Modal 的原生 Esc 默认关闭会绕过保存中状态；取消默认行为后统一走 onClose。
- 同目录运行开发服务器与构建可能争写 `.next`；启动说明明确串行，本机默认 webpack 避开已复现的 Turbopack 中文语法诊断崩溃。
