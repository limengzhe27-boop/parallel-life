# 编剧如何从 Markdown 发布一段世界

先新建或选择作品，点击“导入 Markdown”。可以选择世界观、人物、剧情节点等多份 Markdown、文本文件或 ZIP，也可以粘贴文字。ZIP 中的照片不会自动上传或生成。

## 推荐流程：让项目里的 Agent 整理

1. 读取文稿后选择“让 AI 整理”。这会把本次文稿和当前编辑稿交给项目的文字模型；不会读取私人访谈或其他玩家存档。
2. Agent 提出世界设定、人物、关系、地点、路线、开场历史和消息、阶段时间线与剧情机会。原稿没有写明的必要细节可作为虚构补充，供编剧核对。
3. 先看“原文与实际字段对照”中的“可能遗漏 / 改错”，再看“暂不能判断”。前者需要有具体字段或数值线索；后者可能只是换了写法或暂不支持比对，未匹配不直接算遗漏。“文字已对应”可展开查看，但不等于语义完全正确。每条保留原文位置、判断原因和实际字段，格式或整理说明单独归类。模型整理说明不是保存证据，说明里出现年龄等细节，不代表它已经进入人物或剧情字段。秘密的知情范围仍需要核对，不能把“整理完成”直接等同于“可发布”。

   对实际内容中没有找到原文线索的字段，按整理前的草稿分为“原有内容已保留”“原有内容有改动”“新增补充，待核对合理性”及“来源基线未知”。有改动时显示旧值。原有设定不算本次新增，新增也不自动判为错误或合理；优先核对新增内容是否符合人物、时间线与创作意图。缺少可靠基线时会明确标为未知。
4. 勾选已核对并填入当前编辑稿；这一步不会发布。仍可在世界、人物、剧情页修改，再保存草稿。
5. 检查内容，处理具体缺项；通过后进入私有试演，实际与角色互动，再检查并发布。
6. 发布后所有玩家都能在分支目录看到作品，每人进入自己的独立存档。

已有非空文字、稳定人物编号和未知字段优先保留。已有角色会补齐缺项，新人物或场所作为补充列出；原候选节点的文字和顺序保留，可补成带时间条件的来信或邀约。冲突和不支持的内容会列为待核对项，不会偷偷替编剧修改。过往事实与未来可能事件必须区分，不能把预设选择写成玩家已经完成。

若作品仍保留与新原稿无关的旧设定，请新建作品导入，或先清理旧设定；Agent 不会直接覆盖编剧已写好的内容。新建作品不再默认塞入“起点住处”来限制剧情地点。

## 整理中断与恢复

整理结果与本次原文保存在私有内容后台，只有发起整理的员工可以读取。刷新或重新打开导入窗口时可以核对原操作；当前作品、草稿版本和编辑内容必须匹配，过期结果不能直接覆盖新稿。

每次整理最多两次文字模型调用：第一次生成提案；仅当已收到的提案未通过结构或运行规则校验时，才根据明确问题进行一次纠正。纠正结果仍需核对，无法通过的内容继续显示待检查项，不循环调用。

超时或结果不确定时先查询原来的整理，不自动重付。只有明确选择重新整理才开始新的整理操作。单员工同时只执行一份，每小时最多十次新整理。较长的文稿加当前稿超过整理输入上限时会提示拆分，不静默丢弃后半部分。

## 不调用模型也能导入

保留“仅解析”方式，按支持的标题、表格字段提取明确资料，原文和无法识别的部分留供核对。它不会自动推测日期、地点或执行规则。纯解析预览仅留在当前页面，刷新前请保管原文件。

## 各模块重点核对

- 世界：公开简介与幕后背景分开，主角身份、当前处境、开场日期和地点准确。
- 人物：名字、年龄、身份、性格与说话方式、动机和底线；是否开场认识主角，以及知道哪些既有事实。请核对实际人物表单，不能只看“已提取”说明：模型可能在说明里提到年龄，却未写入身份字段。
- 地点：场所说明和有方向的出行耗时，返程另列。
- 手机历史：消息时间早于或等于开场，并与人物知情一致；不能伪造已付款、已赴约等玩家行动。
- 剧情：已发生事实、阶段和可选事件分开；候选不是必经任务。只有支持的来信或邀约能被运行时调度，不能把备注当成功能。
- 素材：没有实际图片时不生成假图或编造图片链接；原有素材引用保持原样，目前导入不补图片。

人物页的既有事实不是固定示例。展开“修改这条事实”可编辑共用文字，然后保存；勾选只决定当前人物是否知情。新增事实、修改日期或可见范围，进入“到剧情页管理或新增事实”。

## 发布后由谁运行

整理阶段由项目自己的 Agent 生成提案；编剧采用的稿件经过校验，成为发布内容。玩家进入时，系统据此建立独立手机世界，不需要开发人员替每个玩家写故事。开场初始化沿用已核对的设定，不重新调用模型改写它。

进入之后，项目中的 NPC Agent、剧情调度和现场 Agent 按玩家行动继续演绎。模型只提出变更，由运行时校验并保存；角色答应一件事不等于已经实际完成。编辑后台草稿不会改写旧玩家存档。

结构校验通过，只表示当前设定可按支持的规则运行，不证明原文信息全部保留。重要约定、关系细节和年龄等仍应逐项核对实际表单；模型添加的关系描述也可能超出原稿。

自动整理不意味着任意长度、任意机制的剧本都能一次发布。原稿冲突、未知玩法、暂不支持的角色或素材仍需编剧处理或后续开发；专业版本对比、图片附件自动绑定和更大文稿分段整理继续保留在任务清单。

## 如何使用原文对应检查

这一步不额外调用模型。系统直接比较本次原稿与最终提案，不读取模型的自述来证明已填入。

- **找到相同文字**：实际字段存在相同文字，可点开检查放置位置是否正确；不代表人物归属、公开范围或整个情节已核实。
- **可能被改写**：展示可能对应的字段与完整文字。需要核对意思是否变化，例如“相识三年”不能直接变成“共事三年”。候选只是查找线索，不自动替编剧作判断。
- **暂未找到对应**：可能遗漏，也可能换了说法。请对照原文定位，再查看实际人物、历史或剧情；不要仅根据这条提示删除内容或认定导入失败。
- **数字差异**：提示所匹配文字中的年龄、金额等变化。结构化开场时间、路线耗时等仍需在实际内容预览中核对；日期还可能涉及格式与时区换算，提示本身不代表确定错误。
- **实际内容未找到原文线索**：可能是原有编辑稿或合理补充，展开核对即可，不直接判为编造。

例如模型说明写了“26岁”，但人物身份与背景都没有年龄，需要修改实际人物设定。原稿中的约定没有对应时，应确认它属于已经发生的事实，还是未来才可能发生的剧情，再补到合适位置。当前未知字段中，作者原有值保留，AI新提出但未支持的字段会提示未填入。

文字对应不等于经过语义核验的来源映射，也不提供完整覆盖率。短文本、同名人物、多份文件冲突、否定或隐含关系仍可能需要人工判断；达到检查容量时会明确提示未检查完整，原稿仍保留。原文或最终稿变化后重新计算，不沿用旧对应。核对工具不会自动改稿、保存、试演或发布。
