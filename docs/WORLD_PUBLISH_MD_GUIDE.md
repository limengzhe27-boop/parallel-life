# 编剧如何从 Markdown 发布一段世界

先新建或选择一份作品，点击顶部“导入 Markdown”。选择世界观、人物、任务节点文稿，也可选 ZIP 或粘贴文字。提供可下载的虚构填写示例。

## 导入会做什么

- 显示本次识别的世界字段、人物和剧情候选，以及来源文件、待补全内容与原文。
- 世界梗概保留在幕后，不自动成为玩家公开简介。公开简介、开场钩子、主角身份等需原文明确标注。
- 同名人物不自动覆盖；已有内容不被空字段清掉。多份节点稿会累计，同一完整幕后段落反复导入不会重复追加。
- 人物过长或尚未确定的背景会保留在原文报告中；明确提取的字段可以填入新草稿。缺少部分设定的人物标为“待补全”，不是已可运行。
- 候选原文先作为幕后备注。它不是必发生任务，也不表示玩家已做过这些事情。
- 来信缺少具体日期、来源或唯一发送人物时，不编造时间。到“开场时手机里已有的消息”补发送人、原话与时间；人物须是开场已认识的人。

点击“填入当前编辑稿”只修改编辑内容，随后仍需“保存草稿”。原文导入报告留在当前编辑页面，不自动公开或作为世界记忆；刷新不保留这个临时报告，请保管原文或在关闭预览前下载待整理文稿。

## 怎样补到可试演

1. 世界设定：公开简介、吸引点、体验说明、主角身份与当前处境、公开世界背景、幕后背景、基调、开场日期和地点。
2. 人物：名字、身份、开场是否已认识、背景、说话方式、动机、边界。已有关系与知情事实分别核对；不要把未来可能发生的事当角色过去经历。
3. 地点与路线：修改地点名和场所说明；新增地点需说明是否开场已知。路线按方向设置真实耗时，返程另加。不用手写结构化数据来补这些内容。
4. 开场消息：将原稿已存在的消息整理进手机，每条分别给人物、原话与北京时间。过去对话应早于开场，开场来信也不能晚于开场；不会全部挤在访问者打开手机的时间。
5. 剧情：先区分“已发生事实／阶段时间线／可选事件”。若希望某候选运行，选择实际来信或邀约，再补人物、内容、地点、最早时间及前置；只有备注的节点不会自动演绎。先后窗口与拒绝、错过后的替代按剧本填写，结局保持玩家行动决定的可能性。
6. 保存、检查，按中文缺项提示补全。内容合格之后仍须试演并完成真实角色对话，再检查，符合发布条件才可上架。

发布形成正式版本；玩家各自获得独立存档，编辑草稿不改他们正在体验的世界。专业版本对比管理仍是后续工作。

## 当前边界

当前是确定性文稿识别与人工整理，不是把任意长剧本自动变成可玩世界。未明确的时间、人物、地点、关系与剧情执行规则不会由解析器猜补；原稿未支持的机制要另行开发。照片附件不由本导入处理，也不会触发生图。ZIP 上限和文稿上限不等于草稿可以保存的大小，超限会明确阻止导入。
