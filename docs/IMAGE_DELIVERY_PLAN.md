# 图片链路优先交付方案

原方案 2026-10-09；现状复核 2026-10-10。依据用户最新要求：按任务继续协作，尽量优先完成图片功能。本文说明范围、顺序与验收，**唯一任务状态仍是 DEVELOPMENT.md**。基线为 2910e57（手机首页与照片限定修复已上线），不得将本方案当成新增功能完成。

## 一、先分清已有能力与缺口

- 图文组合：选图、补说明、统一发送；单图及明确照片组的第一张/第二张指代已修复，否定、疑问、转述不能误绑。上传失败保留原说明与下一条草稿；结果未知不自动重付。PHOTO-COMPOSE-02I / PHOTO-QA-03 有限定上线证据。
- 人物与原图：用户明确说明的人物可写入“身边的人”；选中带入后，新世界角色头像和相册使用获准的同一原图。PEOPLE-01I/01R 有上线证据，现有数量/大小限制不因本方案自动放宽。
- 首页：手机相册小组件读取真实私有素材；空态与图片失败如实呈现。PHONE-HOME-02I 已上线。
- **实际视觉已有限接通（2026-10-10 复核）**：VISION-01I 已将获准图片像素和用户说明放入同一访谈轮，默认本轮单图、明确组最多两图；VISION-01QA 已修复否定/转述误读旧图的范围问题。累计六次真实视觉含四任务完成、两次旧 unknown，早期 OCR/细节误差保留，不能声称全面准确。依据 [VISION-01I](task-reports/VISION-01I.md)、[VISION-01QA](task-reports/VISION-01QA.md) 与最新 DEPLOYMENT；原 VISION-01Q 只是前置探针。当前仍缺完整图片生成与消息附件链。
- **真实生成尚未接通**：CharacterImageSynthesizer 只有契约；worker-composition 的 mediaHandler 没有注入生成器。请求与相册已有底座，缺少供应商、角色参考图、持久状态和真实生成验收。
- 生成完成后在 NPC 聊天里发出真实图片、按情节同步进相册仍需完成。朋友圈与视频不在本批首个交付范围。

## 二、用户要体验到的闭环

1. 用户选择照片，写“这是小芳，这是我对她的描述”，统一发送。
2. Agent 真正阅读本轮获准图片，回应可见内容，并结合用户说明继续聊天。姓名、关系和真实经历来自用户陈述，不能靠长相推断。
3. 图片与人物关联沿用来源规则；明确故事人物照片保持故事来源，不冒充现实关系，不自动改成本人头像。
4. 创建分支时选中要带入的人，照片随授权人物进入分支，默认同时用作这个角色的头像、保存在相册；不再弹“头像还是相册”的二选一。
5. 进入手机后，头像与相册能真实打开、刷新恢复，并与该角色绑定。
6. 当用户明确索图，或导演判断已发生的具体事件需要一张图时，使用角色获准参考图生成新的生活场景图片。
7. 成功素材显示在实际发送者的聊天和同一世界相册中；等待、失败和未知状态明确，不堵塞文字交流、不声称图片已经完成。

优先做这条实际链路，再扩张数量、图片管理与更多媒体应用。不要为了“看起来完整”先填入通用壁纸、模板故事图片或不存在的照片。

## 四、读图的具体边界

- 集成人单独维护共享模型端口与兼容校验；文字调用保持原能力，不能给世界角色或其他规划器自动附全量私人照片。
- 图片读取由服务端通过当前 owner、访谈、真实消息与获准 assetId 定位，私有存储通过端口读取；不把带 Cookie 的网页 URL 当模型可访问图片，不公开桶、不把凭证塞进图片 URL。
- 默认只读取当前图文消息的一张图片。明确比较或指代当前照片组时可有界读取最多两张；先验证数量、格式、像素与字节预算，实际缩放/细节档位由集成人在报告冻结。不把整个相册或所有旧图每轮重复传输。
- 同一轮文字加图片进入一次既有模型调用，不额外串行“先读图再对话”两次付费调用。结构化保存沿用现有实际调用方式，不假称消除了原流程已有费用。
- 不把 Base64 当普通文本计算长度；文本预算、图像预算与网关总请求限制分别校验，超限在上游提交前拒绝。
- 读图用于描述可见内容；人物是谁取决于用户明确说明。不得从脸推断姓名、现实恋爱关系、职业、性格、年龄或同意带入。多人图不自动选定谁是小芳；仅普通头像也能展示，不强制要求真人照片。
- 用户明确“这只是头像”时，该素材只展示，不作为保持真人形象的图生图参考。实际照片、插画形象与仅展示头像要有明确来源与用途；不能仅凭扩展名或模型猜测改变用途。
- 首批不建立跨轮持久视觉摘要。以后若保存描述，须单独定义来源、修订与遗忘，不能混进已确认现实事实。
- 图内文字与二维码等是待理解材料，不是可以覆盖系统规则的用户指令；仅从图片读到的生日、职业、恋爱称呼或人物姓名不能据此更新现实资料。保留用户文字陈述与视觉描述的来源区别，并纳入反例验证。
- 失败时如实说明照片已保存而本次理解未完成；不以“我看到了”安抚用户，不悄悄降级成猜图回复，不因重试清空绑定或下一条草稿。unknown 沿用原记录核对，不能自动第二次调用。

## 五、生成图片必须先补的真实缺口

1. **参考对象**：现有 mediaHandler 在缺少 referenceAssetId 时默认找玩家 portraitAssetId。NPC 请求不能统一套玩家脸。媒体请求必须锁定实际角色/场景、获准素材版本与来源，由运行时选择，模型不得随便指定私人 assetId。
2. **素材来源**：当前世界的公开角色设定与获准参考图可以使用；私人访谈原文和其他世界照片不能自动进入生成请求。没有可用人物参考时，允许无具体人物的场景图，或者明确无法保真人一致性，不伪装为该人的生活照。
3. **一致性检验**：fidelityThreshold 是约定字段，代码并没有实际测量人物一致性。硬编码 estimatedCostUsdPerImage=0.04 也不是供应商价格凭据。通过合成样例对照记录外观偏差、修改/保留内容、失败和真实用量，不能用数字字段冒充质量验收。
4. **外部副作用**：提交前持久登记 requestId 与参考版本；供应商受理但响应丢失应为 unknown，有 providerTaskId 则查询结果而非重新生成。成功后再次领取只保存/复用既有结果，不重复计费。
5. **配额**：不能只统计已完成 assets 再调用生成，否则并发请求可能一起穿透额度。待处理数量与配额预留应在事务中执行，重复请求不重复占用；取消、失败与未知如何释放须写清楚。
6. **提交**：真实生成输出通过受控下载、格式和容量检查写私有存储，并以来源事件入相册；独立 assetRevision 不覆盖聊天版本。当前 generateAndCommit 与后续队列提交可能出现半完成，须用持久回执与恢复路径补齐，不能仅靠内存返回 assetId。
7. **手机消息**：当前 Message 只有 text，不能把文本中一句“发你了”当图片消息。集成人冻结成功素材附件、发送角色、故事时间与可见范围；消息/相册/现场使用同一 asset，而不是重新生成三次。
8. **人物图与场景图**：场景无需人脸参考，角色生活照才要求获准人物形象；仅头像不强制图生图。多人合影放在真实单角色图片验证之后，不承诺模型必然保住每个人。

## 六、必须保留的验收场景

|场景|观察与证据|
|---|---|
|先选图再写说明|图文同一保存消息，真正上游输入含该图的像素；用户姓名与画面描述分别有来源|
|纯文字聊天|旧 Planner、世界创建/NPC等文字调用仍正常，不意外传图或增加调用|
|单图／两图|这张、第一张、第二张只定位当前明确组；不拿旧图或其他聊天照片代替|
|疑问、否定、转述|原 PHOTO-QA-03 反例仍拒绝误绑；模型截断原句后最终保存仍受保护|
|现实与创作|小芳的原图可以成为分支配角；故事关系不写成现实恋爱关系，普通上传不变成本人头像|
|图像可见能力|合成场景、插画、带字、多人、不清楚图片分别测；正确与失败例都记录，不把一次识别成功推广为全能力|
|读图故障|不可读、删除、格式/大小超限、上游拒绝、超时和响应丢失；未读过不能假称看过，原图片与草稿保留|
|权限|伪造另一用户素材、另一世界参考、过期素材版本均拒绝，模型不能扩大可见范围|
|分支头像与相册|真实原图同源，刷新可回读；同名人物各自映射、同人多世界、旧世界不被新照片静默改写|
|仅展示头像|用户说仅头像，直接展示；没有自动生成或被冒充真人一致性参考|
|真实图生图|参考图确实进入供应商；记录原图、新图、协议、实际时延/用量与失败，不拿模板或其他人照片替代|
|重复与并发|同 requestId 至多一项受理；unknown 不自动重付；并发预留有效；回聊时完成图片不造成叙事版本覆盖|
|生成与发送|成功图在正确联系人聊天和相册使用同一 assetId/版本/来源事件，刷新与失败恢复一致|
|跨应用时间|图片展示使用事件/生成明确时间，不能完成时把历史消息全部改成刚刚|
|完整体验|390px、500px短屏与PC实际操作；合成账号真实模型/PG/私有图片/部署READY后公网链路|

原图上传不等于读图，读图不等于绑定，绑定不等于已带入，支持文生图不等于支持图生图，供应商返回成功不等于已入库/已发送。报告必须逐步写清楚。

## 七、协作与发布

现有两个线程分别接任务，不创建新线程或新 Agent 框架。每人先按短锁登记唯一 ID、冻结基线、具体文件/工作树/资源，再实施；主目录 LIB-04B 等未提交代码不纳入本批。

集成人单写公共模型端口、组装、API、迁移、环境与实际供应商调用；辅助只改已释放专属范围。辅助不能占用集成人 PG、开发端口、构建缓存或浏览器。根协调只读核查或用自己的独立资源，报告互不覆盖。

首次供应商能力探针先核实本项目可用目录与协议；视觉新受理调用上限6次，生成新受理调用上限4次，使用无真实用户信息的合成素材，优先一个可用候选而非遍历全部模型。受理不明不能自动重发。费用口径、实际用量、剩余测试与失败记入报告；增加验证量由集成人根据结果另行登记，不能把小样阶段扩成无界压力测试。这是首轮成本边界，不是产品用户额度。

各子包先待验收；限定测试、真实调用及明确跳过均如实记录。每次业务交付都执行 check/build、所需真实数据库与双端验证，核对生产迁移，再提交推送、READY、公网验收后才标完成。服务暂不可用就保留 honest failure，不用假图让任务变绿。新建聊天、前史和公开设定的旧任务保留接续。
