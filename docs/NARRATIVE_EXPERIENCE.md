# 叙事体验：让选择留下结果

2026-09-28；产品、设计、内容与研发共同使用。主登记仍为 DEVELOPMENT.md，本文不另设完成状态。

## 产品判断

用户来这里想体验“另一个我真的在生活”。吸引进入靠具体的身份愿望和生活画面；继续体验靠人物可信、行动有影响、付出有回报；再次回来靠尚未结束但值得继续的事情。更漂亮的页面、更多角色和更多反转各自都不能替代这个闭环。

推荐的体验循环：**我想成为谁 → 与我有关的一件事 → 有原因的阻力 → 自由行动 → 看得见的结果 → 人物关系变化／喘息 → 自愿继续或分岔。** 困难不是必选项，轻松陪伴和日常成就也成立。起伏来自情境和选择，不从用户真实烦恼中推断可利用的心理弱点。

## 主角原则（用户最新补充）

每个进入分支的玩家都是自己体验中的主角，类似《楚门的世界》的叙事聚焦方式。世界围绕他组织，导演是幕后调度者，NPC 是能与他产生关系、分歧和影响的配角。NPC 的独立动机用于创造可信互动，不能变成让玩家旁观的自治群像。关键决定属于玩家，主要结果由他的行动影响，配角不能抢先解决核心挑战。

导演候选情境增加三项判断：与主角当前目标是否相关；用户能否参与改变；结果是否能被用户感知。全不满足的后台剧情应压缩或不呈现。提供舞台、阻力与回报，不预定用户必胜、必败或唯一正确道路。未来多人相遇时，各自仍有自己的主线；本批不实现多人，也不默认其他玩家是可被操控的NPC。

## 从进入到回访的链路

### 1. 进入：先让人想象自己，而非填写档案

保持“聊聊／分支／我的”三入口。首次聊天只给一句能回应的邀请；个人 Agent 通过自然对话收集愿望和经历。照片可选，不设阻塞表单。推荐卡采用具体身份与生活场景、一句与用户有关的缘由；多个分支同等层级，不用一长段设定解释产品。示例体验必须标明示例，不能声称它来自用户经历。

### 2. 分支：卖一个想体验的问题

“独立导演”只是身份；“第一部电影终于有放映机会，但你和制片人对版本有不同意见”才是可参与的开场。卡片展示身份＋当下的一个生活切面；未知结局留给用户。不要默认每个职业都是逆袭争奖，慢生活、亲密关系、旅行也可以由小愿望和不同偏好驱动。

### 3. 入场：一件事，少数重要的人

锁屏消息承接身份。开机后先围绕同一件事与一至两人交谈。一个明确的机会、一项已知限制、一种现在能做的行动就够了；联系人可以更多，但不同时轰炸。所有对话应像人物在发消息，不是导演给用户解释剧情架构。

### 4. 参与：目标不同，才需要选择

NPC 有自己的目的、能力与顾虑，可以同意、拒绝、讨价还价、帮忙。拒绝应给原因和可改变条件，不能只为制造挫折。用户能接受、拒绝、绕路、搁置或自由提出第三种办法。合理的小请求不必总付代价；有效方案应被承认。

### 5. 回报：不能只有台词夸奖

用户解决一个问题后，已提交的状态必须真正改变：角色回应承认选择、邀请状态变化、作品或照片出现、便签留下回顾。生成素材等待或失败要明示。已取得的进展不为了下一轮反转而收回。部分失败也应留下学习、关系或替代路径，而不是回到同一个问题。

### 6. 回访与再分支

回来先接住一件未了事项或一个结果，不灌长摘要。事情结束时允许自然告别。到真正影响后续走向的选择处再提供“另一种选择会怎样”，预览保留什么、改变什么，确认后建立新分支；不得悄悄改写原人生历史。

## Agent 分工与资料边界

| 角色／服务 | 应负责 | 不应负责 |
|---|---|---|
| 个人向导 | 理解现实经历与愿望，按既定规则沉淀资料 | 把虚构成功当真实经历；承诺尚未创建的分支已存在 |
| 人生探索 | 把经历转成有个人关联的可能性 | 输出所有用户都一样的职业菜单 |
| 世界创建 | 从获准带入的设定建立人物目标、关系、开场 | 将私人访谈原文交给 NPC；预定用户必胜或必败 |
| 导演 | 选当前值得发生的情境，照顾未了事项、回报和节奏 | 替用户行动；不断加压；向每个角色泄露全部信息 |
| NPC | 在可见信息内体现自身立场、聊天和行动提案 | 全知叙述、操纵别的人、直接改全局事实 |
| 记忆与运行时 | 检索有来源的信息、隔离权限、校验并保存后果 | 把人物印象当事实、把忘掉的内容重新召回 |

不需要为了“多 Agent”增加模型次数。导演策略可以先由确定性条件选择，模型负责表达；长期复杂规划再用有限次数的规划调用。每轮仍走现有校验与世界事务，不能另写一个剧情旁路。

## 当前发现与本批边界（NAR-01）

1. 角色上下文已经检索记忆，但模型输入此前遗漏了这些记录。本批接通有来源的、已授权的记忆，补 owner／分支／角色作用域检查；已屏蔽来源不再通过消息、事实或约定绕回。
2. 旧提示要求每轮有新变化、结尾给钩子，容易问个不停。本批改为六种有依据的情境指引：入场、回答、协商、承接承诺、延续、轻松收尾。普通对话不会按轮数强行反转。
3. 世界开场改为一件能参与的事，人物有立场，不预定结果；既有世界不会被自动重写。
4. 导演影响预览原本把人物姓名当 ID 再查找，本批修复姓名显示。

**实际限制**：这是第一层确定性选取＋模型软指引；不是长期剧情状态机，无法硬性保证生成文字永不偏题。承诺策略只消费已有有效记录，本批没有实现完整的承诺抽取／履行／到期机制。检索遗忘源过滤不等于对所有派生记忆实现递归删除。真实体验与留存仍待检验。

## 后续任务及验收

### NAR-02：可持续的剧情线与导演恢复（最优先）

在现有世界事件体系内增加剧情线，不建立第二套世界事实源。每条线至少包括：目标、涉及人物、前提证据、利害、可走路径、已作选择、开放承诺、阶段、已兑现结果、最近使用／冷却。生命周期可包含提出、进行、受阻、解决、搁置；转换必须引用实际事件，不能由一句人物独白直接认定成功。

导演先排除不满足条件、不可见或已解决事项，再优先回应用户当前行动、兑现已有约定、推进相关线索，最后才考虑新事项。不得用“第 N 轮必须反转”。多人目标冲突必须有已建立的依据。未到结果时可以承认仍在进行。

与现有导演命令共同解决并发、部分失败与重复执行：同一触发不能重复发消息，世界状态和节拍结果可恢复，失败不能消费一个未演出的剧情节点。

验收：至少三种身份、每种两个不同选择，刷新后后果保持；解决后不再提出同一障碍；退出再进继续同一条线；并发无重复、失败可恢复；跨用户／跨世界／角色不可见事实隔离。真实数据库测试必需。

### NAR-03：让后果出现在手机里

由同一事件派生消息、日历、相册、便签。先完成约定确认→活动承接→结果留存的小闭环；对生成图片显示处理中／成功／失败／未知，不发不存在的照片。图片生成不是唯一回报，关系和机会变化也有效。

验收：一个行动能在两个相关应用中看到一致后果；刷新不丢；重试不重复；拒绝的邀请不展示已赴约。

### NAR-04：开场与回访质量

先做小规模人工体验，不直接上复杂推荐。设计三种原创样本：职业探索、关系日常、轻松旅行；每种测首次进入、合理协商、拒绝、出乎预料的自由输入、告别、回访。记录用户能否说清“我是谁、我在做什么、我的行动改变了什么”。

质量指标：首次有意义行动的成功率、悬念实际兑现比例、已解决冲突重复率、用户方案得到承接的比例、角色记忆错误率、主动退出是否被尊重。自愿回访与问卷一起看；长对话、总在线时长不独立代表满意。

### 暂缓而不取消

语音按用户要求暂缓。多人、时间、多人生仍保留；当前优先把单个用户的一件事走通。便签删除与旧缓存恢复、素材生成状态、导演并发恢复仍在原任务清单中，不能被本计划覆盖成已完成。
