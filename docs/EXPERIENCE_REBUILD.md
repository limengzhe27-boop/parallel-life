# 如果：完整体验重构基线

2026-09-28 · EXP-01。集成人：codex-main-experience-20260928。与既有「辅助」任务 EXP-01B 独立审查后整合。任务状态唯一来源为 DEVELOPMENT.md。

**本轮交付是经审查的重构基线，不是产品重构完成。** 当前线上仍属开发预览，不应以它通过了构建或能完成聊天，声称达到正式用户、领导或投资人完整体验验收标准。NPC介入、群聊、自动生图是待验证的交互方案，不因为被写入本文就算用户已选定所有形式。

## 1. 重新定义交付目标

产品承诺：从“真实的我”出发，进入一条以我为主角的平行人生；那里的人有态度、事情有进展，我的行动会留下结果，世界也会主动回应我。

区别于通用聊天工具的价值必须可以亲手体验：

- 同一件事会在不同人物的消息、日程、照片与回忆中连贯出现。
- 不需要用户每次先提问：有依据的进展、兑现的承诺与邀约会找上门来。
- 自由回复可以改变后续，角色不会只迎合，也不无理由刁难。
- 返回时能接住上一段生活；退出不被惩罚，轻松相处也有价值。

已有存储、权限、真实文字模型、事件与回执等底座可以保留。重构重点是领域信息如何组织、流程如何推进、内容如何产生、界面如何承载。这不是从零重写，也不能只换一套配色。

## 3. 五个用户可理解的核心对象

| 对象 | 内容 | 原则 |
|---|---|---|
| 我 | 用户明确表达的真实资料、愿望、经历、重要关系 | 可更正、有来源；模型推断不伪装成事实 |
| 人生草案 | 想体验的身份、分岔点、生活基调、虚构起点、带入范围 | 草案不是已创建的世界；各入口读同一份 |
| 正在发生的事 | 目标、人物、已发生行动、约定、困难、结果 | 所有应用读取同一已提交事件，不各自编剧情 |
| 重要的人 | 角色目标、关系、知情范围、习惯与自己的记忆 | 主角是用户；角色有立场但不全知、不替主角决定 |
| 回忆 | 有来源的事件摘要、照片、作品、用户主动记录 | 事实、角色看法、AI图像各自明确；可回看、纠正或遗忘 |

这五个对象是对现有模块的收敛方向，不要求另建五套数据库。模块化单体、现有事件事务/来源/权限机制继续使用。

## 4. 外层路径：聊懂、看懂、选懂，再进入

### 聊聊

首屏只保留品牌顶栏、一句自然邀请、输入框；可有少量不同表达的开场建议，不加年龄/生日表单。开场不强行挖遗憾或创伤，也接受“我就是想试试开咖啡馆”。

向导内部状态：倾听当前诉求 → 澄清最关键的一点 → 形成可修改草案 → 回读确认 → 创建。用户可以直接带着明确设定跳到草案，不机械规定聊满几轮。每轮先回应，再决定是询问、总结、展示草案，或自然收尾；不是每轮必须问问题。

创建前检查的是体验是否清楚，而不是资料条数：想成为谁/改变哪个选择、现在想体验哪种生活、从哪里开始、使用哪些资料。未知的内容可由AI提出并标为虚构设定，让用户一并修改；不要把缺生日当成阻塞。

### 我的

首屏显示小而完整的“当前的我”：头像/称呼、已知的生活处境；未知不补。下方四个稳定入口：

1. **我在意的**：兴趣、价值偏好、愿望；保留愿望与现实的区别。
2. **走过的路**：重要经历与选择，按已知时间组织；未知时间不造日期。
3. **重要的人**：真实关系及用户选择的照片，多个提及归并到同一人。
4. **照片与基本资料**：集中编辑，照片不再占满无内容的首屏。

“新整理的内容”作为小入口或变化提示，不把所有候选卡默认铺满；用户可以打开核对。明确自述按当前约定保存，有歧义/推断/冲突时才请用户确认；生日不能推出性格。自动总结必须引用底层条目及版本，修改原条目后重建摘要，不再独立保留一份过期结论。删除与遗忘不在其他视图复活。

将待处理候选、正式档案、检索记忆的界面职责分开，但共用一套来源与状态规则；旧数据先做映射和差异预览，不批量静默重写用户资料。

合成纯函数验证已复现“2020年毕业”和“我朋友1998年出生”被提取成本人生日。此类误写需先修正再迁移；不能批量猜测哪些旧资料是真实生日。访谈流结束目前只更新对话，资料/候选需统一刷新并保留版本保护。

### 分支与创建

已有分支采用等权卡片：身份、场景图、一个当下进展/未读提示、继续入口。缺少实际生成封面时，不把通用插画称为“平行世界的你”。草案与已有世界清晰分组；不让用户对着两种相似卡片猜哪些可进入。

创建只走一条主线：聊天/分支入口 → 人生草案 → 可编辑起点与带入范围 → 创建 → 手机锁屏。草案卡仅呈现身份、当下情境、关键关系与希望体验的基调；细节展开。用户确认的是这一个故事，不是让系统在后台任选一个新提案。

“开始”前明示照片及人物是否带入。确认后服务端保存不可变起点版本。创建状态使用已完成阶段，不伪造百分比；刷新继续同一个请求，失败能恢复，不重新花费且不丢草案。生成完要通过开场一致性检查：身份、时间、地点、人物关系、首条事件和手机内容互相对应。

## 5. 内层路径：把手机当生活，不当功能菜单

外层承担理解自己与选择人生；世界手机承担生活。外层视觉可以有想象力和场景感；内层使用统一的iPhone式导航、排版、触控尺度、系统层与应用层关系。图片和人物承担情绪，不能靠大量说明文字制造沉浸。

| 屏幕 | 最重要的内容 | 需要统一的规则 |
|---|---|---|
| 锁屏 | 时间、壁纸、一至两条真正相关的通知 | 一次开场事件；时间来自世界；点击直达消息或邀约 |
| 桌面 | 壁纸、常用应用、当前生活入口 | 不放大段世界设定；管理和导演位于明确但次要的入口 |
| 消息列表 | 有进展的人、最后一条消息、未读 | 统一头像/图标/时间；没有消息的联系人进入通讯录 |
| 人物聊天 | 自然对话、明确的邀请与附件 | 可变句长和克制气泡；自由输入；不强塞四句同样快捷语；通知不打断输入 |
| 相册 | 实际照片、最近回忆、事件来源 | 无照片时不展示两排空筛选；点击回到来源事件/对话；生成状态独立可见 |
| 日历 | 今天/近期的约定及待回复邀请 | 一种邀请在所有入口同状态；约定确认不自动等于已参加 |
| 便签 | 用户记录与已存在的生活资料 | 保留编辑与来源；不把导演旁白伪装成用户写的日记 |
| 人生管理 | 身份、调整节奏、返回分支 | 辅助能力不抢主体验；同一位置、同一种返回规则 |

先统一一套组件和样式归属，再整页替换，不能继续在旧全局样式后面追加覆盖。验收必须覆盖空态、少量内容、长对话、多分支、多图、加载、失败、断网、键盘、短屏和电脑居中。模拟短屏不冒充真机键盘测试。

## 6. NPC 的人味与导演分工

当前普通聊天直接调用当前人物的回合规划；导演主要存在于手动推进，不是已完整控制每次对话的总导演。因此不能说“只差给导演加一句更自然”。

目标分工：**导演决定这个时刻值得发生什么、谁有理由参与；NPC决定自己怎样说、愿意做什么；运行时校验并保存；手机显示后果。** 不给每个字都增加一个导演模型调用。

人味的判断不是口头禅或emoji数量，而是：

- 认真接住上一句，记得有来源的共同经历；不知道就不知道。
- 有不同说话节奏与关注点；不人人长篇安慰、最后都问同一个问题。
- 有实际行动：约时间、发已有照片、兑现小承诺、主动告知进展。
- 有边界也有善意，冲突有依据；允许闲聊、沉默和自然结束。
- 用户提出有效方案后能松口；人物不能为保留戏剧性不停搬动门槛。

NPC介入的候选方案按复杂度排序：

1. **相关来信**：用户正在与A谈拍摄，已有事件使B知道需要看场地，B另发一条来信。当前聊天不中断，用户决定何时看。
2. **介绍与转交**：A征询是否介绍B；确认后建立联系，并记录B获知的有限内容。
3. **临时群聊**：确需多人共同决策时建立有成员和知情范围的会话。后续验证后再做，不默认往私人对话里塞第三个人。

新角色出现必须有因果来源和传递信息的权限，不能偷读A与用户私聊，也不能出现每句话都有人插话的噪声。

## 7. 主动世界与图片的目标工作链

触发不只来自用户输入，还可以是：已确认约定接近、NPC完成了承诺、媒体任务完成、上一件事产生后续、用户重新进入世界。离线期间保持有界补算，不无限模拟；暂停应真的停。

统一链路：

**真实触发事件 → 导演挑选有意义且可见的后续 → 指定人物提出行动 → 校验/事务提交 → 消息、日历、相册更新 → 通知与未读 → 用户回应或暂不理会。**

前台需要能收到已提交事件：可见页面订阅或有界读取，断线按事件游标续接；“定期读事件”和“定期让模型编一条消息”是两件事。后台要有部署环境支持的可靠执行者。不能依赖关闭浏览器后还继续的请求，也不能用内存定时器冒充常驻世界。

主动联系受状态和偏好约束：同一事项不重复催、没有有意义进展可以不发、用户暂停或明确告别时停止加压。先完成应用内通知；系统推送另走授权和实现，不擅自启用。

### 照片举例（目标方案，当前未完整实现）

用户与朋友谈到当天的海边外拍 → 已存在的活动或角色行动提供场景依据 → 导演允许一次留影 → 图像服务只使用本分支获准素材 → 成功后保存一份素材 → 同一素材同时进入相册，并以明确附件由有权持有它的朋友发来。

用户不必每次说“帮我生成图”；但也不是只要提到海边就立刻生图。触发依据可以是共同活动结束、明确拍摄行为、完成作品、对话中提出回忆。角色可以分享本来就有的照片，不要每次重新生成。

生成中不能先说“照片已在相册”；成功再发完成消息。失败不造图、不假称肖像一致，可重试且保护已发生的故事；结果未知不自动再次消费。预算不足时继续自然对话，不把付费与关系惩罚绑定。

必要记录：来源事件、请求ID、获准参考素材、出镜人物、接收者/可见范围、叙事时间、生成状态、完成素材ID、投递回执。图片归属和聊天附件靠ID关联，不靠文字猜测。任务重试不能再发同一张图片两次。

## 8. 重构执行与协作

先写可核验的纵向体验，再切换旧路径；不同时维护两个独立事实系统。任务统一登记，编码用独立工作树；公共契约由主任务串行合入。辅助先审查，再在契约稳定后承担指定模块，不能两人同时改大容器。

| 阶段/任务 | 完成内容 | 依赖和验收 |
|---|---|---|
| EXP-02 真实能力与发布门槛 | 移除媒体/朋友圈假成功路径，修正否定创建/误提生日、未看图却赞美/星座推性格、误导进度与状态 | 第一优先；预览示例不能进入生产事件；不调用模型也不标生成成功 |
| EXP-03 统一信息模型 | 资料视图、人生草案、事件关联、附件、提案/生成状态契约；旧数据映射 | 先设计契约再改 UI；来源、更正、版本和权限测试 |
| EXP-04 外层完整重构 | 聊聊引导、我的、等权分支、草案确认、创建恢复；统一组件样式 | EXP-03；同一输入不因入口不同产生不同选中故事/带入范围 |
| EXP-05 世界手机完整重构 | 锁屏、桌面、消息、相册、日历、便签及管理；移除旧覆盖 | EXP-03；全状态矩阵、键盘/返回/长内容、390px/短屏/PC验收 |
| NAR-02 主动叙事运行 | 持久剧情线、因果选择、NPC知情传播、并发恢复与主动调度 | 复用既有NAR任务，不另建相同引擎；先验证可靠提交再自动触发 |
| NAR-03 媒体与事件联动 | 真实生成、附件/相册共同引用、日程及活动后果、通知 | EXP-02/03、NAR-02；真实模型＋数据库＋公网闭环 |
| EXP-06 完整体验发布验收 | 至少一条10–15分钟真实体验链，三种身份变体、回访与失败恢复 | 外层/手机/主动世界接通后；辅助盲测、主任务复核、再邀请体验 |

前两项解决能力真实性和公共契约，再并行做外层/手机/后台。不因为某个页面看起来漂亮就单独宣布成品。每批通过门槛后部署，生产已有世界可继续；未达标的新体验通过隔离预览验证，不能覆盖原数据或导入预设剧情伪装生成。

## 9. 展示给领导前的硬门槛

- 用户不用开发者解释，知道自己是谁、下一步能做什么。
- 从自由聊天形成草案；至少一次修改被准确带入；实际建成的是选中的故事。
- 关键身份、事件和带入资料准确，照片使用范围可理解；没有假图、假动态、假成功。
- 至少一次有因果依据的主动来信，并能继续回应；不能只重播旧通知。
- 至少一件选择有后果、一个承诺有下文、一次自然收尾；NPC不全知、不替用户行动。
- 至少一张真实生成图片或真实已有图片作为明确附件送达，并在相册保留、刷新不重复。若真实生图尚未通过，不宣称已支持生成照片。
- 刷新/离开回来承接原线；未知/失败/重试可靠；核心控件可用且视觉统一。
- 功能检查通过之外，需要独立体验者评价理解度、人物可信度、选择影响与想继续的原因。没有一个单元测试数字能替代这个结论。

## 10. 本轮范围与后续决策

本轮完成审查与重构设计，不再增加新表面互动。语音暂缓；多人、时间、多人生保留，不用本次聚焦取消。群聊/第三人介入形式需要在新消息原型中验证，暂不作为首批必做项。

最先实现的是 EXP-02 和 EXP-03；同时先统一外层和手机的交互稿，再进入 EXP-04/05。下一次交付应展示整条体验路径及明确的替换范围，而不只是几处颜色或话术变化。

## 11. 双方审查采纳记录

已读取辅助独立报告EXP-01B，逐项复核并采纳9项。创建竞争、方向/照片范围、资料漏分类、访谈提示、日期兜底、主动推进、图像准备状态、分支辨识、资料未刷新均进入对应任务。主任务补充朋友圈模板及附件标题猜测。否定创建和经历年份误提已用合成纯函数复现，无生产写入。独立报告没有执行新用户创建或图像调用，不把其意见当成这些链路已完成实测。


## 12. 复审后的切换与验收约束

辅助第二次挑战的三项均采纳：

1. **明确替换而非双轨增加**。EXP-03需交付“入口→唯一用例”映射。聊聊创建和分支创建都调用同一草案提交；资料编辑/提炼通过同一资料命令；各应用附件读取同一素材引用。每批登记待删旧写入口和旧样式规则，切换后测试旧入口不可再写。旧数据适配只能读，不能双写两套档案。灰度按整条体验路径切换，回滚代码不能静默撤销已提交用户事件；新增迁移保持向后兼容。
2. **主动运行的可靠性先于自动播放**。持久触发ID、事件游标、租约与回执必须明确；覆盖暂停与触发竞争、领取后崩溃、媒体已生成但回执丢失、断线重连。目标是幂等提交与可恢复交付，不能承诺外部模型“恰好调用一次”。结果未知时不得自动重新消费。
3. **状态不能变成隐形问卷**。自由输入验收语料包括否定、引用、假设、更正、换话题、拒绝后继续聊、指定已有世界、只要简略虚构起点。先贯通一个自由表达→修改草案→进入手机→有依据的主动来信→自由回应产生后果→回访的完整样例，再扩展到三种身份。EXP-05可先重做界面，其主动生活验收必须依赖NAR-02/03，不得提前标完整体验完成。
